# Junior Frontend Developer - Competency Assessment

## Introduction

This is a competency assessment for the role of Frontend developer, at the
Junior frontend developer level. It is written for an assessor — a line
manager, an interview panel, or a reviewer — who needs to judge whether a
candidate or an employee possesses the baseline abilities this role level
requires, for a hiring decision, a promotion board, onboarding, or a
capability check against the framework.

This assessment is one input among several into that judgement, never the
whole of it. Read `## Advisory` below before you use any part of this
document.

## Advisory

This competency assessment is created by AI and is a work in progress for
educational purposes. It is not a validated assessment instrument — it has not
been piloted, normed or checked for adverse impact — and a rating on this form
must never be the sole basis for a hiring, promotion, pay, performance or
disciplinary decision. Before using it, consult your organisation's human
resources, people development, occupational psychology or legal compliance
colleagues.

## How to use this assessment

**Preparing.** Read `## About this role level` before you score anything, so
that every rating is anchored to what a junior frontend developer is
actually expected to do. Gather whatever evidence exists before you start: a
CV or portfolio, a structured interview, a work sample or task, direct
observation of the person's day-to-day work, or references.

**Scoring on evidence, not impression.** Every rating in the competency matrix
must trace to something the person did, said, produced, or was observed
doing. If you cannot point to evidence for a rating, record it as unknown
rather than guess.

**Consistency.** Score every candidate for this role level the same way.
Where possible, have more than one assessor score independently and compare
notes afterwards, especially for a hiring or promotion decision.

**Fairness.** This is an unvalidated, AI-drafted instrument. Used
inconsistently, it can produce unlawful adverse impact — treating one
candidate less favourably than another for reasons that have nothing to do
with the job. Consistent, evidence-based administration by more than one
assessor materially reduces that risk. Never let a rating be influenced by
anything other than demonstrated, job-related evidence.

## Rating scale

Every skill in the competency matrix is rated on the same five-point scale:

| Value | Rating | Meaning |
| ---: | --- | --- |
| 0 | None | No demonstrated experience of this skill |
| 1 | Beginner | Just starting to learn the skill; requires close supervision |
| 2 | Intermediate | Knows the basics and can perform tasks with some guidance |
| 3 | Advanced | Has a strong grasp of the skill and can work independently |
| 4 | Expert | Demonstrates full mastery and can teach or guide others in the skill |

This is a **proficiency** scale, not a frequency scale: it rates how well the
person does the thing, on the evidence available, not how often they do it.

**Worked example — Accessibility.** At Beginner (1), a candidate could
describe watching someone else fix an accessibility issue, without having
built anything to a standard themselves. At Intermediate (2) — this level's
baseline — they can describe building a user interface that meets
accessibility standards, and fixing issues under someone else's direction. At
Advanced (3), above this level's baseline, they could describe championing
accessibility to stakeholders unprompted, which is more initiative than this
level expects.

## About this role level

A frontend developer designs, builds and improves website software that
meets user needs. In this role, a person is responsible for writing clean,
accessible code following a progressive enhancement approach, creates code
that is open by default and easy for others to reuse, designs software which
meets user needs and creates meaningful interactions and relationships with
users, and has an understanding of the three fundamental frontend
technologies: HTML, CSS and JavaScript.

This assessment covers the **Junior frontend developer** level, the second
step of the role's ladder. The full ladder, in order, is: Apprentice frontend
developer, Junior frontend developer (this level), Frontend developer, Senior
frontend developer, Lead frontend developer, and Head of frontend
development.

A junior frontend developer learns on the job by delivering software
components. At this level, a person is expected to:

- work independently, with guidance from more senior developers, to identify
  user issues and needs
- write clean code that follows web standards
- build their understanding of accessibility
- build their knowledge
- develop software which meets user needs

This level names eleven skills: Accessibility, Communicating information,
Community collaboration, Leadership and guidance (frontend developer),
Modern development standards, Programming and build (frontend developer),
Prototyping, Strategic thinking, Systems integration (frontend developer),
User focus (frontend developer), and Web performance optimisation.

## Competency matrix

### Skill: Accessibility

**What the framework expects at this level**

A junior frontend developer is expected to understand that users have
different accessibility needs, and to build user interfaces that meet
accessibility standards and fix accessibility issues under the direction of
others.

**Baseline for this role level**

Baseline: 2 — Intermediate. Building to a standard is a real step up from the
apprentice level's help-under-direction wording, matching this level's
"deliver software components" accountability.

**Behavioural indicators**

- 0 — None: builds an interface without checking it against any
  accessibility standard.
- 1 — Beginner: attempts to build to a standard but needs frequent
  correction.
- 2 — Intermediate: builds user interfaces that meet a stated accessibility
  standard, and fixes issues when directed to.
- 3 — Advanced: not expected at this level.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask to see an interface the candidate built, and check it against a stated
  accessibility standard.
- Ask about a time they fixed an accessibility issue someone else pointed
  out to them.

### Skill: Communicating information

**What the framework expects at this level**

A junior frontend developer is expected to listen to the needs of design and
business stakeholders and interpret information, to take part in discussions
within a multidisciplinary team, to be an advocate for the team externally
and manage differing perspectives, and to shape and share communications
relevant to the audience.

**Baseline for this role level**

Baseline: 2 — Intermediate. Advocating externally and shaping communications
for an audience are active contributions beyond the apprentice level's
listening-and-restating wording, matching "knows the basics and can perform
tasks with some guidance."

**Behavioural indicators**

- 0 — None: struggles to interpret what a stakeholder is asking for.
- 1 — Beginner: listens and restates accurately, but has not represented the
  team externally.
- 2 — Intermediate: interprets stakeholder needs, takes part actively in
  team discussions, and has represented the team's view to someone outside
  it, with some guidance.
- 3 — Advanced: does this consistently and manages genuinely differing
  perspectives without support.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask about a time the candidate represented their team's view to someone
  outside it.
- Ask them to describe how they shaped a piece of communication for a
  specific audience.

### Skill: Community collaboration

**What the framework expects at this level**

A junior frontend developer is expected to contribute to the work of others,
motivate and empower teams, create the right environment for teams to work
in and identify the best team makeup depending on the situation, and
recognise and deal with issues.

**Baseline for this role level**

Baseline: 2 — Intermediate. Contributing to others' work and recognising and
dealing with issues are active participation, matching "knows the basics and
can perform tasks with some guidance" — the fuller wording around motivating
and empowering teams reads as more senior than this level's own
accountabilities, so evidence of full ownership of that should not be
expected.

**Behavioural indicators**

- 0 — None: does not notice or engage with issues affecting how the team
  works together.
- 1 — Beginner: contributes to someone else's work when asked, but does not
  yet notice team issues themselves.
- 2 — Intermediate: contributes proactively to others' work, and recognises
  and raises a team issue rather than ignoring it.
- 3 — Advanced: actively helps resolve team issues, not just raise them, and
  helps create a good working environment for others.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask about a time the candidate noticed a team issue and what they did
  about it.
- Ask about a piece of work they contributed to that belonged to someone
  else.

### Skill: Leadership and guidance (frontend developer)

**What the framework expects at this level**

A junior frontend developer is expected to follow agreed good practice for
the team, show an awareness of the importance of team dynamics and
collaboration, and understand the importance of feedback.

**Baseline for this role level**

Baseline: 1 — Beginner. Worth noting plainly, not smoothing over: this
skill's wording is identical to the apprentice level's, so the baseline stays
the same even though the level overall has moved on.

**Behavioural indicators**

- 0 — None: does not follow the team's agreed good practice even when told
  what it is.
- 1 — Beginner: follows the team's agreed good practice when reminded, and

  reminded.
- 3 — Advanced: not expected at this level.
- 4 — Expert: not expected at this level.

**Evidence to gather**

  follows, and why it exists.

  without reminders.

### Skill: Modern development standards

**What the framework expects at this level**

A junior frontend developer is expected to explain the most important
principles of modern development standards and how they apply to their
work, and to apply those principles under guidance.

**Baseline for this role level**

Baseline: 2 — Intermediate. This is a step up from the apprentice level's
explanation-only wording, to actually applying standards under guidance,
matching this level's "write clean code that follows web standards"
accountability.

**Behavioural indicators**

- 0 — None: cannot name a development standard their team follows.
- 1 — Beginner: can explain a development standard in general terms but has
  not applied it themselves.
- 2 — Intermediate: has applied a specific standard to their own work, with
  guidance available.
- 3 — Advanced: applies standards consistently without needing to be
  reminded.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Review a piece of code or commit history the candidate produced, and check
  it follows a stated standard.
- Ask the candidate to explain, for one standard they follow, what problem
  it prevents.

### Skill: Programming and build (frontend developer)

**What the framework expects at this level**

A junior frontend developer is expected to collaborate with others to
understand and review software requirements, and to design, code, test,
correct and document user interfaces using the right standards and tools
under the direction of others.

**Baseline for this role level**

Baseline: 2 — Intermediate. Reviewing requirements and building user
interfaces, still under direction but with a broader task than the
apprentice's "simple" interfaces, matches this level's independent-but-guided
accountability.

**Behavioural indicators**

- 0 — None: cannot build a user interface even with direction.
- 1 — Beginner: builds a simple interface with close, step-by-step
  direction.
- 2 — Intermediate: collaborates on reviewing requirements, and designs,
  codes, tests, corrects and documents a user interface under general
  direction, needing occasional guidance.
- 3 — Advanced: does this with minimal direction, and helps correct a peer's
  simple mistakes.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Set a moderately-scoped user interface task and observe the candidate's
  process: do they clarify requirements, test what they built, and document
  it?
- Ask to see a user interface they built recently, and walk through their
  process.

### Skill: Prototyping

**What the framework expects at this level**

A junior frontend developer is expected to understand when to use a specific
prototyping technique or method, and to show the value of prototyping to
their team.

**Baseline for this role level**

Baseline: 1 — Beginner. Understanding and demonstrating value are asked for,
not running prototyping activities, matching the apprentice level's wording
closely.

**Behavioural indicators**

- 0 — None: cannot say when a prototype would help versus building the real
  thing straight away.
- 1 — Beginner: can identify, for a simple example, whether a quick
  prototype would help before committing to a full build.
- 2 — Intermediate: has explained to a colleague or in a team discussion why
  a specific prototype was worth building, and been understood.
- 3 — Advanced: not expected at this level.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Give a short scenario (a new interface idea) and ask whether they would
  prototype it first, and why.
- Ask about a time they helped the team decide to build a rough version of
  an interface before the real one.

### Skill: Systems integration (frontend developer)

**What the framework expects at this level**

A junior frontend developer is expected to show an awareness of how to build
static assets from source code, and to explain how browsers use and present
static assets to end users, including how different versions of an interface
can be delivered for different browsers and devices.

**Baseline for this role level**

Baseline: 1 — Beginner. Awareness and explanation are asked for, not building
and testing a delivered interface independently.

**Behavioural indicators**

- 0 — None: cannot explain what a browser does with a static asset such as a
  built CSS or JavaScript file.
- 1 — Beginner: can explain, in general terms, how static assets are built
  from source code and used by a browser.
- 2 — Intermediate: can describe a real example of an interface behaving
  differently across browsers or devices, and why.
- 3 — Advanced: not expected at this level.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask the candidate to explain, in plain terms, what happens between writing
  source code and a user's browser displaying it.
- Ask about a time they noticed an interface looking or behaving differently
  on a different browser or device.
