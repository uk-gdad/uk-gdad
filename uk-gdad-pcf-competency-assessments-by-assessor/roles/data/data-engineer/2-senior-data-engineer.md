# Senior Data Engineer - Competency Assessment

## Introduction

This assessment is for an assessor — a line manager, a hiring panel member, or
a reviewer — judging whether a candidate or an employee meets the baseline
abilities required for the Data role of Data engineer, at the Senior data
engineer role level. It measures demonstrated skill against the UK GDAD
Profession Capability Framework's own description of this role level, for a
hiring decision, a promotion board, onboarding, or a capability check.

A senior data engineer designs and leads the implementation of data flows
connecting operational systems, analytics and business intelligence systems,
leads the build of streaming systems, and leads work on database management.
This assessment looks for independent, trusted delivery and technical
leadership, not the strategic, organisation-wide remit of the levels above.

This assessment is one input among several into a decision, never the whole of
it. Read `## Advisory` before using it.

## Advisory

This competency assessment is created by AI and is a work in progress for
educational purposes. It is not a validated assessment instrument — it has
not been piloted, normed or checked for adverse impact — and a rating on this
form must never be the sole basis for a hiring, promotion, pay, performance or
disciplinary decision. Before using it, consult your organisation's human
resources, people development, occupational psychology or legal compliance
colleagues.

## How to use this assessment

**Preparing.** Read `## About this role level` first, then gather whatever
evidence exists: a CV or portfolio, a structured interview, a work sample or
task (for example, asking the candidate to design a resilient data
integration approach for a given scenario), direct observation, or
references — particularly references that can speak to how the candidate has
led technical work, such as building a streaming system.

**Score on evidence, not impression.** Every rating must trace to something
the person did, said, produced, or was observed doing. If you cannot point to
evidence for a rating, record it as unknown rather than guess.

**Consistency.** Score every candidate for this role level the same way. For a
hiring or promotion decision, have more than one assessor score independently
before comparing notes.

**Fairness.** Every rating and every piece of evidence you gather must be
about demonstrated, job-related behaviour — see
[Fair and lawful use](#fair-and-lawful-use) in the project specification.
Never let a rating be coloured by anything other than what the person actually
did, said, or produced.

## Rating scale

Every skill in the competency matrix below is rated on the same five-point
scale. This is a **proficiency** scale — it rates how well the person does the
thing, on the evidence available, not how often they do it or how they feel
about it.

| Value | Rating | Meaning |
| ---: | --- | --- |
| 0 | None | No demonstrated experience of this skill |
| 1 | Beginner | Just starting to learn the skill; requires close supervision |
| 2 | Intermediate | Knows the basics and can perform tasks with some guidance |
| 3 | Advanced | Has a strong grasp of the skill and can work independently |
| 4 | Expert | Demonstrates full mastery and can teach or guide others in the skill |

**Worked example — Data integration design.** The framework expects a senior
data engineer to "select and implement the appropriate technologies to
deliver resilient, scalable and future-proofed data solutions". A candidate
who can only deliver a solution that follows technologies someone else has
already chosen is showing **2 — Intermediate**, below this level's baseline.
A candidate who, given a new integration problem, independently selects the
right technologies and can defend the choice against resilience, scalability
and future-proofing criteria is showing **3 — Advanced** — the baseline this
level expects. A candidate who has additionally set the organisation's
standards for making this kind of choice is showing evidence towards
**4 — Expert**.

## About this role level

The Data profession's Data engineer role develops and constructs data
products and services, and integrates them into systems and business
processes.

The role has four levels, in order: Data engineer, Senior data engineer, Lead
data engineer, and Head of data engineering. This assessment is for the
second of them.

A **senior data engineer** designs and leads the implementation of data flows
to connect operational systems, data for analytics and business intelligence
(BI) systems. At this role level, they will recognise opportunities to reuse
existing data flows, lead the build of data streaming systems, optimise code
to ensure processes perform optimally, and lead work on database management.

The framework names ten skills for this role level: Communicating between the
technical and non-technical, Data analysis and synthesis, Data development
process, Data innovation, Data integration design, Data modelling, Metadata
management, Problem management, Programming and build (data and analytics
engineering), and Testing.

## Competency matrix

### Skill: Communicating between the technical and non-technical

**What the framework expects at this level**

A senior data engineer is expected to communicate effectively with technical
and non-technical stakeholders, support and host discussions within a
multidisciplinary team with potentially difficult dynamics, be an advocate
for the team externally, and manage differing stakeholder perspectives.

**Baseline for this role level**

Baseline: 3 — Advanced. Leading the build of streaming systems and database
management work means representing technical decisions to stakeholders who
depend on those systems, so the communicating and hosting this skill
describes needs to happen consistently and unsupervised — a step up from
earlier levels' guided practice with the same wording.

**Behavioural indicators**

- 0 — None: Cannot adapt an explanation for a non-technical audience or
  moderate a disagreement between stakeholders.
- 1 — Beginner: Communicates with stakeholders on routine matters but needs
  support for anything contentious.
- 2 — Intermediate: Handles most stakeholder communication independently but
  escalates genuinely difficult discussions.
- 3 — Advanced: Independently hosts discussions with difficult dynamics,
  advocates for the team externally, and manages conflicting stakeholder
  expectations without escalating.
- 4 — Expert: Is sought out across the organisation to mediate the most
  difficult stakeholder situations.

**Evidence to gather**

- Ask the candidate to describe a difficult stakeholder discussion they
  hosted about a technical decision, such as a database migration or a
  streaming system design.
- Ask a referee whether the candidate has represented the team's work
  externally.

### Skill: Data analysis and synthesis

**What the framework expects at this level**

A senior data engineer is expected to undertake data profiling and source
system analysis, and present clear insights to colleagues to support the end
use of the data. The framework's own wording for this skill is unchanged from
the level below.

**Baseline for this role level**

Baseline: 2 — Intermediate. This level's own accountabilities centre on
leading build and database work rather than on analysis and synthesis
specifically, and the skill's own wording does not move from the level below,
so the baseline is held rather than inflated to match the general seniority of
the role.

**Behavioural indicators**

- 0 — None: Cannot describe what data profiling involves or produce a
  presentable summary of findings.
- 1 — Beginner: With close guidance, profiles a simple source and describes
  basic characteristics.
- 2 — Intermediate: Profiles a source system with some independence and
  presents findings to colleagues clearly enough to support a decision.
- 3 — Advanced: Profiles complex or unfamiliar source systems independently
  and synthesises insight across multiple sources.
- 4 — Expert: Sets the team's standard for source analysis.

**Evidence to gather**

- Ask the candidate to talk through how they would profile an unfamiliar
  source system before designing a data flow from it.
- Ask for an example of a time they presented a data finding to a colleague.

**Rate this skill**

- [ ] 0 — None
- [ ] 1 — Beginner
- [ ] 2 — Intermediate
- [ ] 3 — Advanced
- [ ] 4 — Expert

### Skill: Data development process

**What the framework expects at this level**

A senior data engineer is expected to design, build and test data products
that are complex or large scale, and to build teams to complete data
integration services.

**Baseline for this role level**

Baseline: 3 — Advanced. "Complex or large scale" data products, and building
teams to deliver integration services, is a step beyond delivering to
existing designs, which is where the level below is baselined.

**Behavioural indicators**

- 0 — None: Cannot design or build a complex or large-scale data product.
- 1 — Beginner: Builds simple data products with support.
- 2 — Intermediate: Builds moderately complex data products with some
  support.
- 3 — Advanced: Independently designs, builds and tests complex or
  large-scale data products, and helps assemble the team needed to deliver
  data integration services.
- 4 — Expert: Establishes enterprise-scale data integration procedures across
  the whole development life cycle.

**Evidence to gather**

- Ask the candidate to describe the most complex or large-scale data product
  they have designed and built.
- Ask about a time they helped put together a team to deliver a data
  integration service.

### Skill: Data innovation

**What the framework expects at this level**

A senior data engineer is expected to understand the impact on the
organisation of emerging trends in data tools, analysis techniques and data
usage.

**Baseline for this role level**

Baseline: 2 — Intermediate. Understanding impact is more than awareness, but
the framework reserves identifying the right timing to adopt something for
more senior roles, so the baseline sits at the middle of the scale.

**Behavioural indicators**

- 0 — None: Cannot say what effect a new tool or technique might have on the
  organisation, even when prompted.
- 1 — Beginner: Names emerging tools or trends but cannot judge their likely
  impact.
- 2 — Intermediate: Explains, with reasonable accuracy, what impact a named
  emerging trend would have on the team's or organisation's data work.
- 3 — Advanced: Independently assesses several emerging trends and advises on
  which are worth the organisation's attention.
- 4 — Expert: Horizon-scans proactively and introduces new ways of working.

**Evidence to gather**

- Ask the candidate about an emerging data engineering tool or technique and
  what impact it would have if the organisation adopted it.
- Ask whether they have advised a manager or team on whether to invest time in
  a new approach.

**Rate this skill**

- [ ] 0 — None
- [ ] 1 — Beginner
- [ ] 2 — Intermediate
- [ ] 3 — Advanced

### Skill: Data integration design

**What the framework expects at this level**

A senior data engineer is expected to select and implement the appropriate
technologies to deliver resilient, scalable and future-proofed data
solutions.

**Baseline for this role level**

Baseline: 3 — Advanced. Independently selecting technologies, rather than
delivering to standards already agreed for them, is a clear step up from the
level below.

**Behavioural indicators**

- 0 — None: Cannot select an appropriate technology for a given integration
  problem.
- 1 — Beginner: Delivers to a technology choice someone else has made.
- 2 — Intermediate: Delivers within agreed organisational standards but does
  not yet select technologies independently.
- 3 — Advanced: Independently selects and implements the appropriate
  technologies to deliver resilient, scalable and future-proofed data
  solutions.
- 4 — Expert: Establishes the organisation's integration design standards and
  keeps abreast of best practice across government and industry.

**Evidence to gather**

- Ask the candidate to describe a time they chose between competing
  technologies for a data integration problem, and how they decided.
- Present a short scenario and ask what technology they would select and why.

### Skill: Data modelling

**What the framework expects at this level**

A senior data engineer is expected to produce relevant data models across
multiple subject areas, explain which models to use for which purpose,
understand industry-recognised data modelling patterns and standards and when
to apply them, and compare and align different data models.

**Baseline for this role level**

Baseline: 3 — Advanced. Producing models across multiple subject areas, and
comparing and aligning different models, is a clear step beyond producing and
maintaining models for a single defined need, which is where the level below
is baselined.

**Behavioural indicators**

- 0 — None: Cannot produce a data model or explain when to use a particular
  pattern.
- 1 — Beginner: Produces a simple data model from a clear specification, with
  significant review needed.
- 2 — Intermediate: Produces data models for a defined subject area with
  moderate review.
- 3 — Advanced: Independently produces relevant data models across multiple
  subject areas, explains which pattern fits which purpose, and compares and
  aligns different models.
- 4 — Expert: Designs the organisation's approach to categorising data
  models across government and industry.

**Evidence to gather**

- Ask the candidate to describe two different subject areas they have
  produced data models for, and how the models differed.
- Ask them to compare two industry-recognised modelling patterns and explain
  when each is appropriate.

**Rate this skill**

- [ ] 0 — None
- [ ] 1 — Beginner
- [ ] 2 — Intermediate
- [ ] 3 — Advanced
- [ ] 4 — Expert

### Skill: Metadata management

**What the framework expects at this level**

A senior data engineer is expected to design an appropriate metadata
repository, suggest changes to improve current metadata repositories,
understand a range of tools for storing and working with metadata, and advise
less experienced members of the team about metadata management.

**Baseline for this role level**

Baseline: 3 — Advanced. Designing a repository and advising others describes
someone with strong, independent grasp of metadata practice who is starting
to shape it for others.

**Behavioural indicators**

- 0 — None: Cannot judge whether a metadata repository is fit for purpose.
- 1 — Beginner: Uses an existing repository correctly but could not design or
  improve one.
- 2 — Intermediate: Suggests small improvements to an existing repository
  with support.
- 3 — Advanced: Independently designs a metadata repository appropriate to a
  defined area, proposes improvements to existing repositories, and advises
  less experienced colleagues.
- 4 — Expert: Sets metadata governance for the whole organisation.

**Evidence to gather**

- Ask the candidate to describe a metadata repository they have designed or
  substantially improved.
- Ask about a time they advised a more junior colleague on metadata practice.

### Skill: Problem management

**What the framework expects at this level**

A senior data engineer is expected to initiate and monitor actions to
investigate patterns and trends to resolve problems, effectively consult
specialists where required, determine the appropriate resolution and assist
with its implementation, and determine preventative measures.

**Baseline for this role level**

Baseline: 3 — Advanced. Initiating investigations, consulting specialists, and
determining the resolution and preventative measures describes someone who
owns problem management for their area.

**Behavioural indicators**

- 0 — None: Does not initiate investigation of a problem unless told to.
- 1 — Beginner: Investigates a problem when asked but needs support to decide
  the resolution.
- 2 — Intermediate: Investigates and proposes resolutions for moderately
  complex problems with some oversight.
- 3 — Advanced: Independently initiates and monitors investigations, consults
  specialists appropriately, determines the resolution, and puts preventative
  measures in place.
- 4 — Expert: Anticipates problems before they occur and builds the team's
  wider capability to do the same.

**Evidence to gather**

- Ask the candidate to describe a problem they initiated the investigation
  of, without being asked, and what preventative measure they put in place
  afterwards.
- Ask about a time they consulted a specialist to resolve a problem.

### Skill: Programming and build (data and analytics engineering)

**What the framework expects at this level**

A senior data engineer is expected to use agreed standards and tools to
design, code, test, correct and document moderate-to-complex programs and
scripts from agreed specifications and subsequent iterations, and to
collaborate with others to review specifications where appropriate.

**Baseline for this role level**

Baseline: 3 — Advanced. "Moderate-to-complex programs" built to agreed
standards, plus reviewing specifications collaboratively, describes solid
independent practice — a considerable step up from a data engineer's simple,
directed scripts.

**Behavioural indicators**

- 0 — None: Cannot design or build a program from a specification without
  significant direction.
- 1 — Beginner: Builds simple programs from a clear specification, with
  substantial review needed.
- 2 — Intermediate: Builds moderately complex programs with some review.
- 3 — Advanced: Independently designs, builds, tests and documents
  moderate-to-complex programs to agreed standards, and collaborates on
  reviewing specifications.
- 4 — Expert: Sets programming standards and takes overall technical
  responsibility across a project.

**Evidence to gather**

- Review a program or script the candidate has built and ask them to explain
  the design choices and how it was tested.
- Ask about a time they reviewed a specification with colleagues before
  building against it.

### Skill: Testing

**What the framework expects at this level**

A senior data engineer is expected to review requirements and specifications
and define test conditions, identify issues and risks associated with the
work, and analyse and report test activities and results.

**Baseline for this role level**

Baseline: 3 — Advanced. Fully independent test design and reporting, without
the qualifying support this same wording is baselined against at the level
below, is Advanced practice.

**Behavioural indicators**

- 0 — None: Cannot define test conditions from a set of requirements.
- 1 — Beginner: Executes test scripts reliably but needs help defining test
  conditions.
- 2 — Intermediate: Defines test conditions for straightforward requirements
  with some support.
- 3 — Advanced: Independently reviews requirements and specifications, defines
  test conditions, identifies risks in the work, and reports results clearly
  enough to inform a decision.
- 4 — Expert: Sets testing standards across the team.

**Evidence to gather**

- Ask the candidate to describe how they would turn a set of requirements
  into test conditions for a new streaming data system.
- Ask for an example of a risk they identified through testing that would
  otherwise have gone unnoticed.
