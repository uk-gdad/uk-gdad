# Associate Data Analyst - Competency Assessment

## Introduction

This assessment is for an assessor — a line manager, a hiring panel member, or
a reviewer — judging whether a candidate or an employee meets the baseline
abilities required for the Data role of Data analyst, at the Associate data
analyst role level. It measures demonstrated skill against the UK GDAD
Profession Capability Framework's own description of this role level, for a
hiring decision, a promotion board, onboarding, or a capability check.

An associate data analyst supports data analysis activities and projects,
developing their skills by working closely with other data professionals.
This assessment looks for foundational understanding and early, supervised
practice — explaining why something matters and attempting it with support —
not independent delivery.

This assessment is one input among several into a decision, never the whole of
it. Read `## Advisory` before using it.

## Advisory

This competency assessment is created by AI and is a work in progress for
educational purposes. It is not a validated assessment instrument — it has
not been piloted, normed or checked for adverse impact — and a rating on this
form must never be the sole basis for a hiring, promotion, pay, performance or
disciplinary decision. Before using it, consult your organisation's human
resources, people development, occupational psychology or legal compliance
colleagues.

## How to use this assessment

**Preparing.** Read `## About this role level` first, then gather whatever
evidence exists: a CV or portfolio, a structured interview, a work sample or
task (for example, a short, guided data-cleaning or charting exercise), direct
observation of the candidate shadowing or pairing, or references.

**Score on evidence, not impression.** Every rating must trace to something
the person did, said, produced, or was observed doing. For an associate-level
candidate, "unknown" is a normal and expected answer for several skills —
record it as unknown rather than guess.

**Consistency.** Score every candidate for this role level the same way. For a
hiring or promotion decision, have more than one assessor score independently
before comparing notes.

**Fairness.** Every rating and every piece of evidence you gather must be
about demonstrated, job-related behaviour — see
[Fair and lawful use](#fair-and-lawful-use) in the project specification.
Never let a rating be coloured by anything other than what the person actually
did, said, or produced.

## Rating scale

Every skill in the competency matrix below is rated on the same five-point
scale. This is a **proficiency** scale — it rates how well the person does the
thing, on the evidence available, not how often they do it or how they feel
about it.

| Value | Rating | Meaning |
| ---: | --- | --- |
| 0 | None | No demonstrated experience of this skill |
| 1 | Beginner | Just starting to learn the skill; requires close supervision |
| 2 | Intermediate | Knows the basics and can perform tasks with some guidance |
| 3 | Advanced | Has a strong grasp of the skill and can work independently |
| 4 | Expert | Demonstrates full mastery and can teach or guide others in the skill |

**Worked example — Data visualisation.** The framework expects an associate
data analyst to "develop and use an appropriate data visualisation under
supervision to tell a meaningful story that is relevant to set goals". A
candidate who, given a simple data set and a chart type, cannot produce a
readable chart even with help is showing **0 — None**. A candidate who, with
guidance, builds a simple bar or line chart that correctly shows the data and
can say what story it tells is showing **1 — Beginner** — the baseline this
level expects. A candidate who, unprompted, chooses the right chart type for
the message and checks it is accessible (for example, that colour is not the
only way information is conveyed) is showing evidence closer to
**2 — Intermediate**, above this level's own baseline.

## About this role level

The Data profession's Data analyst role collects, manages, explores and shares
data to support organisational objectives and deliver business impact. Across
the role, a data analyst identifies, collects and moves data between a range
of systems; applies data analysis and data visualisation tools and
techniques; prepares, manages and models data, following appropriate
standards and practices; and communicates data, insights and conclusions in
appropriate formats.

The role has four levels, in order: Associate data analyst, Data analyst,
Senior data analyst, and Principal data analyst. This assessment is for the
first of them.

An **associate data analyst** supports data analysis activities and projects,
and develops their skills in data analysis by working closely with other data
professionals. At this role level, they will support the development and
delivery of data analysis and data projects, develop analytical approaches
and data visualisations under supervision, and work with others to understand
roles within a multi-disciplinary team and how data analysts work with them.
It is a supervised, learning-first level.

The framework names nine skills for this role level: Applying statistical
and analytical tools and techniques, Communicating between the technical and
non-technical, Data ethics and privacy, Data management, Data preparation and
linkage, Data visualisation, Delivering business impact through data,
Developing code for analysis, and Managing a data project. The framework
lists Managing a data project three times in the published summary, with
identical wording each time; this assessment treats it as the one skill it
is.

## Competency matrix

### Skill: Applying statistical and analytical tools and techniques

**What the framework expects at this level**

An associate data analyst is expected to support the development of
statistical and analytical insights and reports under supervision, explain the
benefits of basic statistical and analytical techniques, and explain the
value of quality assurance and best practices in developing statistical and
analytical outputs. This is understanding and supervised support, not
independent analysis.

**Baseline for this role level**

Baseline: 1 — Beginner. "Support... under supervision" and "explain the
benefits" describe knowledge plus first attempts rather than independent
analytical work, so the baseline sits at the first rung above None.

**Behavioural indicators**

- 0 — None: Cannot say why a basic statistical technique, such as an average
  or a simple trend line, might be useful.
- 1 — Beginner: Explains, when asked, why a basic technique is useful and
  contributes to a statistical report under close supervision.
- 2 — Intermediate: Applies a basic statistical technique with only light
  guidance and checks the result makes sense.
- 3 — Advanced: Independently selects and applies appropriate statistical
  techniques to answer a research question.
- 4 — Expert: Develops and teaches others a range of statistical techniques.

**Evidence to gather**

- Ask the candidate to explain, in plain terms, what a basic statistical
  technique such as a mean, median or simple trend shows, and when it might
  mislead.
- Ask about a time they contributed to an analytical report, even in a small
  way, and what their contribution was.

### Skill: Communicating between the technical and non-technical

**What the framework expects at this level**

An associate data analyst is expected to explain why it is important to
communicate technical concepts in non-technical language, and to explain the
types of communication that can be used with internal and external
stakeholders, and their impact.

**Baseline for this role level**

Baseline: 1 — Beginner. As with the other "explain" bullets at this level,
this is knowledge of the idea rather than demonstrated communication skill
under real conditions, so the baseline sits at Beginner.

**Behavioural indicators**

- 0 — None: Cannot say why a technical explanation might confuse a
  non-technical colleague.
- 1 — Beginner: Explains why jargon should be avoided with a non-technical
  audience, and names a couple of communication channels and roughly how they
  differ.
- 2 — Intermediate: Adapts a short explanation for a specific non-technical
  audience with some coaching.
- 3 — Advanced: Independently tailors technical explanations to different
  stakeholders.
- 4 — Expert: Coaches others in adapting technical communication.

**Evidence to gather**

- Ask the candidate to explain a simple data concept, such as what a data set
  is, as if to someone with no data background.
- Ask about a time they had to explain something technical to a non-technical
  person, and what they changed about how they explained it.

### Skill: Data ethics and privacy

**What the framework expects at this level**

An associate data analyst is expected to explain the importance of using data
ethics and privacy in their work, and to identify appropriate channels to
discuss ethical issues, with support.

**Baseline for this role level**

Baseline: 1 — Beginner. Explaining importance and identifying channels with
support is awareness plus a first practical step, which fits Beginner.

**Behavioural indicators**

- 0 — None: Cannot explain why data ethics or privacy matters in their work.
- 1 — Beginner: Explains why data ethics and privacy matter, and, with
  support, can say who they would raise a concern with.
- 2 — Intermediate: Independently identifies the right channel to raise an
  ethical or privacy concern.
- 3 — Advanced: Proactively spots and raises ethical or privacy risks in their
  own work before being asked.
- 4 — Expert: Advises others on data ethics and privacy risk.

**Evidence to gather**

- Ask the candidate why data ethics and privacy matter when working with
  people's data, using an example relevant to the organisation.
- Ask who they would talk to if they were unsure whether a piece of analysis
  raised a privacy concern, in their current or a previous role.
- Do not ask the candidate to disclose any personal data or case details as
  part of this evidence gathering.

### Skill: Data management

**What the framework expects at this level**

An associate data analyst is expected to explain the importance of data
governance policies, and to explain how data management tools, procedures and
methods relate to a specific project.

**Baseline for this role level**

Baseline: 1 — Beginner. Both bullets ask for explanation rather than applying
governance independently, so the baseline sits at Beginner.

**Behavioural indicators**

- 0 — None: Cannot say why data governance policies exist.
- 1 — Beginner: Explains, in general terms, why data governance matters and
  how a specific tool or method relates to a project they have worked on.
- 2 — Intermediate: Follows data governance policy in their own work with
  only light supervision.
- 3 — Advanced: Applies data governance policy independently and spots when a
  project's data management approach does not fit the policy.
- 4 — Expert: Champions and improves data governance practice for others.

**Evidence to gather**

- Ask the candidate to explain why an organisation might have a policy about
  who can access certain data.
- Ask about a data management tool or procedure they have used, and how it
  related to the project they were working on.

### Skill: Data preparation and linkage

**What the framework expects at this level**

An associate data analyst is expected to explain the importance of data
models and their uses, identify appropriate channels in the organisation to
learn about data modelling and quality standards, identify data quality
issues and provide possible solutions, and prepare and cleanse data under
supervision, contributing to making it fit for purpose.

**Baseline for this role level**

Baseline: 1 — Beginner. "Under supervision" and "identify appropriate
channels... to learn" describe a guided first step into real data preparation
work, so the baseline sits at Beginner.

**Behavioural indicators**

- 0 — None: Cannot identify an obvious data quality issue, such as a missing
  or duplicated value, even when pointed at it.
- 1 — Beginner: With supervision, prepares and cleanses a simple data set,
  identifies an obvious data quality issue, and suggests a plausible fix.
- 2 — Intermediate: Prepares and cleanses moderately complex data with only
  light supervision.
- 3 — Advanced: Independently plans and prepares data for a data model.
- 4 — Expert: Develops analytical data models and mentors others in data
  quality practice.

**Evidence to gather**

- Give the candidate a small, simple data extract with an obvious quality
  issue (for example, a duplicated row or a missing value) and ask them to
  spot it and suggest a fix.
- Ask about a time they cleaned or prepared data as part of a course, a
  project, or a previous role.

### Skill: Data visualisation

**What the framework expects at this level**

An associate data analyst is expected to develop and use an appropriate data
visualisation under supervision to tell a meaningful story relevant to set
goals, explain the value of sharing a story effectively, and explain why it
is important to develop inclusive, accessible data visualisations that
recognise different user needs.

**Baseline for this role level**

Baseline: 1 — Beginner. "Under supervision" caps the practical expectation,
while the accessibility point is still at "explain why it's important" rather
than demonstrated practice, so the baseline sits at Beginner.

**Behavioural indicators**

- 0 — None: Cannot produce a readable chart from a simple data set, even with
  help.
- 1 — Beginner: With guidance, builds a simple, correct chart from a small
  data set and explains what story it tells; can say why accessible design
  matters.
- 2 — Intermediate: Chooses an appropriate chart type unprompted and applies
  basic accessible design principles, such as not relying on colour alone.
- 3 — Advanced: Independently develops a range of visualisations tailored to
  different audiences.
- 4 — Expert: Sets visualisation standards and mentors others in accessible
  design.

**Evidence to gather**

- Ask the candidate to sketch or describe how they would visualise a simple
  data set to answer a specific question.
- Ask them to explain why a visualisation should be accessible to someone who
  is colour-blind or uses a screen reader.
- Review a chart or dashboard the candidate has produced, if one is available.

### Skill: Delivering business impact through data

**What the framework expects at this level**

An associate data analyst is expected to explain why it is important to
understand the organisation's priorities, contribute to the development of
data products to deliver business impact, and explain how to align data and
analysis to meet business requirements.

**Baseline for this role level**

Baseline: 1 — Beginner. "Contribute to" and "explain" describe supporting
work and understanding rather than independently delivering a data product,
so the baseline sits at Beginner.

**Behavioural indicators**

- 0 — None: Cannot say why understanding the organisation's priorities
  matters for their work.
- 1 — Beginner: Explains why organisational priorities matter and describes a
  small contribution they made to a data product.
- 2 — Intermediate: Identifies, with some support, how a piece of analysis
  aligns to a specific business requirement.
- 3 — Advanced: Independently develops and delivers a data product that aligns
  to organisational priorities.
- 4 — Expert: Champions the role of data in delivering business impact across
  the organisation.

**Evidence to gather**

- Ask the candidate to explain why it matters that their analysis work
  connects to what the organisation is trying to achieve.
- Ask about a task or project they contributed to, and how it helped the

### Skill: Developing code for analysis

**What the framework expects at this level**

An associate data analyst is expected to explain the importance of coding for
analysis, explain the value of maintaining analytical approach documentation,
and design an analytical approach with support, for example writing simple
code.

**Baseline for this role level**

Baseline: 1 — Beginner. Writing simple code "with support" is a first,
guided step, so the baseline sits at Beginner.

**Behavioural indicators**

- 0 — None: Cannot write even a simple line of analytical code with support.
- 1 — Beginner: Writes simple code with support to carry out a basic
  analytical task, and explains why documenting the approach matters.
- 2 — Intermediate: Writes simple code with only light support and documents
  it adequately.
- 3 — Advanced: Independently designs an analytical approach and the code to
  implement it.
- 4 — Expert: Sets coding standards and reviews others' analytical code.

**Evidence to gather**

- Ask the candidate to describe or, if appropriate, demonstrate a simple piece
  of analytical code they have written, for example in a spreadsheet formula
  language, SQL, Python or R.
- Ask about any coursework, tutorial, or self-directed learning involving
  code for data analysis.

### Skill: Managing a data project

**What the framework expects at this level**

An associate data analyst is expected to understand a problem statement and
explain the intended outcome of a data project, explain the importance of
data in solving a problem, and explain why it is important to adapt their
ways of working to deliver different project outcomes and requirements. The
framework lists this skill three times in the published summary, with
identical wording each time; the bullets are merged here into one block.

**Baseline for this role level**

Baseline: 1 — Beginner. Every bullet asks for understanding and explanation,
not for running or contributing structured activity to a project, so the
baseline sits at Beginner.

**Behavioural indicators**

- 0 — None: Cannot explain what a given data project is trying to achieve.
- 1 — Beginner: Explains, in their own words, what a data project's problem
  statement means and why data matters to solving it.
- 2 — Intermediate: Contributes to defining a problem statement or gathering
  requirements for a data project, with support.
- 3 — Advanced: Independently plans and implements stages of a data project's
  life cycle.
- 4 — Expert: Advises on problem statement development and project life cycle
  planning for others.

**Evidence to gather**

- Ask the candidate to explain, in their own words, the goal of a data
  project they have been part of, even in a small role.
- Ask why they think the way of working on a data project might need to
  change depending on what it is trying to achieve.
