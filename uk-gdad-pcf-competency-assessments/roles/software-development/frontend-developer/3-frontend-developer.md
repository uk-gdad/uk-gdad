# Frontend Developer - Competency Assessment

## Introduction

This is a competency assessment for the role of Frontend developer, at the
Frontend developer level. It is written for an assessor — a line manager, an
interview panel, or a reviewer — who needs to judge whether a candidate or an
employee possesses the baseline abilities this role level requires, for a
hiring decision, a promotion board, onboarding, or a capability check
against the framework.

This assessment is one input among several into that judgement, never the
whole of it. Read `## Advisory` below before you use any part of this
document.

## Advisory

This competency assessment is created by AI and is a work in progress for
educational purposes. It is not a validated assessment instrument — it has not
been piloted, normed or checked for adverse impact — and a rating on this form
must never be the sole basis for a hiring, promotion, pay, performance or
disciplinary decision. Before using it, consult your organisation's human
resources, people development, occupational psychology or legal compliance
colleagues.

## How to use this assessment

**Preparing.** Read `## About this role level` before you score anything, so
that every rating is anchored to what a frontend developer at this level is
actually expected to do. Gather whatever evidence exists before you start: a
CV or portfolio, a structured interview, a work sample or task, direct
observation of the person's day-to-day work, or references.

**Scoring on evidence, not impression.** Every rating in the competency matrix
must trace to something the person did, said, produced, or was observed
doing. If you cannot point to evidence for a rating, record it as unknown
rather than guess.

**Consistency.** Score every candidate for this role level the same way.
Where possible, have more than one assessor score independently and compare
notes afterwards, especially for a hiring or promotion decision.

**Fairness.** This is an unvalidated, AI-drafted instrument. Used
inconsistently, it can produce unlawful adverse impact — treating one
candidate less favourably than another for reasons that have nothing to do
with the job. Consistent, evidence-based administration by more than one
assessor materially reduces that risk. Never let a rating be influenced by
anything other than demonstrated, job-related evidence.

## Rating scale

Every skill in the competency matrix is rated on the same five-point scale:

| Value | Rating | Meaning |
| ---: | --- | --- |
| 0 | None | No demonstrated experience of this skill |
| 1 | Beginner | Just starting to learn the skill; requires close supervision |
| 2 | Intermediate | Knows the basics and can perform tasks with some guidance |
| 3 | Advanced | Has a strong grasp of the skill and can work independently |
| 4 | Expert | Demonstrates full mastery and can teach or guide others in the skill |

This is a **proficiency** scale, not a frequency scale: it rates how well the
person does the thing, on the evidence available, not how often they do it.

**Worked example — Leadership and guidance (frontend developer).** At
Intermediate (2), a candidate could describe following agreed good practice
and giving straightforward feedback to a peer, without yet handling a
genuine disagreement. At Advanced (3) — this level's baseline — they can
describe resolving a technical dispute between wider peers and indirect
stakeholders, taking all views into account, and making a decision
characterised by real risk and complexity rather than a low-stakes one. At
Expert (4), above this level's baseline, they would be setting the standard
other leads are measured against, which is more influence than this level
expects.

## About this role level

A frontend developer designs, builds and improves website software that
meets user needs. In this role, a person is responsible for writing clean,
accessible code following a progressive enhancement approach, creates code
that is open by default and easy for others to reuse, designs software which
meets user needs and creates meaningful interactions and relationships with
users, and has an understanding of the three fundamental frontend
technologies: HTML, CSS and JavaScript.

This assessment covers the **Frontend developer** level, the third step of
the role's ladder — the point at which the role becomes fully independent.
The full ladder, in order, is: Apprentice frontend developer, Junior frontend
developer, Frontend developer (this level), Senior frontend developer, Lead
frontend developer, and Head of frontend development.

A frontend developer builds software components, primarily in the form of
user interfaces. At this level, a person is expected to:

- collaborate and work closely with other disciplines to develop designs and
  working prototypes based on user needs and in support of organisational
  aims
- develop software components that form part of a product to meet user needs
- write clean, well-tested code that follows web standards
- coach and mentor more junior colleagues

This level names eleven skills: Accessibility, Communicating information,
Community collaboration, Leadership and guidance (frontend developer),
Modern development standards, Programming and build (frontend developer),
Prototyping, Strategic thinking, Systems integration (frontend developer),
User focus (frontend developer), and Web performance optimisation.

## Competency matrix

### Skill: Accessibility

**What the framework expects at this level**

A frontend developer is expected to build user interfaces that meet a
predefined set of standards, champion accessibility to internal stakeholders,
offer design feedback to mitigate the risk of failing accessibility testing,
and offer recommendations on the best tools and methods to use when
accessibility testing.

**Baseline for this role level**

Baseline: 3 — Advanced. Championing accessibility to stakeholders and giving
design feedback are independent, influencing activities well beyond the
junior level's build-to-standard-under-direction wording, matching this
level's independent delivery and coaching accountabilities.

**Behavioural indicators**

- 0 — None: builds an interface without checking it against a stated
  standard.
- 1 — Beginner: builds to a standard with frequent correction.
- 2 — Intermediate: builds to a predefined standard consistently, but has
  not yet championed accessibility to stakeholders unprompted.
- 3 — Advanced: builds interfaces to a predefined accessibility standard
  independently, champions accessibility to internal stakeholders, offers
  design feedback that heads off testing failures, and recommends
  appropriate tools and methods for testing.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask about a time the candidate raised an accessibility concern with a
  designer or stakeholder before it became a problem in testing.
- Ask them to recommend a tool or method for accessibility testing, and why.

### Skill: Communicating information

**What the framework expects at this level**

A frontend developer is expected to work collaboratively and build
relationships with others, identify issues through Agile "health checks" and
work with others to address them, manage stakeholder expectations, be
flexible and capable of proactive and reactive communication, and host or
moderate difficult discussions within the team or with senior stakeholders.

**Baseline for this role level**

Baseline: 3 — Advanced. Hosting or moderating difficult discussions with
senior stakeholders is a clear step up from the junior level's representing-
the-team-externally wording, matching this level's collaborate-closely-with-
other-disciplines accountability.

**Behavioural indicators**

- 0 — None: struggles to manage a stakeholder's expectations without
  support.
- 1 — Beginner: communicates reactively but is not yet proactive.
- 2 — Intermediate: manages stakeholder expectations for straightforward
  situations, with some guidance on harder ones.
- 3 — Advanced: identifies issues through team health checks and works with
  others to address them, manages stakeholder expectations proactively, and
  has hosted or moderated a difficult discussion with a senior stakeholder.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask the candidate to describe a difficult discussion they hosted or
  moderated, and how they handled it.
- Ask about an issue they identified through a team health check, and what
  they did about it.

### Skill: Community collaboration

**What the framework expects at this level**

A frontend developer is expected to work collaboratively in a group, actively
networking with others, adapt feedback to ensure it is effective and
lasting, use their topic to identify problems or issues in the team dynamic
and rectify them, and identify issues through Agile "health checks" with the
team, helping to stimulate the right responses.

**Baseline for this role level**

Baseline: 3 — Advanced. Rectifying team dynamic issues and stimulating the
right response to a health check are active, independent contributions well
beyond the junior level's contribute-and-recognise wording, matching this
level's coaching accountability.

**Behavioural indicators**

- 0 — None: does not notice or engage with issues affecting how the team
  works together.
- 1 — Beginner: recognises a team issue but relies on someone else to act on
  it.
- 2 — Intermediate: raises team issues and contributes to fixing them, with
  guidance.
- 3 — Advanced: actively networks and collaborates across the group, adapts
  feedback so it lands well and lasts, and has used their own expertise to
  identify and rectify a genuine team dynamic issue.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask about a time the candidate used their technical expertise to spot and
  fix a team dynamic issue, not just a technical one.
- Ask how they adapt feedback depending on who they are giving it to.

### Skill: Leadership and guidance (frontend developer)

**What the framework expects at this level**

A frontend developer is expected to understand the impact of decisions, make
decisions characterised by different levels of risk and complexity, and
resolve technical disputes between wider peers and indirect stakeholders,
taking into account all views and opinions.

**Baseline for this role level**

Baseline: 3 — Advanced. This is a substantial escalation from the junior
level's follow-agreed-practice wording, to making risk-bearing decisions and
resolving genuine disputes, matching this level's coach-and-mentor
accountability.

**Behavioural indicators**

- 0 — None: avoids making a decision that carries any risk, deferring
  everything to someone else.
- 1 — Beginner: makes low-risk decisions but needs support for anything more
  complex.
- 2 — Intermediate: makes decisions of moderate risk and complexity with
  occasional guidance.
- 3 — Advanced: understands the impact of a decision before making it, makes
  decisions characterised by real risk and complexity independently, and has
  resolved a technical dispute between wider peers or indirect stakeholders
  by weighing all views fairly.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask the candidate to describe a technical dispute they resolved between
  people who disagreed, and how they weighed the different views.
- Ask about a decision they made that carried real risk, and how they
  thought through the impact beforehand.

### Skill: Programming and build (frontend developer)

**What the framework expects at this level**

A frontend developer is expected to collaborate with others when necessary to
review specifications, and to use the agreed specifications to build, test
and document user interfaces of medium to high complexity, using the right
standards and tools.

**Baseline for this role level**

Baseline: 3 — Advanced. "Medium to high complexity" and independent use of
agreed specifications match a strong, independent grasp of the skill, and
this level's "develop software components that form part of a product"
accountability supports a baseline above Intermediate.

**Behavioural indicators**

- 0 — None: cannot build a working user interface from a specification
  without heavy support.
- 1 — Beginner: needs step-by-step direction to build from a specification.
- 2 — Intermediate: builds simple-to-medium complexity interfaces from a
  specification, with some guidance.
- 3 — Advanced: builds, tests and documents user interfaces of medium to
  high complexity independently, using the right standards and tools, and
  collaborates on specification review when needed.
- 4 — Expert: does this reliably at the highest complexity the role sees, and
  is sought out to review others' work.

**Evidence to gather**

- Set a realistic, medium-complexity interface task and observe the
  candidate's full process: specification review, build, test and
  documentation.
- Ask to see a complex user interface the candidate built recently, and
  discuss the decisions they made.

### Skill: Prototyping

**What the framework expects at this level**

A frontend developer is expected to approach prototyping as a team activity,
actively soliciting prototypes and testing with others, to establish design
patterns and iterate them, and to use a variety of prototyping methods and
choose the most appropriate.

**Baseline for this role level**

Baseline: 2 — Intermediate. This is a meaningful step up from the junior
level's understanding-only wording, involving active solicitation and method
choice, but still framed as a team activity rather than leading it, matching
"knows the basics and can perform tasks with some guidance."

**Behavioural indicators**

- 0 — None: has never actively solicited a prototype or tested one with
  others.
- 1 — Beginner: has taken part in a prototyping activity someone else set
  up.
- 2 — Intermediate: actively solicits prototypes, tests them with others,
  and chooses a reasonable method for the situation, sometimes checking their
  choice with a colleague.
- 3 — Advanced: consistently chooses the most appropriate prototyping method
  for a given problem, and establishes design patterns that get reused.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask the candidate to describe a prototype they set up, why they chose that
  method, and what they learned from testing it with others.
- Ask about a design pattern that came out of a prototyping exercise they led
  or contributed to.

### Skill: Strategic thinking

**What the framework expects at this level**

A frontend developer is expected to work within a strategic context and
communicate how activities meet strategic goals, and to contribute to the
development of strategy and policies.

**Baseline for this role level**

Baseline: 2 — Intermediate. Contributing to strategy development is a real
step up from the junior level's administrative-support wording, but this
level's own accountabilities are still mostly about delivering software
rather than setting direction, so Intermediate — not yet independent
ownership of strategy — is the better fit.

**Behavioural indicators**

- 0 — None: cannot explain how their work connects to a wider strategic

  only contributing when asked.
- 4 — Expert: not expected at this level.

### Skill: Systems integration (frontend developer)

**What the framework expects at this level**

A frontend developer is expected to build static assets from source code and
test that the resulting user interface works as expected when delivered over
the internet, and to work on integration tests and support configuration of
the network part of the system as part of a wider team.

**Baseline for this role level**

Baseline: 2 — Intermediate. Building and testing static assets independently
is a real step up from the junior level's awareness-only wording, while
network configuration is done as part of a wider team, matching "knows the
basics and can perform tasks with some guidance."

**Behavioural indicators**

- 0 — None: cannot build or test a static asset delivered over the internet.
- 1 — Beginner: builds a static asset with significant support.
- 2 — Intermediate: builds static assets from source code and tests that the
  interface works as delivered, and contributes to integration tests and
  network configuration as part of a wider team.
- 3 — Advanced: leads this work rather than only contributing to it, across
  more complex delivery scenarios.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask the candidate to describe a time they built and tested a static asset
  and confirmed it worked as delivered over the internet.
- Ask about their contribution to an integration test or network
  configuration task as part of a wider team.

### Skill: User focus (frontend developer)

**What the framework expects at this level**

A frontend developer is expected to collaborate effectively with user
researchers and interaction designers to represent user needs internally, to
champion user research to focus on all users, and to prioritise and define
approaches to understand the user story, guiding others in doing so.

**Baseline for this role level**

Baseline: 3 — Advanced. Championing research and guiding others is a clear
step up from the junior level's explain-the-purpose wording, matching this
level's collaborate-closely-with-other-disciplines and coach-and-mentor
accountabilities.

**Behavioural indicators**

- 0 — None: does not represent user needs in their work or decisions.
- 1 — Beginner: uses user evidence when given it, but does not champion
  research.
- 2 — Intermediate: collaborates with user researchers and uses evidence
  independently, with some guidance on prioritising approaches.
- 3 — Advanced: collaborates effectively with user researchers and
  interaction designers to represent user needs internally, champions
  research to focus on all users, and guides others on the right approach to
  understanding a user story.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask the candidate to describe a time they championed user research that
  changed a decision on a piece of work.
- Ask about a time they guided a colleague on the right approach to
  understanding a user story.

### Skill: Web performance optimisation

**What the framework expects at this level**

A frontend developer is expected to explain the principles of web
performance, explain how poor performance can negatively affect user
experience, help improve web performance, and help identify and resolve web
performance issues.

**Baseline for this role level**

Baseline: 2 — Intermediate. Helping identify and resolve issues, not just
under supervision, is a step up from the junior level's help-under-
supervision wording, matching "knows the basics and can perform tasks with
some guidance."

**Behavioural indicators**

- 0 — None: cannot explain how poor performance affects user experience.
- 1 — Beginner: explains the principles but has not identified a real
  performance issue themselves.
- 2 — Intermediate: explains the principles of web performance and how poor
  performance harms user experience, and has helped identify and resolve a
  real performance issue.
- 3 — Advanced: identifies and resolves performance issues independently and
  proactively, without waiting to be asked.
- 4 — Expert: not expected at this level.

**Evidence to gather**

- Ask the candidate to describe a real web performance issue they helped
  identify and resolve.
- Ask them to explain how a specific performance problem affects a real
  user's experience of a page.
