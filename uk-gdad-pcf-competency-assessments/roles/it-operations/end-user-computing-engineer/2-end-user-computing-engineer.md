# End User Computing Engineer - Competency Assessment

## Introduction

This assessment is for an assessor — a line manager, an interview panel
member, or anyone else evaluating a candidate or an employee — who needs to
judge whether a person has the baseline abilities the IT operations
profession's end user computing engineer role level requires. It measures
demonstrated skill against the UK GDAD Profession Capability Framework's own
description of this level, for a hiring decision, a promotion or progression
board, onboarding a new starter, or a periodic capability check. It is one
input into that decision, never the whole of it — see `## Advisory` before
you begin.

## Advisory

This competency assessment is created by AI and is a work in progress for
educational purposes. It is not a validated assessment instrument — it has
not been piloted, normed or checked for adverse impact — and a rating on this
form must never be the sole basis for a hiring, promotion, pay, performance or
disciplinary decision. Before using it, consult your organisation's human
resources, people development, occupational psychology or legal compliance
colleagues.

## How to use this assessment

**Preparing.** Read `## About this role level` first, so you know what the
framework actually expects before you look at any evidence. Then gather what
exists for this person: a CV or portfolio, a structured interview, a work
sample or task, direct observation of them at work, or references from people
who have worked with them. At this level the framework expects on-site,
first-time fault resolution with escalation where needed, and some coaching of
associates, so look for evidence of hands-on fixing and of explaining things to
someone newer, not only of following a script.

**Score on evidence, not impression.** Every rating must trace to something
the person did, said, produced, or was observed doing. If you cannot point to
evidence for a rating, record it as unknown rather than guess — an honest gap
teaches you more than a guess dressed up as a score.

**Stay consistent.** Score every candidate for this role level the same way,
using the same evidence sources wherever you can. For a hiring or promotion
decision, have more than one assessor score independently, then compare notes,
rather than settling on a single view first.

**Fairness.** An unvalidated, AI-drafted instrument like this one, used
inconsistently, can produce unlawful adverse impact even when nobody intends
it. Consistent, evidence-based administration by more than one assessor
materially reduces that risk. Never let a rating be influenced by anything
other than demonstrated, job-related evidence.

## Rating scale

Every skill in the competency matrix is rated on the same five-point
proficiency scale — how well the person does the thing, on the evidence
available, not how often they do it.

| Value | Rating | Meaning |
| ---: | --- | --- |
| 0 | None | No demonstrated experience of this skill |
| 1 | Beginner | Just starting to learn the skill; requires close supervision |
| 2 | Intermediate | Knows the basics and can perform tasks with some guidance |
| 3 | Advanced | Has a strong grasp of the skill and can work independently |
| 4 | Expert | Demonstrates full mastery and can teach or guide others in the skill |

**Worked example.** Take Skill: Incident management. At 1 — Beginner, a
candidate can register an incident they are handed and follow a runbook step
by step, but needs someone to check each step before moving on. At 2 —
Intermediate, the baseline for this level, they identify and register an
incident unassisted, gather the information a service desk manager or incident
manager needs to act on it, and allocate it to the right channel without being
told which one. At 3 — Advanced, they diagnose the incident themselves,
prioritise it correctly against other open work and find the resolution rather
than only routing it onward. Calibrate against evidence like this before you
start scoring.

## About this role level

IT operations role: End user computing engineer. An end user computing
engineer is responsible for managing the product life cycle of all
service-raised incidents (incident control) and all service requests (request
control), which requires the use of knowledge management. In this role, you
are also responsible for informing customers on progress and advising on
workarounds where necessary, as well as the support and maintenance of end
user services.

The role has four levels, in order: associate end user computing engineer,
end user computing engineer, senior end user computing engineer, lead end user
computing engineer, and principal end user computing engineer. This assessment
covers end user computing engineer, the second of those.

Role level: End user computing engineer. An end user computing engineer works
on-site, maintaining hardware and fixing technical problems as quickly as
possible.

At this role level, the framework expects someone to:

- provide first-time resolution by troubleshooting and diagnosing or
  escalating faults, or both, to service desk managers, incident managers and
  problem managers to investigate and resolve
- coach associates and share knowledge with team colleagues

The framework names eleven skills for this level: Asset and configuration
management, Change management, IT service reporting, Incident management,
Ownership and initiative, Problem management, Service focus, Service
management framework knowledge, Technical specialism, Testing, and User
focus.

## Competency matrix

### Skill: Asset and configuration management

**What the framework expects at this level**

An end user computing engineer maintains secure configuration and accurate
information, controls IT assets in one or more areas, and verifies the
location and state of IT assets.

**Baseline for this role level**

Baseline: 2 — Intermediate. Controlling assets in one or more areas and
verifying their location and state without being told each step is routine,
guided work — the framework does not yet ask this level to manage compliance
or risk across a whole estate, so Intermediate rather than Advanced.

**Behavioural indicators**

- 0 — None: cannot say where the asset register is or what it is for.
- 1 — Beginner: updates the asset register when told exactly what to change.
- 2 — Intermediate: keeps configuration and asset records accurate for their
  own area day to day, and can verify an asset's location and state without
  prompting.
- 3 — Advanced: spots and corrects a discrepancy in the asset register before
  it causes a problem, and improves how their team keeps records.
- 4 — Expert: owns asset and configuration accuracy across a whole service and
  is the person others check a difficult record against.

**Evidence to gather**

- Ask the candidate to describe how they keep an asset or configuration record
  accurate day to day, with an example.
- Review an asset or configuration record they maintained, and ask what would
  have gone wrong if it had drifted.
- Ask a referee for an example of the candidate catching an inaccurate asset
  record before it caused an incident.

### Skill: Change management

**What the framework expects at this level**

An end user computing engineer implements change requests and applies change
control procedures under supervision.

**Baseline for this role level**

Baseline: 1 — Beginner. The framework's own wording — "under supervision" —
sets the ceiling for this skill at this level; the candidate implements what
is asked, checked by someone else, which is a Beginner description even where
they do it well.

**Behavioural indicators**

- 0 — None: has not implemented a change request.
- 1 — Beginner: implements a change request and applies change control
  procedure, with a colleague checking the work.
- 2 — Intermediate: implements routine change requests correctly without
  needing a check at every step.
- 3 — Advanced: implements complex changes unsupervised and helps a colleague
  through the change control procedure.
- 4 — Expert: is trusted to implement high-impact changes without supervision.

**Evidence to gather**

- Ask the candidate to walk through a change request they implemented and what
  the change control procedure required of them.
- Review a change record or ticket they closed.
- Ask a referee whether the candidate's implemented changes have needed
  correction after the fact.

### Skill: IT service reporting

**What the framework expects at this level**

An end user computing engineer collates data from data repositories and
provides basic reporting, and can explain what a Key Performance Indicator
(KPI) is and why it is important.

**Baseline for this role level**

Baseline: 1 — Beginner. "Basic reporting" and explaining a concept, rather
than producing a report to an agreed timeframe for stakeholders, is
close-supervision-level work under the scale's own description.

**Behavioural indicators**

- 0 — None: cannot explain what a KPI is.
- 1 — Beginner: collates data from a data repository and produces a basic
  report when asked, and can explain what a KPI is and why it matters.
- 2 — Intermediate: produces basic reports to a regular pattern without being
  asked each time, and checks the data before passing it on.
- 3 — Advanced: produces reports to an agreed format and timeframe and can
  interpret what the data shows to a stakeholder.
- 4 — Expert: designs a new reporting approach that others adopt.

**Evidence to gather**

- Ask the candidate to explain a KPI relevant to end user services and why it
  matters to the business.
- Review a basic report they produced from raw data.
- Ask a referee how reliably the candidate's reports have been accurate and on
  time.

### Skill: Incident management

**What the framework expects at this level**

An end user computing engineer identifies and registers incidents, gathering
the required information and allocating it to the appropriate channel.

**Baseline for this role level**

Baseline: 2 — Intermediate. Identifying, registering and correctly routing an
incident unassisted is guided-but-independent triage work, not close
supervision, and not yet the diagnosis and resolution work of the next level
up.

**Behavioural indicators**

- 0 — None: cannot say what information an incident record needs.
- 1 — Beginner: registers an incident someone else has already identified,
  with the details checked before it is filed.
- 2 — Intermediate: identifies an incident, gathers the information needed and
  allocates it to the right channel without prompting.
- 3 — Advanced: spots that an incident is really a symptom of something wider
  and flags it for problem management before being asked to.
- 4 — Expert: is the person colleagues check with when an incident does not
  fit the usual channels.

**Evidence to gather**

- Walk through a real or simulated fault report and observe how the candidate
  gathers information and decides where to route it.
- Ask for an example of an incident they registered and what happened to it
  next.
- Ask a referee about the accuracy of the candidate's incident records.

### Skill: Ownership and initiative

**What the framework expects at this level**

An end user computing engineer owns an issue until a new owner has been found
or the problem has been mitigated or resolved.

**Baseline for this role level**

Baseline: 2 — Intermediate. Holding onto an issue through a handover rather
than dropping it once escalated is basic, guided-but-independent
professionalism expected of every working-level engineer, not yet the
proactive accountability the framework describes at lead level.

**Behavioural indicators**

- 0 — None: drops an issue once it is out of their hands.
- 1 — Beginner: keeps an issue open on their own list but needs reminding to
  chase it.
- 2 — Intermediate: tracks an issue through to a confirmed handover or
  resolution without being chased.
- 3 — Advanced: proactively checks that a handed-over issue actually landed
  with its new owner and was picked up.
- 4 — Expert: is the person others rely on to never let an issue slip, across
  a whole shift or team.

**Evidence to gather**

- Ask for an example of an issue the candidate followed through to resolution
  or a confirmed handover.
- Ask a referee whether issues assigned to the candidate have gone missing or
  stalled.
- Review a ticket history showing the candidate's ownership of an issue over
  time.

### Skill: Problem management

**What the framework expects at this level**

An end user computing engineer investigates problems in systems, processes and
services, with an understanding of the level of a problem — for example,
strategic, tactical or operational — and contributes to the implementation of
remedies and preventative measures.

**Baseline for this role level**

Baseline: 2 — Intermediate. Investigating with an understanding of a
problem's level and contributing to remedies is applied, guided work; the
framework does not yet ask this level to determine the resolution or
preventative measures alone, which is why this sits below Advanced.

**Behavioural indicators**

- 0 — None: cannot distinguish a problem from an incident.
- 1 — Beginner: investigates a problem when told exactly what to look at.
- 2 — Intermediate: investigates a problem unassisted, correctly judges
  whether it is strategic, tactical or operational, and contributes ideas to
  the remedy.
- 3 — Advanced: leads the investigation of a problem and proposes the
  preventative measure that is adopted.
- 4 — Expert: spots patterns across multiple problems that others have missed.

**Evidence to gather**

- Ask the candidate to describe a problem they investigated and how they
  judged its level.
- Review a problem record or root-cause note they contributed to.
- Ask a referee about the candidate's contribution to a preventative measure
  that was implemented.

### Skill: Service focus

**What the framework expects at this level**

An end user computing engineer takes inputs and establishes coherent
frameworks that work.

**Baseline for this role level**

Baseline: 2 — Intermediate. Turning a set of inputs into a working framework
for their own area of work is applied, guided practice, short of the
bigger-picture, cross-service view the framework describes at senior levels.

**Behavioural indicators**

- 0 — None: cannot describe how their daily tasks fit into the wider service.
- 1 — Beginner: follows a service framework someone else has set up.
- 2 — Intermediate: takes several inputs — tickets, requests, escalations —
  and organises their own work into a coherent, working routine.
- 3 — Advanced: improves a service framework so it works better for the
  wider team, not just themselves.
- 4 — Expert: designs a service framework that a whole team adopts.

**Evidence to gather**

- Ask the candidate to describe how they organise a typical day's mix of
  incidents, requests and follow-ups into a coherent routine.
- Ask a referee whether the candidate's way of working has helped or hindered
  the wider team.
- Review any process note or checklist the candidate has produced for their
  own work.

### Skill: Service management framework knowledge

**What the framework expects at this level**

An end user computing engineer shows they have a Level 3 service management
framework qualification.

**Baseline for this role level**

Baseline: 2 — Intermediate. A named, held qualification demonstrates working
knowledge applied with some guidance; it is evidence of grounding rather than
of teaching others, so Intermediate rather than Advanced or Expert.

**Behavioural indicators**

- 0 — None: holds no service management framework qualification and cannot
  describe the framework's basic concepts.
- 1 — Beginner: is working towards a Level 3 service management framework
  qualification.
- 2 — Intermediate: holds a Level 3 service management framework
  qualification and applies its concepts correctly in day-to-day work.
- 3 — Advanced: applies the framework's concepts to improve how their team
  works, beyond what the qualification alone requires.
- 4 — Expert: holds a higher-level qualification or is asked to explain the
  framework to others.

**Evidence to gather**

- Ask the candidate to show their Level 3 service management framework
  certificate or equivalent evidence.
- Ask the candidate to explain a framework concept, such as incident versus
  problem, in their own words.
- Ask a referee how the candidate applies the framework in practice, not just
  whether they hold the certificate.

### Skill: Technical specialism

An end user computing engineer assists in technical support activities and
carries out agreed or routine maintenance and administration tasks.

**Baseline for this role level**

Baseline: 2 — Intermediate. Carrying out agreed, routine maintenance tasks

### Skill: User focus

**What the framework expects at this level**

An end user computing engineer identifies and engages with users or
stakeholders to collate user needs evidence, understands and defines research
that fits user needs, and uses quantitative and qualitative data about users
to turn user focus into outcomes.

**Baseline for this role level**

Baseline: 2 — Intermediate. Collating user needs evidence and turning data
into outcomes for a specific fault or request is applied, guided work — real,
but bounded to the individual case in front of them rather than the
cross-channel judgement the framework asks for from senior levels.

**Behavioural indicators**

- 0 — None: fixes the reported fault without asking the user anything about
  their wider need.
- 1 — Beginner: asks the user basic clarifying questions when prompted to.
- 2 — Intermediate: engages the user directly to understand what they
  actually need, not just what they reported, and uses that to resolve the
  issue in a way that works for them.
- 3 — Advanced: spots a pattern in what several users need and feeds it back
  so the service improves for everyone.
- 4 — Expert: shapes how the wider team engages with users.

**Evidence to gather**

- Observe or ask the candidate to describe a call or interaction where they
  found out more than the user's initial report.
- Ask for an example where understanding the user's actual need changed how
  they resolved an issue.
- Ask a referee how users or colleagues describe the candidate's manner with
  users.
