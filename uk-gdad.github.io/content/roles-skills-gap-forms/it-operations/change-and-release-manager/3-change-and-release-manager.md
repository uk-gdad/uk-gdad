# Change and release manager - skills gap form

## Introduction

This form is for you if you work as a change and release manager in the UK Government Digital and Data
profession. Human resources or your manager has sent it so that you can set out what you do now, where
the gaps are, and what would close them.

The framework describes this level as ensuring that technical changes to IT services are adequately
assessed for impact, prioritised, scheduled, authorised and implemented, in line with processes and using
appropriate tools. You **chair the change advisory board**. It expects you to provide an escalation
point, make decisions for all technical changes, and co-ordinate releases and interdependencies.

*Make decisions for all technical changes* is an unusually absolute phrase. It means the difficult calls
— the urgent change on a Friday afternoon, the release that has already slipped twice — arrive at you,
and that the answer "no" has to be available or the role is decorative.

Change and release manager is the top of this role. Eleven skills. Expect about 35 minutes.

## About this role level

**The role: change and release manager.** You lead the change advisory board, ensuring adequate risk
assessment and scheduling of technical changes and releases. You own the configuration management
database and the access, security and configuration of change activities and release procedures.

**Your level: change and release manager.** You ensure technical changes are adequately assessed for
impact, prioritised, scheduled, authorised and implemented, in line with processes and using appropriate
tools, and you chair the change advisory board. The framework expects that you:

- provide an escalation point
- make decisions for all technical changes
- co-ordinate releases and interdependencies

**There is no level above this one.** This role has three levels and this is the highest. Where people go
next is a question about other roles — IT service management, service transition, or operations
leadership — and the framework does not define it as a next step, so this form does not invent one.

**Where this level sits:**

1. Configuration analyst
2. Change and release analyst
3. **Change and release manager** — you are here

**Two things worth knowing about this role.**

First, the two levels below yours are worded **almost identically to each other** — ten of eleven skills
match. Your level is where most of the published progression in this role actually happens: asset and
configuration management, change management, community collaboration, incident management, ownership,
problem management, service focus, and user focus all rise.

Second, *Continuity management* is worded as **explain the basic principles** at all three levels,
including yours — the only skill in this role that never changes. Given that you authorise the changes
most likely to threaten continuity, that is worth noticing.

**The eleven skills this form covers**, in the framework's order:

### Skill: Asset and configuration management

**What the framework expects.** Three things: **manage configuration management for the organisation**,
ensuring value for the business and adherence to company policies; ensure that changes to assets are
recorded and controlled appropriately; and **advocate organisational commitment to asset control**.

**What that looks like here.** Advocacy is the item that decides whether the database is any good.
Configuration accuracy is everyone's responsibility and nobody's priority, and it decays unless someone
keeps making the case.

### Skill: Change management

### Skill: Community collaboration

**What the framework expects.** Four things: work collaboratively in a group, actively networking with
others; **adapt feedback to ensure it is effective and lasting**; use your topic to identify problems or
issues in the team dynamic and rectify them; and identify issues through Agile health checks with the
team, and help stimulate the right responses.

**What that looks like here.** Chairing a board where people arrive defensive is a facilitation problem
rather than a process one. A board that feels like a tribunal gets minimal information; one that feels
like collective risk assessment gets the truth.
