# Change and release analyst - skills gap form

## Introduction

This form is for you if you work as a change and release analyst in the UK Government Digital and Data
profession. Human resources or your manager has sent it so that you can set out what you do now, where
the gaps are, and what would close them.

The framework describes this level as planning and rolling out software, and designing and carrying out
procedures for the distribution and installation of changes to systems and services. It expects you to
undertake analysis after release and set the plan for upcoming changes, and to liaise with DevOps and
service designers.

**Analysis after release** is the item worth dwelling on. Most organisations plan changes carefully and
then never look back at whether they worked. Doing that consistently is how a change process gets
better rather than merely heavier.

Eleven skills. Expect about 35 minutes.

## About this role level

**The role: change and release manager.** Change and release managers lead the change advisory board,
ensuring adequate risk assessment and scheduling of technical changes and releases. They own the
configuration management database and the access, security and configuration of change activities and
release procedures.

**Your level: change and release analyst.** You plan and roll out software, and design and carry out
procedures for the distribution and installation of changes to systems and services. The framework
expects that you:

- undertake analysis after release and set the plan for upcoming changes
- liaise with DevOps and service designers

**Where this level sits.** This role has three levels:

1. Configuration analyst
2. **Change and release analyst** — you are here
3. Change and release manager

**Two things worth knowing about this role.**

First, **ten of your eleven skills are worded identically at configuration analyst below you.** Only
*Change management* rose — from implementing changes under supervision to analysing and assessing
impact, documenting requests and actioning them. That is the narrowest published gap between two levels
in the whole framework, so your accountabilities carry the rest of the difference.

Second, the step to change and release manager changes far more: asset and configuration management,
community collaboration, incident management, ownership, problem management, service focus and user focus
all rise, while change management shifts to implementing and optimising the processes themselves.

**The eleven skills this form covers**, in the framework's order:

1. Asset and configuration management
2. Availability and capacity management
3. Change management
4. Community collaboration
5. Continuity management
6. Incident management
7. Ownership and initiative
8. Problem management
9. Service focus
10. Service management framework knowledge
11. User focus

### Skill: Asset and configuration management

**What the framework expects at this level.** Three things: maintain secure configuration and accurate
information; control IT assets in one or more areas; and verify the location and state of IT assets.

**Same wording as configuration analyst.**

**What that looks like here.** Change assessment depends entirely on the accuracy of these records. If
you cannot see what depends on a component, you cannot assess the impact of changing it.

**The next step.** At manager you manage configuration management for the organisation, ensure changes to
assets are recorded and controlled, and advocate organisational commitment to asset control.

### Skill: Change management

**What the framework expects at this level.** Three things: **analyse and assess the impact of change**;
document change requests; and action changes from change requests.

**This is the only skill that rose from configuration analyst**, and it is the core of your job.

**What that looks like here.** Good impact assessment is mostly about knowing what is connected to what,
and asking the person requesting the change the questions they have not thought about. Bad impact
assessment is a form filled in to satisfy a process.

**The next step.** At manager you implement new and current change management processes and support change
management, actively improving and optimising processes.

### Skill: User focus

**What the framework expects at this level.** Two things: **show an awareness or understanding of user
experience analysis and its principles**; and **explain the purpose of user stories and the focus on user
needs**.

**A user story** is a short sentence describing what someone needs and why: "As a caseworker, I need the
release notes in advance so that I can warn my team." It keeps the reason attached to the requirement.

**Same wording as configuration analyst.**

**What that looks like here.** A change that goes perfectly technically and takes a service down at the
worst possible moment for its users has not gone well. Knowing when people actually use a service is
part of scheduling.

**The next step.** At manager you identify and engage with users or stakeholders to collate evidence,
define research that fits user needs, and use data to turn user focus into outcomes.
