# Apprentice DevOps engineer - start here

Welcome. If you are starting out as an apprentice DevOps engineer, this page
is for you: what the role is about, where to find everything else this
repository has for it, and a pathway for building the skills it asks for, one
step at a time.

## Purpose

Development operations engineers underpin good development processes:
managing tools and testing environments, keeping central code control tidy,
maintaining development standards, and writing the software that automates
everything else. As an apprentice, you're attending certified training and
building that picture on the job, mostly by shadowing people who already do
it — you're expected to be involved in getting things done, not yet in
deciding how they should be done. That's exactly right for where you are:
the habits you pick up watching a good DevOps engineer work are worth more
right now than any shortcut to doing it solo.

## Learning pathway

Work through these roughly in order. Each one is a requirement of this role
level, described plainly, with a way to go deeper by asking an AI tool a
specific question — the answers you get will be shaped around your own
team's tools and code, which a generic tutorial never is.

- [ ] **Understand the basics of software development and how services are built**

  You are expected to understand the process of software development and
  have a basic knowledge of how services get built, even before you're
  writing much code yourself.

  Ask AI: "I'm new to software development. Explain, step by step, how a
  small piece of code goes from being written to running as part of a live
  service."

- [ ] **See why development standards exist**

  You are expected to explain why using modern development standards
  matters, even though applying them under guidance comes at the next
  level.

  Ask AI: "Explain, for a complete beginner, what 'modern development
  standards' means in software engineering and why teams bother enforcing
  them."

- [ ] **Learn what prototyping is for**

  Explain what prototyping is, and why and when to use it, and start
  understanding how to work in an open, collaborative way — for example, by
  working in a pair with someone more experienced.

  Ask AI: "Explain what a prototype is in software development, why teams
  build one before the real thing, and what pair working actually looks
  like day to day."

- [ ] **Get comfortable helping fix service faults**

  Help with the investigation and fixing of service faults, completing
  defined activities under direction — you are not expected to diagnose a
  fault alone yet, only to help competently once someone more senior has
  pointed you at it.

  Ask AI: "What should someone new to a team do first when they're asked to
  help investigate a service fault, so they're useful rather than in the
  way?"

- [ ] **Learn what availability and capacity management actually means**

  Explain availability and capacity management processes — why a service
  needs to stay up, and why "up" isn't enough if it can't handle the load
  it's given.

  Ask AI: "Explain, simply, what 'availability' and 'capacity' mean for an
  online service, and why they're treated as separate concerns."

- [ ] **Start building security awareness**

  Explain information security and the security controls available to
  protect solutions and services, even before you're expected to apply them
  yourself.

  Ask AI: "What are the main categories of security control used to protect
  a software service, explained simply enough for someone new to the field?"

You do not need to master all of this before you start. Ask your manager or
whoever you're shadowing which of these your team leans on most, and start
there.
