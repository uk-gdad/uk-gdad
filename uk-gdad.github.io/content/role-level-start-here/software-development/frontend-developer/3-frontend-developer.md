# Frontend developer - start here

Welcome. If you are working toward the frontend developer level, this page is
for you: what the role expects, where to find everything else this
repository has for it, and a pathway for building the skills it asks for.

## Purpose

A frontend developer builds software components, primarily in the form of
user interfaces — the step up from junior is real ownership: you collaborate
closely with other disciplines to develop designs and working prototypes
based on genuine user needs, develop components that form part of a real
product, write clean and well-tested code as standard, and start coaching
and mentoring more junior colleagues. That last point matters as much as the
technical ones: this is the level where your judgement starts shaping other
people's work, not just your own.

## Learning pathway

Work through these roughly in order. Each one is a requirement of this role
level. Where you want to go deeper, ask an AI tool a specific question
rather than searching for a generic guide — you'll get an answer shaped
around your own codebase and team.

- [ ] **Build interfaces of real complexity from agreed specifications**

  Collaborate with others when necessary to review specifications, then use
  the agreed specifications to build, test and document user interfaces of
  medium to high complexity, using the right standards and tools.

  Ask AI: "What changes about reviewing a specification once you're
  building interfaces of real complexity, rather than simple ones under
  direction?"

- [ ] **Own how your interface gets delivered to real users**

  Build static assets from source code and test that the resulting user
  interface works as expected when delivered over the internet, and work on
  integration tests and network configuration as part of a wider team.

  Ask AI: "What can go wrong between a user interface working locally and
  working as expected once it's actually delivered over the internet?"

- [ ] **Represent user needs, not just build to a spec**

  Collaborate effectively with user researchers and interaction designers
  to represent user needs internally, champion user research so it covers
  all users, and guide others in understanding the user story rather than
  working it out alone.

  Ask AI: "What does representing user needs internally actually look like
  for a frontend developer, as distinct from the job a user researcher
  does?"

- [ ] **Champion accessibility, not just fix issues**

  Build user interfaces that meet a predefined set of standards, champion
  accessibility to internal stakeholders, offer design feedback that
  reduces the risk of failing accessibility testing, and recommend the best
  tools and methods for testing it.

  Ask AI: "How would a frontend developer champion accessibility to a
  stakeholder who sees it as slowing delivery down?"

- [ ] **Take ownership of web performance, not just help improve it**

  Explain the principles of web performance and how poor performance harms
  user experience, and help improve and resolve performance issues rather
  than waiting to be directed to them.

  Ask AI: "How would a frontend developer identify a web performance issue
  worth fixing, before a user or a stakeholder complains about it?"

- [ ] **Connect your daily work to the wider strategy**

  Work within a strategic context and communicate how your activities meet
  strategic goals, and start contributing to the development of strategy
  and policy rather than only working within it.

  Ask AI: "How would a developer explain to a stakeholder how a specific
  piece of frontend work supports a wider organisational strategy?"

- [ ] **Start making judgement calls, and resolving disputes between peers**

  Understand the impact of your decisions, make decisions characterised by
  different levels of risk and complexity, and resolve technical disputes
  between wider peers and indirect stakeholders, taking all views into
  account.

  Ask AI: "How would a developer resolve a technical disagreement between
  two peers where both have a reasonable case, without just picking a
  side?"

- [ ] **Manage stakeholder expectations, not just communicate information**

  Work collaboratively and build relationships with others, identify issues
  through team health checks, manage stakeholder expectations, and host or
  moderate difficult discussions within the team or with senior
  stakeholders.

  Ask AI: "What does 'managing stakeholder expectations' actually involve
  day to day for a frontend developer, beyond just answering their
  questions?"

- [ ] **Actively shape the team you work in**

  Network actively within the team, adapt feedback so it's effective and
  lasting, use team health checks to spot problems in team dynamics, and
  help stimulate the right response to what they surface.

  Ask AI: "What makes feedback 'effective and lasting' rather than
  something a colleague hears once and forgets?"

- [ ] **Apply development standards, and help others apply them too**

  Apply modern development standards yourself and support others in
  applying them — the step up from junior is the second half of that
  sentence: it's now partly about other people's practice, not just yours.

  Ask AI: "What's an effective way to help a colleague apply a development
  standard they're struggling with, without just doing it for them?"

- [ ] **Treat prototyping as a genuine team activity**

  Approach prototyping as something the whole team does together, actively
  seeking out prototypes and testing with others, establishing design
  patterns and iterating them, and choosing from a variety of prototyping
  methods.

  Ask AI: "How does prototyping as a team activity differ from one person
  building a prototype and showing it to the team afterwards?"

Ask your manager or a more senior colleague which of these your team relies on
most right now, and start there.
