# Developer - start here

Welcome. If you are working toward the developer level, this page is for
you: what the role expects, where to find everything else this repository
has for it, and a pathway for building the skills it asks for.

## Purpose

A developer delivers software components that form part of a product — the
step up from junior is real ownership: you develop software to meet user
needs, follow best practice guidelines and help improve them, write clean,
secure and well-tested code as standard, coach and mentor more junior
colleagues, and operate the services you build, spotting issues in
production rather than handing that responsibility to someone else. A new
skill appears here — development process optimisation — because at this
level you're expected to notice when the way the team works could be better,
not just work within it.

## Learning pathway

Work through these roughly in order. Each one is a requirement of this role
level. Where you want to go deeper, ask an AI tool a specific question
rather than searching for a generic guide — you'll get an answer shaped
around your own codebase and services.

- [ ] **Design and build without someone directing every step**

  Collaborate with others when necessary to review specifications, then use
  the agreed specifications to design, code, test and document programs or
  scripts of medium-to-high complexity, using the right standards and
  tools.

  Ask AI: "What changes about reviewing a specification once you're
  expected to work from it independently, rather than being directed
  through it?"

- [ ] **Turn logical designs into working physical ones**

  Translate logical designs into physical designs, produce detailed designs
  documented to the required standard, and design systems with managed
  levels of risk and complexity using technology you already understand
  well.

  Ask AI: "What's the practical difference between a logical design and a
  physical design in software systems, and what does 'managed risk' mean
  when choosing between them?"

- [ ] **Build and test real interfaces between systems**

  Build and test simple interfaces between systems yourself, and work on
  more complex integration as part of a wider team.

  Ask AI: "What makes testing an interface between two systems different
  from testing either system on its own, and what tends to get missed?"

- [ ] **Represent user needs, not just build to a spec**

  Collaborate with user researchers and represent users internally, explain
  the difference between user needs and desires, champion user research so
  it covers all users, and guide others in understanding the user story.

  Ask AI: "What does representing user needs internally actually look like
  for a developer, as distinct from the job a user researcher does?"

- [ ] **Start improving the development process itself**

  Explain the importance of developing process efficiency and the common
  ways processes get optimised, support specific activities to improve
  them, and identify the obvious deficiencies — this is a new skill at this
  level, and it's the first sign you're expected to improve the system, not
  just work within it.

  Ask AI: "What are common signs that a development process has an obvious
  deficiency worth raising, even before you know how to fix it?"

- [ ] **Apply development standards, and help others apply them too**

  Apply modern development standards yourself and support others in
  applying them — the step up from junior is the second half of that
  sentence: it's now partly about other people's practice, not just yours.

  Ask AI: "What's an effective way to help a colleague apply a development
  standard they're struggling with, without just doing it for them?"

- [ ] **Approach prototyping as a genuine team activity**

  Treat prototyping as something the whole team does together, actively
  seeking out prototypes and testing with others, establishing design
  patterns and iterating them, and choosing from a variety of prototyping
  methods rather than defaulting to one.

  Ask AI: "How does prototyping as a team activity differ from one person
  building a prototype and showing it to the rest of the team afterwards?"

- [ ] **Manage live services against real business needs**

  Manage service components to make sure they meet business needs and key
  performance indicators — a step up from explaining availability and
  capacity concepts, into actually being accountable for them.

  Ask AI: "What key performance indicators would a developer typically be
  accountable for when managing a live service component?"

- [ ] **Design security in, rather than bolting it on**

  Design solutions and services with security controls included from the
  start, specifically engineered to mitigate the security threats relevant
  to what you're building.

  Ask AI: "What does it mean in practice to 'design security in' from the
  start of building a solution, rather than adding controls afterwards?"

- [ ] **Keep helping fix faults by following procedure**

  This skill's wording plateaus here, unchanged from junior level: helping
  fix service faults by following agreed procedures, and carrying out
  maintenance tasks on the infrastructure that keeps things running.

  Ask AI: "What would taking ownership of finding and fixing faults,
  beyond following an agreed procedure, look like at the next level?"

Ask your manager or a more senior colleague which of these your team relies on
most right now, and start there.
