# Infrastructure engineer - start here

Welcome. If you are working toward the infrastructure engineer level, this
page is for you: what the role expects, where to find everything else this
repository has for it, and a pathway for building the skills it asks for.

## Purpose

Working in a team of infrastructure specialists and engineers, an
infrastructure engineer supports and maintains infrastructure solutions and
services as directed and according to departmental policy, ensuring
services are delivered and used as required and working with third parties
to provide them. Coding and scripting, service focus and testing are new at
this level, and most other named skills grow, because building and
configuring infrastructure yourself asks for more than supporting a team
that does.

## Learning pathway

Work through these roughly in order. Each one is a requirement of this role
level, described plainly, with a way to go deeper by asking an AI tool a
specific question rather than searching for a generic guide.

- [ ] **Build, configure and support infrastructure directly**

  Build, configure, administer and support infrastructure solutions and
  services — for example, networking and physical infrastructure,
  commercial-off-the-shelf software, open source packages and solutions,
  or virtual and cloud computing.

  Ask AI: "What's the practical difference between configuring an
  infrastructure component and just supporting one that someone else
  configured?"

- [ ] **Translate designs into detail, and document them properly**

  Translate logical designs into physical designs, produce detailed
  designs, and document all your work using required standards, methods
  and tools, including prototyping tools where appropriate.

  Ask AI: "What's the difference between a logical design and a physical
  design in infrastructure engineering, and why does documenting the
  translation between them matter?"

- [ ] **Design systems with manageable risk and complexity**

  Design systems characterised by managed levels of risk, manageable
  business and technical complexity, and meaningful impact, working with
  well understood technology and identifying appropriate patterns.

  Ask AI: "How would an infrastructure engineer judge whether a system
  they're designing has 'manageable' complexity, rather than something
  that needs escalating to a more senior colleague?"

- [ ] **Build and test simple interfaces between systems**

  Build and test simple interfaces between systems, and work on more
  complex integration as part of a wider team.

  Ask AI: "What should an infrastructure engineer test first when building
  an interface between two systems?"

- [ ] **Take ownership of an issue until it's resolved**

  Own an issue until a new owner has been found or the problem has been
  mitigated or resolved, rather than passing it on the moment it gets
  difficult.

  Ask AI: "What does 'owning an issue' mean in practice for an
  infrastructure engineer, when the actual fix might belong to someone
  else's team?"

- [ ] **Investigate problems, and help implement remedies**

  Investigate problems in systems, processes and services, understanding
  the level of a problem — for example, strategic, tactical or
  operational — and contribute to the implementation of remedies and
  preventative measures.

  Ask AI: "What's the difference between fixing a problem and contributing
  to a preventative measure that stops it recurring?"

- [ ] **Troubleshoot across different technology capabilities**

  Troubleshoot and identify problems across different technology
  capabilities.

  Ask AI: "What's a structured way to troubleshoot an infrastructure fault
  when it isn't obvious which technology layer is causing it?"

- [ ] **Execute test scripts, and understand testing's role**

  Correctly execute test scripts under supervision, and understand the
  role of testing and how it works.

  Ask AI: "Why does infrastructure work get tested the same way software
  does, and what's different about testing infrastructure changes?"

- [ ] **Build coherent frameworks from scattered inputs**

  Take inputs and establish coherent frameworks that work, rather than
  leaving infrastructure information scattered across different sources.

  Ask AI: "What does 'establishing a coherent framework' mean in practice
  for someone supporting infrastructure across several services?"

- [ ] **Keep explaining information security controls**

  This skill's wording plateaus here, unchanged from associate level:
  explaining information security and the security controls available to
  protect solutions and services.

  Ask AI: "Given this skill's description hasn't changed since the level
  below, what would genuinely infrastructure-engineer-level security
  judgement add beyond what's written here?"

- [ ] **Keep learning about scripting tools and software**

  This skill also plateaus: describing different scripting tools and
  software that are available and currently in use.

  Ask AI: "What's a sensible way for an infrastructure engineer to keep
  track of which scripting tools are actually in current use, rather than
  which ones are popular in general?"

- [ ] **Keep applying modern development standards under guidance**

  This skill's wording plateaus too: explaining the most important
  principles of modern development standards and applying them under
  guidance.

  Ask AI: "What would applying modern development standards without
  guidance look like, compared to applying them under guidance as this
  level asks?"

Ask a senior infrastructure engineer which of these your team relies on most
right now, and start there.
