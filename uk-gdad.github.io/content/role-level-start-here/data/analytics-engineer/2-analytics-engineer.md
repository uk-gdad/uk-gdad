# Analytics engineer - start here

Welcome. If you are working toward the analytics engineer level, this page
is for you: what the role expects, where to find everything else this
repository has for it, and a pathway for building the skills it asks for.

## Purpose

An analytics engineer develops and tests data models assigned by more
senior analytics engineers, helping people in a defined area access and use
data. You draft documentation that meets standards, work with other
analytics engineers to resolve issues and risks, support trainee analytics
engineers, provide training and support for users of data sets, and keep
developing your own skills alongside more experienced colleagues. A new
skill appears here — programming and build — because producing a real data
model means writing and testing the code that actually builds it.

## Learning pathway

Work through these roughly in order. Each one is a requirement of this role
level. Where you want to go deeper, ask an AI tool a specific question
rather than searching for a generic guide — you'll get an answer shaped
around your own data models.

- [ ] **Write and document simple programs under direction**

  Design, code, test, correct and document simple programs or scripts
  under the direction of others — the whole small cycle, not just the
  coding part.

  Ask AI: "Walk me through the full cycle of writing a simple data
  transformation script: designing it, coding it, testing it, and
  documenting it, so I don't skip a step."

- [ ] **Produce data models, and understand where to use them**

  Produce data models and understand where to use different types,
  compare tools and models, reverse-engineer a model from a live system,
  and understand industry-recognised modelling patterns and standards.

  Ask AI: "How would an analytics engineer decide which type of data
  model fits a given dataset and use case, rather than defaulting to the
  one they know best?"

- [ ] **Profile data, and present clear insight**

  Undertake data profiling and source system analysis, and present clear
  insights to colleagues to support how the data actually gets used.

  Ask AI: "What makes a data profiling finding genuinely useful to a
  colleague who isn't a data specialist, rather than just technically
  accurate?"

- [ ] **Use metadata for complex analysis, and keep it accurate**

  Use metadata repositories to complete complex tasks such as data and
  systems integration impact analysis, and maintain a repository to keep
  information accurate and current.

  Ask AI: "Explain, simply, what a metadata repository is for and why
  keeping it accurate matters for tasks like integration impact analysis."

- [ ] **Communicate effectively across a multidisciplinary team**

  Communicate effectively with technical and non-technical stakeholders,
  support discussions within a multidisciplinary team that may have
  difficult dynamics, advocate for your team externally, and manage
  differing stakeholder perspectives.

  Ask AI: "What should an analytics engineer focus on when explaining a
  technical data decision to a non-technical stakeholder, so it actually
  lands?"

- [ ] **Keep staying aware of innovation in data tools and uses**

  This skill's wording plateaus here, unchanged from trainee level: showing
  an awareness of opportunities for innovation with new tools and uses of
  data.

  Ask AI: "What's a realistic next step, beyond staying aware of data
  innovation, that an analytics engineer could actually practise?"

- [ ] **Keep investigating problems at the right level**

  This skill also plateaus: investigating problems in systems, processes
  and services with an understanding of their level, and contributing to
  remedies and preventative measures.

  Ask AI: "What would taking more ownership of problem investigation,
  beyond contributing to remedies, look like at the next level?"

- [ ] **Keep executing test scripts under supervision**

  This skill's wording plateaus too: correctly executing test scripts
  under supervision, and understanding the role testing plays.

  Ask AI: "What would moving from executing test scripts under supervision
  to designing them independently actually involve?"

Ask your manager or a more senior colleague which of these your team relies on
most right now, and start there.
