# Associate quality assurance test analyst - start here

Welcome. If you are starting out as an associate quality assurance test
analyst, this page is for you: what the role is about, where to find
everything else this repository has for it, and a pathway for building the
skills it asks for, one step at a time.

## Purpose

A quality assurance test analyst interprets what a piece of work actually
needs to be tested for, then creates and runs the tests that check it against
those needs. As an associate, you are learning to do that under supervision:
following test approaches someone else has set, analysing user stories and
designs with support, and building up the basic functional and non-functional
testing techniques the role runs on. Every artefact you learn to read a little
more confidently, and every defect you help track through to resolution, is
building the analytical instinct that the rest of this role depends on. There
is no shortcut to that instinct — it comes from doing the work, with people
willing to check your reasoning while you're still forming it.

## Learning pathway

Work through these roughly in order. Each one is a requirement of this role
level, described plainly, with a way to go deeper by asking an AI tool a
specific question — the answers you get will be shaped around your own
team's work in a way a generic page never could be.

- [ ] **Learn to spot what "quality" means for a specific piece of work**

  Before you can analyse anything, you need to describe the quality
  characteristics that matter — correctness, usability, reliability — and
  explain why each is worth checking. At this level you are expected to
  analyse artefacts such as user stories, prototypes and designs with
  support, and to explain what might put a quality goal at risk.

  Ask AI: "I'm new to test analysis. Explain what 'quality characteristics'
  means when analysing a user story or a design, with a simple example."

- [ ] **Understand why testing needs an approach, and follow one**

  You are expected to explain the value of a quality testing approach, plan
  or strategy, how different ways of delivering software change it, and to
  follow one that someone else has set, with support.

  Ask AI: "Explain, for someone new to test analysis, what a test approach or
  test strategy is for, and why following one matters even when it feels like
  extra process."

- [ ] **Design and run a simple test, with guidance**

  Contribute to deciding which test types and techniques fit, follow guidance
  to design, build and maintain simple tests that match what users need, and
  run simple tests with support. You are also expected to be able to explain,
  in plain terms, why automating some testing is worthwhile.

  Ask AI: "Walk me through designing a simple test case for a feature I
  describe to you, and explain what makes a test case actually useful rather
  than just technically correct."

- [ ] **Learn to report and follow up a defect properly**

  Follow an existing defect management process, report and communicate
  defects with the right information, and retest and escalate when needed.
  You are not expected to design this process yet, only to use it well.

  Ask AI: "What details should go into a defect report so someone else can
  act on it without needing to come back and ask me questions?"

- [ ] **Get comfortable with the tools and environments testing relies on**

  You are expected to explain why testing processes, environments and tools
  matter, follow test engineering practices and standards with support, and
  help maintain the automated tests and tooling the team already has.

  Ask AI: "Explain, for a beginner, why test environments and basic test
  tooling matter, and what 'supporting the maintenance' of them might look
  like day to day."

- [ ] **Practise explaining technical findings in plain language**

  You will work with people who never see a test case. This level expects you
  to explain why translating technical concepts into non-technical language
  matters, and to recognise the different ways internal and external
  stakeholders need to be communicated with.

  Ask AI: "Give me a technical testing finding, and show me two ways to
  explain it — one for a developer and one for someone with no technical
  background."

You do not need to master all of this before you start. Ask your manager or a
more senior analyst which of these your team leans on most, and start there.
