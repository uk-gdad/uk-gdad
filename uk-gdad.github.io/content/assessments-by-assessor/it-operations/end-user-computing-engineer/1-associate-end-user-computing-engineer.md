# Associate End User Computing Engineer - Psychometric Assessments

## Introduction

This document is written for you: an assessor administering a workplace job-specific psychometric assessment to a candidate for associate end user computing engineer, within the UK Government Digital and Data profession. These assessments are job-specific: rather than abstract puzzles, they use the kinds of things an associate genuinely sees every day — incident tickets, service requests, knowledge base articles, simple reports with Key Performance Indicators (KPIs), and conversations with the users they support.

An associate end user computing engineer, working in an established team, supports end user computing engineers in their daily work, under their direction. That work depends on a handful of core thinking skills: noticing patterns, following logical rules, checking details carefully, working with simple numbers, reading instructions and messages accurately, and making sensible judgement calls about when to act alone and when to ask. The four assessment types in this document measure exactly these skills:

1. A **cognitive assessment**, covering pattern spotting, logical thinking, error checking, prioritisation, and problem solving.
2. A **numeric reasoning assessment**, covering percentages, averages, and reading simple tables and charts using ticket volumes, KPIs, and service data.
3. A **verbal reasoning assessment**, covering reading and understanding passages such as process guides, emails, and knowledge articles.
4. A **situational judgement assessment**, presenting realistic workplace situations and asking which responses are most and least effective.

Each section follows the same pattern: an overview of what the assessment measures, a mapping to the specific skills in the role, a set of items with full worked explanations for use as an answer key, administration notes, and common pitfalls to watch for when scoring.

**How to administer this fairly.** Use the same items and time allowance for every candidate assessed at this role level. Hold the correct answers and explanations back from the candidate until after they have responded. Let the candidate work through each section without interruption, and note anything unusual about the conditions so the record is honest. Afterwards, use the explanations to structure a debrief. This assessment is one input among several — see the advisory below for what it should never be used for on its own. This is an early-career assessment: expect care, attention, honesty, and steady thinking, not deep technical expertise.

## Workplace job-specific cognitive assessment

### About this assessment

A workplace job-specific cognitive assessment measures the everyday thinking skills this role depends on, using practical workplace scenarios rather than abstract puzzles. Instead of rotating shapes or completing number grids, a candidate is presented with the materials of the actual job — incident tickets, ticket queues, knowledge base articles, escalation rules, and simple checklists — and asked to reason about them quickly and accurately.

The typical format is an online, timed test lasting around 15 to 30 minutes, usually with 15 to 30 questions covering pattern recognition, logical deduction, error checking, prioritisation, and applied problem solving. Scoring is objective against a norm group. Many platforms are adaptive, and ungraded practice questions are usually offered first.

Cognitive assessment is used for this role because it is built on careful, structured thinking done at pace. When a user reports a fault, an associate gathers the required information, decides what kind of incident it is, and allocates it to the appropriate channel. When something looks odd — three similar tickets in one morning, a record that does not match reality — noticing the pattern quickly can save the whole team hours.

### How this assessment maps to the role

The assessment dimensions map directly to the named skills in the role summary:

- **Pattern recognition** maps to the **Problem management** skill: investigating problems in systems, processes and services starts with noticing that several separate incidents share a common cause.
- **Logical deduction** maps to the **Incident management** skill: identifying and registering incidents, gathering the required information and allocating each one to the appropriate channel means applying routing rules correctly every time.
- **Error checking** maps to the **IT service reporting** skill.
- **Prioritisation** maps to the **Ownership and topic** skill.
- **Applied problem solving** maps to the **User focus** skill and the **Problem management** skill together.

### Practice questions

Present these to the candidate under the timing above; do not reveal the correct answers or explanations until after they have responded.

**Question 1 (easy) — Pattern recognition in a ticket queue**

The team's ticketing system gives every incident a reference in the format INC, then a hyphen, then six digits — for example INC-104276. Service requests use REQ, then a hyphen, then six digits — for example REQ-104277. Tidying the queue under a mentor's direction, these references appear:

1. INC-104301
2. REQ-104302
3. INC-10430
4. REQ-104304
5. INC-104305

Which reference breaks the format?

- A) Reference 1
- B) Reference 3
- C) Reference 4
- D) Reference 5

**Correct answer: B**

**Explanation:** Checking each reference against the rule (correct prefix, hyphen, exactly six digits), reference 3 has only five digits after the hyphen. This tests checking a format rule one part at a time — prefix, separator, digits — rather than judging the whole reference at a glance, since broken references can get lost, miscounted, or sent to the wrong queue.

**Question 2 (easy) — Logical deduction from an escalation rule**

The team's guide says: "If an incident affects more than five users, it must be escalated to the senior engineer immediately." A colleague reports: "Ticket INC-221040 was escalated to the senior engineer immediately." Which one of the following must be true?

- A) INC-221040 affected more than five users.
- B) INC-221040 affected five users or fewer.
- C) The rule was followed correctly.
- D) None of the above must be true.

**Correct answer: D**

**Explanation:** The rule states one reason for escalation but does not say escalation happens only for that reason — an engineer might escalate for an unrelated reason, such as a security concern. Options A, B and C each assume more than the evidence guarantees. This tests concluding only what the information guarantees — recording facts separately from assumptions is what keeps incident tickets accurate and trustworthy.

**Question 3 (easy) — Error checking a hardware request list**

A user emails a list of equipment for three new starters, to be checked against the standard new starter kit: one laptop, one headset, one mouse, and one security pass holder per person. The email lists: 3 laptops, 3 headsets, 2 mice, 3 security pass holders, and 1 docking station. Which two statements are correct?

- A) The list is one mouse short, and the docking station is not part of the standard kit.
- B) The list is one headset short, and the docking station is not part of the standard kit.
- C) The list is one mouse short, and one laptop too many.
- D) The list matches the standard kit exactly.

**Correct answer: A**

**Explanation:** Comparing the list against the standard kit item by item shows mice are one short (2 against 3 needed) and the docking station is an extra item not on the standard kit, needing a query. This tests careful line-by-line checking — catching a shortage before new starters arrive, and querying an unapproved extra item, are both part of good request control.

**Question 4 (moderate) — Prioritisation of a morning queue**

Arriving at 09:00, four items may be handled in any order, under the team's guidance:

1. A ticket from a user whose laptop will not switch on; the user has a presentation to a director at 10:00.
2. A routine request to install approved software for a user who says "no rush, any time this week."
3. A note from a mentor asking for the asset log to be updated with three laptop serial numbers "by end of day."
4. A ticket reporting that the printer on the fourth floor is showing a low toner warning but is still printing.

Which order is most sensible?

- A) 3, 1, 2, 4 — do the mentor's task first because they are senior
- B) 1, 3, 4, 2 — urgent user-blocking issue first, then the same-day task, then the warning, then the no-rush request
- C) 2, 4, 3, 1 — do the quick and easy items first
- D) 4, 1, 3, 2 — printers affect many users, so always start with printers

**Correct answer: B**

**Explanation:** Item 1 is both urgent and high impact, so it comes first. Item 3 is due today but not immediately. Item 4 is a warning rather than a failure and can wait, though it should not be forgotten. Item 2 has an explicit week-long window. Option A confuses seniority with urgency. Option C picks tasks for convenience rather than impact. Option D applies a rigid rule instead of judging the actual situation. This tests weighing urgency and impact together rather than applying a single fixed rule.

**Question 5 (moderate) — Pattern recognition across incidents**

During one morning, incidents are registered: 09:12 — Building A floor 2, "Wi-Fi keeps dropping"; 09:31 — Building A floor 2, "Laptop loses network every few minutes"; 09:48 — Building B floor 1, "Cannot open a spreadsheet attachment"; 10:02 — Building A floor 2, "Video calls keep freezing"; 10:15 — Building A floor 3, "Forgotten password." What is the most useful observation to share with the team?

- A) Five separate users have five separate problems.
- B) Three incidents from Building A floor 2 describe network-related symptoms in about an hour — they may share one cause worth investigating.
- C) Building A has more incidents than Building B, so Building A users need training.
- D) The spreadsheet issue is the most serious because attachments involve security.

**Correct answer: B**

**Explanation:** Three of five tickets share a location and consistent network-related symptoms, suggesting one underlying cause. Option A misses the pattern. Option C jumps from a count to an unsupported conclusion. Option D invents a security concern the ticket does not mention. This tests the problem management skill of noticing that separate incidents may be one problem in disguise, and naming the level of the problem (operational, here) to help route it correctly.

**Question 6 (moderate) — Logical deduction about allocation rules**

The allocation guide says: (i) hardware faults go to the desk-side team; (ii) software faults go to the applications team; (iii) if a ticket involves both hardware and software, it goes to the desk-side team first; (iv) anything mentioning suspicious emails goes to the security team regardless of other rules. A user reports: "My laptop screen flickers, and since yesterday my email app also crashes when I open it." Where should the ticket go first?

- A) The applications team, because the email app is crashing
- B) The desk-side team, because the ticket involves both hardware and software
- C) The security team, because email is mentioned
- D) It should be split into two tickets and sent to two teams at once

**Correct answer: B**

**Explanation:** The flickering screen is hardware, the crashing app is software, so rule (iii) applies. Rule (iv) concerns suspicious emails, not a crashing email application — a tempting trap that superficially resembles the trigger but is not it. This tests applying rules in order and reading them precisely, checking exact wording when two rules seem to overlap.

**Question 7 (moderate) — Error checking an asset log update**

Three laptop swaps must be recorded in the asset log: for each swap, mark the old laptop "Returned to store" and the new laptop "In use," recording the user's name against the new laptop only. Afterwards, the log shows:

| Asset | Status | User |
|---|---|---|
| LT-0451 (old) | Returned to store | — |
| LT-0892 (new) | In use | J. Adeyemi |
| LT-0463 (old) | Returned to store | M. Kaur |
| LT-0899 (new) | In use | M. Kaur |
| LT-0470 (old) | Returned to store | — |
| LT-0901 (new) | Returned to store | P. O'Brien |

How many rows contain an error?

- A) 0
- B) 1
- C) 2
- D) 3

**Correct answer: C**

**Explanation:** Row 3 wrongly keeps a user name against an old, returned laptop. Row 6 wrongly marks a new laptop as returned to store instead of in use. This tests checking each row against the two stated rules methodically — accurate records matter because others rely on them, and this is the foundation of the basic reporting skill.

**Question 8 (moderate) — Applied problem solving with a user story**

The team writes user stories in the format: "As a [type of user], I want [something], so that [benefit]." A user rings and says: "I need admin rights on my laptop." Following the team's user-focus approach, what is the most useful first question to ask?

- A) "Which laptop model do you have?"
- B) "What are you trying to do that currently isn't working?"
- C) "Have you tried turning it off and on again?"
- D) "Who is your line manager, so I can request approval?"

**Correct answer: B**

**Explanation:** "I need admin rights" is a proposed solution, not the underlying need. Asking what the user is trying to achieve may reveal a safer, faster route — such as installing an application through the approved catalogue — without granting admin rights at all. This tests the user focus skill of separating what a user asks for from what they need, rather than processing the stated request before understanding it.

**Question 9 (challenging) — Multi-step deduction about a recurring fault**

A meeting room laptop fails every Monday morning but works for the rest of the week. Facts: (i) the laptop is left plugged in over the weekend; (ii) building power is shut down every Sunday from 02:00 to 04:00 for maintenance; (iii) the laptop's battery is known to be faulty and holds no charge; (iv) when the laptop loses all power completely, it needs a manual restart before it will boot. What is the most likely explanation for the Monday failures?

- A) Users are mistreating the laptop on Fridays.
- B) The Sunday power shutdown cuts mains power; with a faulty battery the laptop fully powers off and then waits for the manual restart nobody performs until Monday.
- C) The laptop has a software fault that only activates on Mondays.
- D) The building's Wi-Fi is switched off at weekends.

**Correct answer: B**

**Explanation:** Chaining the facts: the weekend power cut removes the laptop's only power source since the battery holds no charge, and a full power loss requires a manual restart nobody performs until Monday. Every fact is used, and the weekly timing matches. Options A, C and D introduce causes with no supporting facts. This tests recognising that a recurring weekly pattern usually points to a recurring weekly cause — problem investigation in miniature.

**Question 10 (challenging) — Prioritisation with incomplete information**

At 14:00, two open items: (1) a ticket from one user whose second monitor shows no picture, and (2) a ticket saying "the shared drive is slow," raised by one user but mentioning "others are complaining too." A mentor is in a meeting until 15:00. What is the best course of action?

- A) Work on the monitor ticket first because it was raised first, and leave the shared drive ticket until the mentor returns.
- B) Spend a few minutes checking whether the shared drive issue really affects multiple users — for example, by checking for related tickets or asking in the team channel — because if it does, it is higher impact and may need escalating; meanwhile keep the monitor user informed.
- C) Escalate both tickets immediately to the senior engineer to be safe.
- D) Interrupt the mentor's meeting to ask which ticket to do first.

**Correct answer: B**

**Explanation:** A few minutes of checking resolves the key uncertainty — the scale of the shared drive issue — without needing the mentor. Option A uses arrival order instead of impact. Option C over-escalates without any checking. Option D interrupts unnecessarily for something investigable independently. This tests recognising that a small, quick investigation to size an uncertain issue is almost always the right first move.

**Question 11 (challenging) — Error checking against two sources**

The team's KPI report says: "We closed 120 incidents this week, of which 96 were closed within the target time, giving 80% within target." The ticket system export shows 120 incidents closed, 90 within target. The knowledge article about the report defines the target percentage as incidents closed within target divided by total incidents closed. Which statement best describes the situation?

- A) The report is correct and the export must be wrong.
- B) The export is correct and the report's 80% figure should actually be 75%.
- C) Both are correct because 96 out of 120 is 75%.
- D) The percentage cannot be checked without more information.

**Correct answer: B**

**Explanation:** 96 ÷ 120 = 80% (matching the report's own arithmetic), but 90 ÷ 120 = 75% using the export's figures — the two sources disagree about the underlying count. Since the export is the original data source and the report is derived from it, the export is more trustworthy. Option C is arithmetically wrong. Option D underestimates the information available. This tests recognising that reports are only useful when their numbers can be traced back to the data — and that a discrepancy like this should be flagged to the team rather than silently corrected, since it might reveal a filtering error.

**Question 12 (challenging) — Applied problem solving under a process constraint**

A user's laptop fails completely at 16:30 on a Friday. The user is a caseworker who must submit statutory case decisions by a legal deadline on Monday. The loan laptop cupboard is empty, and the process says replacement laptops are issued only after a fault is confirmed by a senior engineer, all of whom have left for the day. What is the most constructive action before the end of the day?

- A) Tell the user nothing can be done until Monday and log the ticket for the morning.
- B) Give the user admin account details so they can use any spare machine.
- C) Register the incident with full details, flag the Monday statutory deadline clearly, check whether the user can access their casework through another approved route, and alert the on-call or duty contact if the team has one.
- D) Take a laptop from an empty desk and give it to the user, sorting the paperwork out next week.

**Correct answer: C**

**Explanation:** Registering the incident with complete information and a clearly flagged deadline means whoever picks it up understands the urgency immediately. Checking for an approved alternative route is advising on workarounds — a core part of the role — and may solve the user's real need even without fixing the laptop today. Option A abandons the user's need. Option B is a serious security breach. Option D bypasses asset control. This tests combining maximum effort within the rules with clear, loud communication, rather than either rule-breaking or helplessness.

### Administration tips

- **Watch for whether a candidate checks a rule one part at a time** rather than judging at a glance.
- **Score for whether a candidate concludes only what the information guarantees** in deduction items.
- **Note whether a candidate distinguishes urgency from seniority or arrival order** in prioritisation items.
- **Keep timing consistent** across candidates for this level.
- **Use the incomplete-information item (Question 10) to observe whether a candidate investigates before escalating or interrupting.**

### Common pitfalls to watch for when scoring

- **Rewarding an answer that adds detail the question never gave**, treating an assumption as established fact.
- **Accepting an option that breaks a rule to be helpful** — sharing credentials, skipping approvals, bypassing asset control.
- **Missing when a candidate confuses seniority or arrival order with actual urgency.**
- **Crediting an answer that trusts a printed figure over a traceable raw count.**
- **Rewarding an answer that fails to combine action with communication.**

## Workplace job-specific numeric reasoning assessment

### About this assessment

A workplace job-specific numeric reasoning assessment measures how confidently and accurately a candidate works with the kinds of numbers this role genuinely involves. It is not a maths exam full of algebra — it is practical, everyday arithmetic: percentages, averages, simple ratios, and reading tables and charts, applied to service data such as ticket volumes, closure rates, KPI figures, and stock counts.

The typical format is an online, timed test lasting 20 to 30 minutes, with around 15 to 20 questions, each usually a small table, chart, or short description with a calculation or interpretation to make. A calculator is normally permitted, and scoring measures whether the right calculation is chosen and carried out carefully.

Numbers run quietly through this role. IT service reporting means counting, summing, and calculating percentages, and understanding what KPIs mean and why they matter. Even simple daily tasks involve numbers — stock counts, ticket volumes, whether this week's queue is growing or shrinking.

### How this assessment maps to the role

- **Percentages and KPIs** map to the **IT service reporting** skill.
- **Reading tables and charts** maps to the **IT service reporting** skill.
- **Counting and categorising** maps to the **Incident management** skill.
- **Trends and comparisons** map to the **Problem management** skill.
- **Simple rates and averages** map to the **User focus** skill.

### Practice questions

Present these to the candidate under the timing above; do not reveal the correct answers or explanations until after they have responded.

**Question 1 (easy) — Percentage of tickets closed**

This week the team received 150 incident tickets and closed 120 of them. What percentage of the received tickets were closed?

- A) 70%
- B) 75%
- C) 80%
- D) 85%

**Correct answer: C**

**Explanation:** 120 ÷ 150 = 0.8 = 80%. This tests the simplest and most common KPI-style calculation in service reporting, done quickly enough to check a weekly figure rather than just copy it.

**Question 2 (easy) — Reading a simple table**

| Category | Tickets |
|---|---|
| Hardware | 14 |
| Software | 22 |
| Access requests | 9 |
| Network | 5 |

How many tickets were registered in total, and which category had the most?

- A) 50 total; Software most
- B) 48 total; Software most
- C) 50 total; Hardware most
- D) 45 total; Access requests most

**Correct answer: A**

**Explanation:** 14 + 22 + 9 + 5 = 50, with Software (22) the largest category. This tests totalling and ranking a column — exactly what's done when collating data for a basic report — and a strong candidate's answer would add the column twice, in different orders, to cross-check the total.

**Question 3 (easy) — Average tickets per day**

Over five working days, the following numbers of incidents were registered: 12, 8, 15, 10, and 5. What was the average (mean) number of incidents registered per day?

- A) 9
- B) 10
- C) 11
- D) 12

**Correct answer: B**

**Explanation:** (12 + 8 + 15 + 10 + 5) ÷ 5 = 50 ÷ 5 = 10. A sense-check confirms 10 sits comfortably within the 5–15 range. This tests the basic mean calculation feeding KPIs such as "average daily incident volume", used to plan desk staffing.

**Question 4 (moderate) — Percentage change in ticket volume**

Last week the team received 120 incidents. This week it received 138. By what percentage did incident volume increase?

- A) 12%
- B) 15%
- C) 18%
- D) 20%

**Correct answer: B**

**Explanation:** (138 − 120) ÷ 120 = 18 ÷ 120 = 15%. The common error is dividing by the new figure instead of the original. This tests always dividing by the starting value in a percentage change, and a strong candidate's answer notes that a 15% week-on-week rise is exactly the kind of trend the problem management skill should flag for investigation.

**Question 5 (moderate) — KPI target check**

The team's KPI target is: "At least 90% of password reset requests completed within 4 hours." This week there were 60 password reset requests, and 52 were completed within 4 hours. Did the team meet the target, and what was the actual percentage (to the nearest whole number)?

- A) Yes — 90%
- B) No — 87%
- C) Yes — 92%
- D) No — 82%

**Correct answer: B**

**Explanation:** 52 ÷ 60 ≈ 86.67%, rounding to 87%, below the 90% target. This tests checking a KPI honestly against its stated target, and a strong candidate's answer notes the more useful follow-up: 0.9 × 60 = 54 completions were needed, so the team fell 2 short — a concrete, fixable number.

**Question 6 (moderate) — Ratio of stock**

The loan equipment cupboard holds laptops and tablets in the ratio 3:1. There are 24 devices in total. After a busy morning, 6 laptops are loaned out. How many laptops remain in the cupboard?

- A) 12
- B) 14
- C) 16
- D) 18

**Correct answer: A**

**Explanation:** One ratio part = 24 ÷ 4 = 6; laptops = 3 parts = 18; after 6 are loaned, 18 − 6 = 12 remain. The common slip is stopping after finding 18 laptops and forgetting the loans. This tests completing every stage of a two-step question, checked by re-reading what is actually being asked.

**Question 7 (moderate) — Reading a chart described in words**

A bar chart of calls to the service desk shows: Monday 80 calls, Tuesday 65, Wednesday 70, Thursday 60, Friday 45. What share of the week's calls came on Monday (to the nearest whole percent)?

- A) 20%
- B) 25%
- C) 30%
- D) 33%

**Correct answer: B**

**Explanation:** Total = 320; Monday's share = 80 ÷ 320 = 25%. A sense-check confirms an even spread would give 20% per day, and Monday being clearly the busiest fits an answer a little above that. This tests reading a described chart as a table, and a strong candidate's answer notes the operational insight — Mondays being consistently heaviest explains why teams schedule more desk cover at the start of the week.

**Question 8 (moderate) — Time calculations for response targets**

The team's target is to respond to new incidents within 2 hours during working hours (09:00–17:00). A ticket arrives at 16:15 on Tuesday. Working hours pause overnight and resume at 09:00 on Wednesday. By what time must the team respond?

- A) 18:15 Tuesday
- B) 09:45 Wednesday
- C) 10:15 Wednesday
- D) 11:00 Wednesday

**Correct answer: C**

**Explanation:** 45 minutes of the target is used by 17:00 Tuesday, leaving 1 hour 15 minutes to run from 09:00 Wednesday, giving 10:15. This tests understanding how SLA clocks pause and resume outside working hours — a classic trap when setting realistic expectations and keeping users accurately informed.

**Question 9 (challenging) — Comparing two weeks of KPI data**

| Measure | Week 1 | Week 2 |
|---|---|---|
| Incidents received | 200 | 250 |
| Incidents closed within target | 160 | 190 |

A colleague says: "Week 2 was better — we closed 30 more incidents within target." Is the colleague's conclusion sound as a KPI comparison?

- A) Yes — 190 is more than 160, so performance improved.
- B) No — as a percentage, Week 1 was 80% within target and Week 2 was 76%, so the rate actually fell.
- C) No — Week 2 was worse because more incidents were received.
- D) Cannot say — the table does not contain enough information.

**Correct answer: B**

**Explanation:** Week 1's rate (160 ÷ 200 = 80%) exceeds Week 2's (190 ÷ 250 = 76%), even though the raw count of on-target closures rose. This tests recognising that KPIs are usually rates, not raw counts, since workload changes week to week — the colleague's comparison hides that the team handled 25% more incidents and kept a slightly smaller share within target.

**Question 10 (challenging) — Stock forecasting**

The team issues an average of 4 replacement headsets per week. The store currently holds 22 headsets. A delivery of new stock takes 3 weeks to arrive after being ordered. If the team wants never to run out, by the end of which week should an order be placed at the latest?

- A) End of week 1
- B) End of week 2
- C) End of week 3
- D) End of week 4

**Correct answer: B**

**Explanation:** Stock runs out during week 6 (22 ÷ 4 = 5.5 weeks). A delivery must arrive by the end of week 5, meaning an order by the end of week 2 (2 + 3 = 5). This tests working backwards from a run-out point by the delivery lead time — running out of basic kit turns routine requests into complaints.

**Question 11 (challenging) — Weighted workload calculation**

A password reset takes 10 minutes, a software install takes 30 minutes, and a laptop build takes 90 minutes. Today's queue contains 6 password resets, 4 software installs, and 2 laptop builds. Roughly how many hours of work is in the queue?

- A) 5 hours
- B) 6 hours
- C) 7 hours
- D) 8 hours

**Correct answer: B**

**Explanation:** (6 × 10) + (4 × 30) + (2 × 90) = 60 + 120 + 180 = 360 minutes = 6 hours. This tests multiplying each task type by its average time and summing, keeping everything in one unit until the final conversion — a simple example of the data-to-decision thinking the reporting skill builds towards.

**Question 12 (challenging) — Spotting a misleading average**

The team reports "average time to resolve hardware incidents: 3.6 hours" for last week. Individual resolution times were: 1 hour, 1 hour, 1.5 hours, 1.5 hours, and 13 hours (one incident needed a part ordered). A user asks: "So hardware faults typically take about 3 or 4 hours to fix?" What is the most accurate and helpful reply?

- A) "Yes — the average is 3.6 hours, so that is the typical time."
- B) "Actually, most faults were fixed in 1 to 1.5 hours; one unusual incident needing a spare part pulled the average up. The typical time is closer to 1.5 hours."
- C) "No, faults take 13 hours if parts are needed, so expect 13 hours."
- D) "The average is meaningless and should be ignored."

**Correct answer: B**

**Explanation:** The average is arithmetically correct (18 ÷ 5 = 3.6) but unrepresentative — four of five incidents took 1–1.5 hours, and one extreme value drags the mean up. This tests recognising that a mean can be pulled by one outlier, and communicating both the typical experience and the reason the average looks higher — informing customers honestly rather than repeating a technically true but misleading figure.

### Administration tips

- **Score the three core moves**: percentage, percentage change, and average.
- **Watch for whether a candidate names the base before dividing.**
- **Note whether a candidate sense-checks a result against the plausible range of the data.**
- **Keep timing consistent** across candidates for this level.
- **Use the misleading-average item (Question 12) to observe whether a candidate explains a mean pulled by an outlier honestly to a user.**

### Common pitfalls to watch for when scoring

- **Accepting a raw count as if it answered a rate question**, or vice versa.
- **Missing when a candidate stops after the first step of a two-step question.**
- **Crediting an answer that rounds too early**, compounding a small error.
- **Missing when a candidate misreads a paused SLA clock.**
- **Rewarding an answer that trusts a printed figure over a traceable raw count.**

## Workplace job-specific verbal reasoning assessment

### About this assessment

A workplace job-specific verbal reasoning assessment measures how accurately a candidate reads, understands, and draws conclusions from written material of the kind this role genuinely involves: knowledge base articles, process guides, emails from users and colleagues, service announcements, and short policy extracts.

The typical format is an online, timed test lasting 15 to 25 minutes. The most common question style is True / False / Cannot say. Other styles ask for the best summary of a passage, what a user's email is actually asking for, or the clearest way to phrase a message. The governing rule: answer using only the passage.

Reading accurately is a support skill in disguise for this role. Knowledge articles must be followed exactly — a skipped step in a fix procedure can make a fault worse. User emails must be read for what is really being reported, which is often different from the subject line.

### How this assessment maps to the role

- **Comprehension of procedures** maps to the **Incident management** skill.
- **True/false/cannot-say discipline** maps to the **Problem management** skill.
- **Identifying what a message really asks** maps to the **User focus** skill.
- **Clear-writing judgement** maps to the role's duty of informing customers on progress and advising on workarounds.
- **Reading reports and definitions** maps to the **IT service reporting** skill.

### Practice questions

For each True/False/Cannot-say question, judge the statement strictly against the passage.

**Question 1 (easy) — Comprehension of a knowledge article**

Passage: "Before reimaging any laptop, confirm that the user's files are synchronised to cloud storage. If synchronisation cannot be confirmed, do not reimage; instead, escalate to a senior engineer. Reimaging deletes all local data."

Statement: "A laptop may be reimaged once the user's files are confirmed as synchronised to cloud storage."

- A) True
- B) False
- C) Cannot say

**Correct answer: A**

**Explanation:** The article's one condition for reimaging — confirmed synchronisation — matches the statement directly, and escalation is required only when synchronisation cannot be confirmed. This tests underlining condition words ("before," "if," "instead") to find the logic of a procedure — sloppy reading here would risk deleting a user's files permanently.

**Question 2 (easy) — What is the user actually asking?**

A user emails: "Subject: Broken laptop. Hi — my laptop is fine actually, but ever since the update last week, when I plug into the meeting room screen nothing appears on it. The laptop screen still works. I have an important session with external visitors on Thursday. Can you help before then?"

What is the user actually reporting, and what is the deadline?

- A) A broken laptop, needed by Thursday
- B) A problem displaying to an external screen since an update, needed before Thursday
- C) A faulty meeting room screen, no deadline
- D) A request for a new laptop before Thursday

**Correct answer: B**

**Explanation:** The subject line ("Broken laptop") is corrected immediately in the body ("my laptop is fine actually"). The real report is a display fault since an update, with a Thursday deadline. This tests reading the whole message rather than trusting the subject line — users often mislabel their issues, and gathering the required information means recording the real symptom, the trigger, and the deadline.

**Question 3 (easy) — True/false/cannot say on a service notice**

Passage: "The printing service will be unavailable on Saturday from 08:00 to 12:00 for planned maintenance. Email and shared drives will not be affected."

Statement: "The printing service will be available on Sunday."

- A) True
- B) False
- C) Cannot say

**Correct answer: C**

**Explanation:** The notice says nothing about Sunday at all — the answer is Cannot say, even though it might feel natural to assume the service will be back. This tests the discipline of not adding an assumption to a passage's silence, since an accurate answer to a user asking "so printing will definitely be fine on Sunday?" would be "that's the plan," not an unconditional promise.

**Question 4 (moderate) — Following a procedure with conditions**

A process guide states: "New software requests: (1) Check the application is in the approved catalogue. (2) If it is in the catalogue, install it and close the request. (3) If it is not in the catalogue, do not install it; forward the request to the software assurance team and inform the user of the expected 10 working day review. (4) Requests from the finance department during month-end week must additionally be scheduled outside working hours."

A finance user requests a catalogue-approved application during month-end week. What does the guide require?

- A) Install it immediately and close the request.
- B) Forward the request to the software assurance team.
- C) Install it, but schedule the installation outside working hours.
- D) Refuse the request until month-end week is over.

**Correct answer: C**

**Explanation:** The application is in the catalogue, so rule (2) applies, but rule (4) stacks an additional condition for this finance/month-end request — scheduling outside working hours. Option A misses rule (4); option B wrongly applies the not-in-catalogue path; option D invents a refusal. This tests recognising that "additionally" stacks a rule on top of others rather than replacing them.

**Question 5 (moderate) — Inference from a colleague's handover note**

Passage: "INC-30877 — user's laptop overheats and shuts down. Cleaned the fan vents, updated firmware, ran hardware diagnostics twice: all passed. Shutdowns continued during my tests. I've requested a like-for-like replacement device; awaiting stock. User has been told and is using a hot-desk PC meanwhile."

Statement: "The engineer believes the fault has been fixed by the firmware update."

- A) True
- B) False
- C) Cannot say

**Correct answer: B**

**Explanation:** The note explicitly states shutdowns continued after the update, and the engineer requested a replacement — a pointless step if the update had worked. This is False, not Cannot say, because the passage contains clear contradicting evidence. This tests distinguishing False (contradicted) from Cannot say (silent), which matters when picking up a colleague's ticket without repeating steps already ruled out.

**Question 6 (moderate) — Choosing the clearest user update**

A non-technical user's incident (a failed email sync on their phone) is waiting on another team. Which message is best?

- A) "Your ticket has been escalated to Tier 3 pending MDM policy remediation; ETA unknown at this juncture."
- B) "Hi — an update on your phone email issue: we've found the cause and passed it to our specialist team to fix. We expect news by Thursday, and I'll update you then even if it isn't finished. Meanwhile, your email still works on your laptop."
- C) "We are working on it."
- D) "Hi — unfortunately the MDM enrolment token expired, which invalidated the ActiveSync certificate chain. Reprovisioning requires a policy push from the EMM console."

**Correct answer: B**

**Explanation:** Option B states what is happening, who is doing it, when the user will next hear, and a workaround. Option A is jargon with no commitment. Option C is empty. Option D is technically detailed but meaningless to a non-technical user with no next step offered. This tests writing a status update with all four elements — advising on workarounds and informing customers on progress done well.

**Question 7 (moderate) — True/false/cannot say on a policy extract**

Passage: "Portable devices must be encrypted before being issued to users. Devices returned from users must be securely wiped within five working days of return. Devices awaiting wiping must be stored in the locked cabinet in the IT store."

Statement: "A returned device may be reissued to a new user four days after its return, provided it has been securely wiped and encrypted."

- A) True
- B) False
- C) Cannot say

**Correct answer: A**

**Explanation:** Every stated condition is satisfied — wiping within five days, encryption before issue — and no minimum waiting period is set. This tests reading a policy for exactly what it constrains, no more: policies permit what they permit, and inventing an unstated waiting period would slow users down without cause.

**Question 8 (moderate) — Identifying the main point of a passage**

Passage: "From next month, all incidents will be registered through the new service portal rather than by email. Emailed reports will receive an automatic reply directing users to the portal. During the first four weeks, the service desk will register portal-shy users' incidents by phone as a transition measure. The change aims to capture complete information at first contact, reducing the back-and-forth that currently delays resolution."

Which sentence best summarises the announcement?

- A) The service desk will stop helping users who email.
- B) Incident registration is moving to a portal to capture better information up front, with phone support easing the transition.
- C) Email is being switched off across the organisation.
- D) Resolution times are currently too slow because users provide poor information.

**Correct answer: B**

**Explanation:** Option B captures the change, its purpose, and the qualifier. Option A distorts the passage — phone support is explicitly offered. Option C overstates. Option D turns a diplomatic purpose statement into blame the passage does not assign. This tests summarising a change fairly, accurately, and without inventing blame — a skill needed when explaining changes to frustrated users.

**Question 9 (challenging) — Inference across two passages**

Passage 1 (knowledge article): "Model X laptops with the July firmware are affected by a known battery drain fault. The August firmware resolves it. Affected users should be offered the firmware update at first contact."
Passage 2 (email from a user): "My Model X laptop's battery has been draining fast for weeks. Your colleague updated my firmware in September and it made no difference. Can someone help?"

Statement: "The user's battery drain is caused by the known July firmware fault."

- A) True
- B) False
- C) Cannot say

**Correct answer: B**

**Explanation:** The August fix should have resolved the July fault, but the user's September update (after the fix was available) made no difference — contradicting the statement. This tests treating a known problem as a hypothesis to test rather than an automatic diagnosis, and updating a conclusion when a remedy's failure is decisive counter-evidence.

**Question 10 (challenging) — Precise reading of a KPI definition**

A reporting guide defines: "First-time fix rate: the percentage of incidents resolved by the first engineer who handles them, without escalation or reassignment, measured across all incidents closed in the calendar month. Incidents reopened within five working days of closure are excluded from the numerator but remain in the denominator."

Statement: "An incident resolved by the first engineer, but reopened three working days later, increases the first-time fix rate."

- A) True
- B) False
- C) Cannot say

**Correct answer: B**

**Explanation:** The reopened incident adds one to the denominator (all closed incidents) but nothing to the numerator (first-time fixes) — pulling the rate down, not up. This tests parsing a KPI definition as a fraction and placing a scenario's incident into it precisely, since misreading an inclusion or exclusion rule produces a report that quietly flatters or punishes the team unfairly.

**Question 11 (challenging) — Judging tone and accuracy together**

A user has waited two days for a laptop repair promised in one day, because a part arrived late. Which draft apology and update is best?

- A) "We apologise for any inconvenience caused. Your ticket remains in progress."
- B) "Hi — I'm sorry your repair has taken longer than the one day we promised. The replacement part arrived late from our supplier; it's now here, and your laptop will be ready by 15:00 today. If it would help sooner, we can set you up on a loan laptop this morning — just reply and I'll arrange it."
- C) "Hi — sorry for the delay, but this was the supplier's fault, not ours. These things happen and are outside our control. It'll be done at some point today hopefully."
- D) "Hi — great news, your laptop is nearly ready! Thanks so much for your amazing patience, you're a star!"

**Correct answer: B**

**Explanation:** Option B owns the missed promise, explains the cause honestly, gives a specific new commitment, and offers a workaround. Option A is vague boilerplate. Option C shifts blame and hedges the new promise. Option D is warm but content-free. This tests combining honesty, accountability, and a concrete next step — the role's communication duty done properly.

### Administration tips

- **Score for whether a candidate distinguishes False from Cannot say correctly.**
- **Watch for whether a candidate reads the whole message rather than trusting a subject line or headline.**
- **Note whether a candidate identifies stacking conditions** ("additionally," "must also") correctly.
- **Use the clear-writing item (Question 6) as a live discussion point** in debrief.
- **Keep timing consistent** across candidates for this level.

### Common pitfalls to watch for when scoring

- **Crediting an answer drawn from outside knowledge** rather than the passage.
- **Missing when a candidate trusts a subject line or headline over the message body.**
- **Rewarding an answer that misses a stacking condition.**
- **Accepting a plausible-but-unstated option as if the passage supported it.**
- **Over-penalising an appropriate "Cannot say" as if it were indecision.**

## Workplace job-specific situational judgement assessment

### About this assessment

A situational judgement assessment presents realistic workplace situations and asks the candidate to judge how effective different responses would be. It has no arithmetic and no passage to parse — the material is human: a frustrated user, a mistake, a queue that is too long, a colleague who needs help. For each scenario, the candidate typically picks the most effective response, the least effective response, or rates every option.

The typical format is 10 to 20 scenarios, usually untimed or generously timed. Scoring compares choices against the judgement of experienced professionals and the organisation's values: user focus, collaboration, ownership, honesty, appropriate escalation, and inclusion.

Judgement calls are daily events for an associate, and most are about knowing boundaries as a trainee: when to try something alone, when to ask, when to pass a problem to the team, and how to treat users well while learning. At this level, scoring rarely expects heroics — the best answers are usually honest, prompt, user-focused, and appropriately humble.

### How this assessment maps to the role

- **Knowing when to escalate** maps to the **Ownership and topic** skill.
- **Handling users with care** maps to the **User focus** skill and the role's duty of informing customers on progress.
- **Owning mistakes** maps to the **Incident management** skill.
- **Contributing to the team** maps to the **Problem management** skill.
- **Working under direction** maps to the role level itself.

### Practice questions

Present these to the candidate under generous or untimed conditions; do not reveal the correct answers or explanations until after they have responded.

**Question 1 (easy) — A task beyond training**

A user asks for help fixing an error recognised from a knowledge article, but the fix involves system settings not yet trained on, and a mentor is at lunch. The user says: "Go on, just try it — how hard can it be?" Which response is most effective?

- A) Attempt the fix — the knowledge article describes it, and users come first.
- B) Say help cannot be given and ask the user to raise another ticket later.
- C) Explain that this fix needs a trained colleague, register the incident fully with the article reference attached, and let the user know when the mentor will be back and that it will be handed straight over.
- D) Ask the user to try changing the settings themselves while reading the article aloud.

**Correct answer: C**

**Explanation:** Option C is honest, registers the incident properly with a useful reference, and sets a clear handover expectation — ownership done correctly even without personally fixing it. Option A risks damaging a user's machine with an untrained change. Option B abandons the user unnecessarily. Option D outsources risk to the least qualified person present. This tests recognising that the strong answer is the reliable path to a fix, not the fastest attempt beyond one's training.

**Question 2 (easy) — A mistake in the asset log**

Updating the asset log reveals a laptop issue was recorded against the wrong user — logged against a different person than the one who actually received the laptop. Nobody has noticed. Which response is most effective, and which is least effective?

- A) Correct the record quietly — no harm done, no need to mention it.
- B) Correct the record, report what happened and what was fixed, and double-check other entries made the same day.
- C) Leave it — unsure how to edit records, and it might fix itself.
- D) Report it but leave the correcting to someone more senior.

**Correct answer: most effective B; least effective C**

**Explanation:** Option B fixes the error, is transparent about it, and checks for the same slip elsewhere — transparency lets the team judge knock-on effects and builds trust. Option A hides the event, so nobody checks for consequences. Option D is honest but passively avoids a correction well within scope. Option C is least effective, leaving wrong data in a system others rely on and hoping it self-corrects. This tests prompt, transparent correction as the professional standard for data errors.

**Question 3 (easy) — A frustrated user at the desk**

A user arrives visibly angry: "This is the third time my laptop has crashed this week and nobody has done anything!" Two previous tickets exist, both closed as "resolved" by different engineers. Which response is most effective?

- A) Point out that both previous tickets were marked resolved, so the earlier fixes must have worked at the time.
- B) Listen to the user's account without interrupting, acknowledge the frustration of a recurring fault, register a new incident linking the two previous tickets, and flag the recurrence to the team so it can be investigated as a possible underlying problem.
- C) Apologise repeatedly and promise the laptop will be fixed today, whatever it takes.
- D) Explain that crashes are usually caused by users running too many programs at once.

**Correct answer: B**

**Explanation:** Listening and acknowledging de-escalates a reasonable frustration; linking the previous tickets treats three "resolved" crashes as one unresolved problem in disguise; flagging the pattern routes it appropriately. Option A wins the argument and loses the user. Option C promises an outcome not controlled. Option D blames the user with an unevidenced guess. This tests acknowledging the person, capturing the history, and escalating the pattern.

**Question 4 (moderate) — Conflicting instructions**

A mentor asked for the afternoon to be spent updating asset records "without fail — the audit is Friday." At 14:00, a different senior engineer asks for help moving equipment, saying "the records can wait." Which response is most effective?

- A) Follow the most recent instruction — the senior engineer outranks the mentor.
- B) Refuse the senior engineer because the mentor's instruction came first.
- C) Briefly explain the conflict to the senior engineer, and if they still need the help, quickly confirm the change of plan with the mentor before switching.
- D) Try to do both by moving equipment now and updating records after hours without telling anyone.

**Correct answer: C**

**Explanation:** Surfacing the conflict cheaply — one sentence, one quick confirmation — protects both tasks and both relationships, since neither instruction-giver may know the other's constraint. Option A silently drops a deadline called "without fail." Option B refuses based on arrival order alone. Option D hides the conflict and commits to unapproved hours. This tests recognising that working under direction includes telling directors when their directions collide.

**Question 5 (moderate) — Noticing a pattern nobody asked about**

Registering tickets reveals four incidents this week mentioning the same application freezing after a recent update — logged by different engineers, each resolved individually with a restart, and closed. Nobody has connected them, and this is the newest team member. Which response is most effective, and which is least effective?

- A) Say nothing — the tickets are closed, the engineers are experienced, and it is not their place.
- B) Reopen all four tickets and merge them into a problem record personally.
- C) Mention what was noticed to a mentor or in the team channel, with the four ticket references, and ask whether it is worth raising as a possible problem.
- D) Email the application's vendor directly to report a fault in their update.

**Correct answer: most effective C; least effective A**

**Explanation:** Option C is exactly what contributing to problem management means at this level: noticing the pattern, gathering evidence, and passing it through the right channel with appropriate humility. Option B has the right instinct but the wrong authority — merging records is a decision for the problem process. Option D leaps over the whole organisation to an external party. Option A is least effective, since silence guarantees the pattern continues unaddressed. This tests ownership with humility: raise it, evidence it, let the process decide.

**Question 6 (moderate) — A colleague's shortcut**

Shadowing an engineer who resolves a user's issue by logging in with the user's password (written on a sticky note "to save time"), the engineer says afterwards: "I know we're not supposed to, but it's quicker, and everyone does it." Which response is most effective?

- A) Say nothing — the trainee role means the colleague is teaching.
- B) Publicly report the engineer to the security team immediately.
- C) Tell the engineer, privately and without accusation, discomfort with working that way, and if the practice seems routine, raise the pattern with a mentor or team leader so it can be addressed properly.
- D) Adopt the shortcut too — consistency with the team matters most.

**Correct answer: C**

**Explanation:** Option C holds the line personally while preserving the relationship, and raises a routine pattern through the proper channel rather than a personal report about one person. Option A is complicity through silence. Option B skips every proportionate step. Option D adopts a security breach as a habit. This tests integrity and proportionate escalation.

**Question 7 (moderate) — The queue and the walk-up**

Alone at the walk-up desk for twenty minutes while colleagues attend a stand-up: the phone rings, a user arrives holding a laptop, and a chat message arrives saying "my screen froze mid-presentation, audience waiting!!". Which response is most effective?

- A) Handle them strictly in arrival order: phone, then desk, then chat.
- B) Quickly triage all three: acknowledge the desk user, check the chat — a live presentation failure is likely most urgent — and let the phone go to voicemail or ask the caller to hold while dealing with the most time-critical issue first.
- C) Deal with the person physically present first — face-to-face always takes priority.
- D) Send the chat user a link to the self-service portal to focus on the phone and the desk.

**Correct answer: B**

**Explanation:** Thirty seconds of triage finds where urgency actually lives — in content, not channel — and the live presentation failure outranks a laptop that can wait on the desk and an unknown phone call. Acknowledging the desk user costs seconds and buys goodwill. Options A and C apply channel rules instead of judging impact. Option D deflects the most urgent user at their worst moment. This tests judged triage over rigid rules.

**Question 8 (moderate) — Asked to skip the process**

A manager from another team says: "My new starter begins Monday and has no laptop — the request got lost somewhere. Just grab one from the store for me now and we'll sort the paperwork next week. I'll take responsibility." Which response is most effective?

- A) Hand over the laptop — a manager has accepted responsibility, and the new starter's first day matters.
- B) Refuse and walk away — process is process.
- C) Explain that laptops can only be issued through the asset process, then actively help: register the request immediately, flag it urgent with the Monday start date, and alert a mentor or team lead who can expedite it properly the same day.
- D) Tell the manager to email the service desk and hope for the best.

**Correct answer: C**

**Explanation:** Issuing untracked equipment breaks asset control, and "I'll take responsibility" does not transfer accountability for the process — but pure refusal fails a genuine new starter too. Option C holds the process line while making the process fast, converting a corridor favour into a legitimate expedited request most teams can fulfil by Monday. Option A trades a protective rule for convenience. Option D adds delay without removing it. This tests compliance with energy: say no to the shortcut and yes to the outcome.

**Question 9 (challenging) — Honest uncertainty with a user**

Having told a user their software installation is complete, it becomes apparent the wrong version may have been installed — not certain, and checking takes about ten minutes. The user has already thanked and left, and the shift ends in fifteen minutes. Which response is most effective, and which is least effective?

- A) Say nothing — if it is wrong, they will raise another ticket, and it will be handled tomorrow.
- B) Check immediately; if the version is wrong, contact the user straight away, apologise, and either fix it now or arrange the earliest fix — recording the true status on the ticket before finishing the shift.
- C) Leave a note for tomorrow's shift asking someone to check the version "when they get a chance."
- D) Message the user: "Please double-check the version yourself and let me know if there's a problem."

**Correct answer: most effective B; least effective A**

**Explanation:** Ten minutes of checking is a small cost against a possible day of a user working with wrong software. Recording the true status protects the team's data and first-time-fix figures. Option A knowingly converts a possible mistake into the user's problem to protect fifteen minutes. Option C dilutes urgency and accountability. Option D transfers a quality-checking duty to the user. This tests ownership at small scale — owning an issue's honest state until it is genuinely resolved, including in the last fifteen minutes of a shift.

**Question 10 (challenging) — Inclusion at the desk**

A user with a visual impairment asks for help configuring a new laptop's screen reader and magnification settings, never configured before, mentioning tiredly that "IT always makes this take weeks." Which response is most effective?

- A) Configure the settings by trial and error while the user waits — refusing would be discriminatory.
- B) Say assistive technology is a specialist matter and the user should contact the accessibility team themselves.
- C) Be honest about not having configured these tools before, register the request with clear detail, find out whether the organisation has an assistive technology specialist or guide, and personally track the ticket so the user gets a named contact and does not have to chase — asking the user what setup has worked for them before.
- D) Give the user a loan laptop with default settings and suggest managing without the tools for now.

**Correct answer: C**

**Explanation:** Option C is honest about limits, engages the right expertise, keeps ownership so the user is not bounced between teams, and treats the user as the expert in their own needs. Option A gambles with tools the user depends on to work at all. Option B repeats exactly the experience that exhausted the user. Option D asks a disabled user to manage without their equipment. This tests inclusion, honesty about competence, and ownership that survives handover.

**Question 11 (challenging) — When help does not arrive**

A network fault affecting one meeting room was escalated to senior engineers two days ago, following the process exactly, and remains unpicked-up. A user books that room for an important external meeting tomorrow morning and asks whether it will be working. A mentor is on leave. Which response is most effective?

- A) Assure the user it will probably be fine by tomorrow — escalated tickets usually get resolved quickly.
- B) Tell the user the room has a fault and there is nothing more that can be done — the ticket is with another team.
- C) Chase the escalation actively today: speak to the senior team, explain the new deadline, update the ticket with this urgency, and give the user an honest status plus a practical fallback — help book an alternative room now in case the fix does not land in time.
- D) Attempt to fix the network fault personally this evening when the office is quiet.

**Correct answer: C**

**Explanation:** Escalation is not the end of ownership. Re-energising the escalation with new information (the deadline didn't exist two days ago), keeping the record accurate, and pairing an honest status with a concrete fallback converts tomorrow from a gamble into a plan. Option A is a comfortable guess. Option B is a complete abdication. Option D exceeds training on infrastructure not owned, alone, out of hours. This tests persistent ownership, honest communication, and contingency thinking.

### Administration tips

- **Score for whether a candidate acts and communicates together** — the strongest options both fix or route the problem and keep people informed.
- **Watch for whether a candidate escalates with evidence and follow-through**, rather than either heroics or silence.
- **Note whether a candidate distinguishes honesty from harshness** in user-facing scenarios.
- **Use most/least items to check whether a candidate rates each option on its own merits.**
- **Keep candidates scored to associate-level judgement** — escalate well, not solve alone.

### Common pitfalls to watch for when scoring

- **Rewarding the heroic answer** where a candidate single-handedly fixes something beyond training.
- **Crediting the invisible answer** — silence, waiting, hoping, "not my place."
- **Confusing honest bluntness with unkindness**, or vice versa.
- **Rewarding over-escalation of minor decisions** as if it were appropriate caution.
- **Missing when a candidate lets a promise outrun what can actually be controlled.**

## Conclusion

This document has given you a substantial set of assessment material for the four types most relevant to an associate end user computing engineer: cognitive ability, numerical reasoning, verbal reasoning, and situational judgement.

The cognitive section tests checking ticket references and asset logs for small errors, chaining facts to explain a recurring fault, and applying escalation and allocation rules precisely. The numeric section tests closure rates, SLA deadlines, and spotting a misleading average. The verbal section tests reading knowledge articles and policy extracts precisely and drafting honest, kind updates. The situational judgement section tests judgement calls about escalation, mistakes, shortcuts, and inclusion.

**Scoring and debrief.** Work through each section's worked answers against the candidate's responses, using the explanations above as an answer key and as talking points. A candidate who reasons well but lands on the wrong answer is a different signal from one who guesses. A short debrief conversation afterwards is often more informative than the raw score.

**Records and consistency.** Keep a note of the conditions under which the assessment was administered alongside the result, and use the same items and conditions for every candidate assessed for this role level.

**One assessment among several.** This result is one input into a wider decision about whether a candidate can support carefully, read procedures precisely, and exercise sound judgement about when to act and when to ask — never the whole of that decision. Pair it with the candidate's experience and a conversation, and revisit the advisory above before it informs any hiring, promotion, pay, performance or disciplinary decision.
