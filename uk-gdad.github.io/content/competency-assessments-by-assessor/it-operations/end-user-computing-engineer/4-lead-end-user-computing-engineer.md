# Lead End User Computing Engineer - Competency Assessment

## Introduction

This assessment is for an assessor — a line manager, an interview panel
member, or anyone else evaluating a candidate or an employee — who needs to
judge whether a person has the baseline abilities the IT operations
profession's lead end user computing engineer role level requires. It measures
demonstrated skill against the UK GDAD Profession Capability Framework's own
description of this level, for a hiring decision, a promotion or progression
board, onboarding a new starter, or a periodic capability check. It is one
input into that decision, never the whole of it — see `## Advisory` before
you begin.

## Advisory

This competency assessment is created by AI and is a work in progress for
educational purposes. It is not a validated assessment instrument — it has
not been piloted, normed or checked for adverse impact — and a rating on this
form must never be the sole basis for a hiring, promotion, pay, performance or
disciplinary decision. Before using it, consult your organisation's human
resources, people development, occupational psychology or legal compliance
colleagues.

## How to use this assessment

**Preparing.** Read `## About this role level` first, so you know what the
framework actually expects before you look at any evidence. Then gather what
exists for this person: a CV or portfolio, a structured interview, a work
sample or task, direct observation of them at work, or references from people
who have worked with them. At this level the framework expects expert
technical understanding alongside vendor and supplier accountability, so look
for evidence of both technical depth and commercial or supplier-facing
judgement.

**Score on evidence, not impression.** Every rating must trace to something
the person did, said, produced, or was observed doing. If you cannot point to
evidence for a rating, record it as unknown rather than guess — an honest gap
teaches you more than a guess dressed up as a score.

**Stay consistent.** Score every candidate for this role level the same way,
using the same evidence sources wherever you can. For a hiring or promotion
decision, have more than one assessor score independently, then compare notes,
rather than settling on a single view first.

**Fairness.** An unvalidated, AI-drafted instrument like this one, used
inconsistently, can produce unlawful adverse impact even when nobody intends
it. Consistent, evidence-based administration by more than one assessor
materially reduces that risk. Never let a rating be influenced by anything
other than demonstrated, job-related evidence.

## Rating scale

Every skill in the competency matrix is rated on the same five-point
proficiency scale — how well the person does the thing, on the evidence
available, not how often they do it.

| Value | Rating | Meaning |
| ---: | --- | --- |
| 0 | None | No demonstrated experience of this skill |
| 1 | Beginner | Just starting to learn the skill; requires close supervision |
| 2 | Intermediate | Knows the basics and can perform tasks with some guidance |
| 3 | Advanced | Has a strong grasp of the skill and can work independently |
| 4 | Expert | Demonstrates full mastery and can teach or guide others in the skill |

**Worked example.** Take Skill: User focus. At 2 — Intermediate, a candidate
engages a user directly to understand their need and uses that to resolve one
issue well. At 3 — Advanced, they champion user research more widely and can
explain the difference between what a user asks for and what they actually
need. At 4 — Expert, the baseline for this level, they collaborate with user
researchers, represent users internally, prioritise and define the approach
to understanding the user story, guide others in doing so, and recommend
which tools and methods the team should use — the framework's own wording for
this level, and a clear step beyond independent competence into guiding
others. Calibrate against evidence like this before you start scoring.

## About this role level

IT operations role: End user computing engineer. An end user computing
engineer is responsible for managing the product life cycle of all
service-raised incidents (incident control) and all service requests (request
control), which requires the use of knowledge management. In this role, you
are also responsible for informing customers on progress and advising on
workarounds where necessary, as well as the support and maintenance of end
user services.

The role has five levels, in order: associate end user computing engineer,
end user computing engineer, senior end user computing engineer, lead end user
computing engineer, and principal end user computing engineer. This assessment
covers lead end user computing engineer, the fourth of those.

Role level: Lead end user computing engineer. A lead end user computing
engineer has expert technical understanding and is accountable for vendor and
supplier management. At this level, the framework expects someone to work
with relevant IT operations and other functions, such as technical
architecture, to understand lower-level productivity, development and
feasibility. The framework does not list separate day-to-day accountability
bullets for this level beyond this description; its expectations are carried
in the skills below.

The framework names eleven skills for this level: Asset and configuration
management, Change management, IT service reporting, Incident management,
Ownership and initiative, Problem management, Service focus, Service
management framework knowledge, Technical specialism, Testing, and User
focus.

## Competency matrix

### Skill: Asset and configuration management

**What the framework expects at this level**

A lead end user computing engineer maintains secure configuration and
accurate information, controls IT assets in one or more areas, and verifies
the location and state of IT assets.

**Baseline for this role level**

Baseline: 3 — Advanced. The framework's wording is unchanged since level 2,
but by the time someone leads vendor and supplier relationships and expert
technical work, foundational configuration control is assumed to be strong
and independent rather than merely guided — its absence from this level's
extra wording reflects that it is no longer a growth area, not a lowered
expectation.

**Behavioural indicators**

- 0 — None: cannot say where the asset register is or what it is for.
- 1 — Beginner: updates the asset register when told exactly what to change.
- 2 — Intermediate: keeps configuration and asset records accurate for their
  own area, and can verify an asset's location and state without prompting.
- 3 — Advanced: spots and corrects a discrepancy in the asset register before
  it causes a problem, and improves how the team keeps records.
- 4 — Expert: owns asset and configuration accuracy across a whole service
  and is the person others check a difficult record against.

**Evidence to gather**

- Ask the candidate to describe how they have improved asset or configuration
  accuracy for a team, not just for themselves.
- Review an asset or configuration standard they set or improved.
- Ask a referee for an example of the candidate catching a systemic
  configuration problem before it caused an incident.

### Skill: Change management

**What the framework expects at this level**

A lead end user computing engineer manages high-impact, complex change
requests and ensures that release policies, procedures and processes are
applied.

**Baseline for this role level**

Baseline: 4 — Expert. Managing high-impact, complex changes and being
responsible for release policy application, rather than just assessing and
actioning changes, is ownership at a scale that fits full mastery — the
person others rely on to get the highest-risk changes right.

**Behavioural indicators**

- 0 — None: cannot describe what makes a change high-impact or complex.
- 1 — Beginner: contributes to part of a complex change under a colleague's
  direction.
- 2 — Intermediate: manages a moderately complex change with a senior
  colleague available to check progress.
- 3 — Advanced: manages a high-impact, complex change independently, and
  applies release policies correctly.
- 4 — Expert: manages the highest-impact, most complex changes in the
  service, and ensures the wider team applies release policy consistently.

**Evidence to gather**

- Ask the candidate to describe a high-impact, complex change they managed
  end to end, including how they handled the risk.
- Review a change record or post-implementation review for a complex change
  they led.
- Ask a referee whether the candidate's management of complex changes has
  needed correction, and how release policy compliance was checked.

### Skill: IT service reporting

**What the framework expects at this level**

A lead end user computing engineer produces relevant reports in an
appropriate format and agreed timeframe, works with stakeholders to discuss
any changes in the reporting processes, and interprets a data set and
communicates this to others.

**Baseline for this role level**

Baseline: 3 — Advanced. The framework's wording is unchanged from the senior
level, and this level's growth is expressed through Change management,
Incident management and User focus instead — Advanced remains the right
baseline here.

**Behavioural indicators**

- 0 — None: cannot produce a report to an agreed format.
- 1 — Beginner: produces a report to a template someone else has set, with
  the content checked before it is sent.
- 2 — Intermediate: produces reports to the agreed format and timeframe
  unassisted, but relies on others to interpret what the numbers mean.
- 3 — Advanced: produces reports to format and timeframe, interprets the data
  for stakeholders in plain terms, and discusses process changes with them.
- 4 — Expert: redesigns the reporting process for a service and gets
  stakeholder buy-in for it.

**Evidence to gather**

- Ask the candidate to walk through a report they produced and how they
  explained the data in it to a stakeholder.
- Review a report and any accompanying commentary they wrote.
- Ask a referee for an example of the candidate discussing a reporting process
  change with a stakeholder.

### Skill: Incident management

**What the framework expects at this level**

A lead end user computing engineer leads the investigation and resolution of
incidents.

**Baseline for this role level**

Baseline: 4 — Expert. Leading the investigation and resolution, rather than
personally diagnosing and prioritising as at senior level, is directing
others through incidents — the teaching-and-guiding definition of Expert on
this scale.

**Behavioural indicators**

- 0 — None: cannot organise an incident response beyond their own actions.
- 1 — Beginner: follows another lead's direction during an incident.
- 2 — Intermediate: directs a straightforward incident response with support
  available if it escalates.
- 3 — Advanced: leads the investigation and resolution of most incidents
  independently, co-ordinating others involved.
- 4 — Expert: leads the response to the most serious or complex incidents,
  and is the person others learn incident leadership from.

**Evidence to gather**

- Ask the candidate to describe an incident they led the investigation and
  resolution of, including how they directed others involved.
- Ask a referee to describe the candidate's leadership during a difficult
  incident.
- Review an incident report or post-incident review the candidate authored or
  led.

### Skill: Ownership and initiative

**What the framework expects at this level**

A lead end user computing engineer takes accountability for issues that occur
and is proactive in searching for potential problems, and achieves excellent
user outcomes.

**Baseline for this role level**

Baseline: 3 — Advanced. Proactively searching for problems before they occur,
rather than only owning an issue once it exists, is a genuine step up from
the level below, matching independent, strong-grasp practice.

**Behavioural indicators**

- 0 — None: only acts once an issue has already been raised.
- 1 — Beginner: owns an existing issue through to resolution when reminded to.
- 2 — Intermediate: owns issues through to resolution unprompted, but has not
  yet proactively surfaced a potential problem before it occurred.
- 3 — Advanced: takes accountability for issues that occur, proactively looks
  for potential problems, and consistently achieves a good outcome for users.
- 4 — Expert: builds a habit of proactive problem-searching into how the
  whole team works.

**Evidence to gather**

- Ask for an example of a potential problem the candidate spotted and
  addressed before it became an incident.
- Ask a referee whether the candidate takes accountability when something
  goes wrong, or shifts blame.
- Review evidence of a user outcome the candidate achieved that went beyond
  the minimum fix.

### Skill: Problem management

**What the framework expects at this level**

A lead end user computing engineer initiates and monitors actions to
investigate patterns and trends to resolve problems, effectively consults
specialists where required, determines the appropriate resolution and assists
with its implementation, and determines preventative measures.

**Baseline for this role level**

Baseline: 3 — Advanced. The framework's wording is unchanged from the senior
level, so the baseline holds; this level's added weight sits in Change
management, Incident management and vendor accountability instead.

**Behavioural indicators**

- 0 — None: cannot distinguish a problem from an incident.
- 1 — Beginner: investigates a problem when told exactly what to look at.
- 2 — Intermediate: investigates a problem and contributes ideas to a remedy,
  but relies on a colleague to decide the resolution.
- 3 — Advanced: initiates and monitors an investigation into a pattern or
  trend, consults specialists appropriately, determines the resolution and
  the preventative measure, and assists with implementing it.
- 4 — Expert: spots a pattern across problems that others have missed and
  changes how the team investigates as a result.

**Evidence to gather**

- Ask the candidate to describe a problem investigation they initiated, who
  they consulted, and what resolution and preventative measure they
  determined.
- Review a problem record or root-cause report they own.
- Ask a referee for an example of a preventative measure the candidate
  determined that stopped a recurring issue.

### Skill: Service focus

**What the framework expects at this level**

A lead end user computing engineer takes inputs and establishes coherent
frameworks that work.

**Baseline for this role level**

Baseline: 3 — Advanced. The framework's wording is unchanged since level 2,
but a lead who is accountable for vendors and cross-functional work is
expected to shape frameworks that work for others, not only for themselves —
Advanced reflects that without over-reading a static line of text.

**Behavioural indicators**

- 0 — None: cannot describe how their daily tasks fit into the wider service.
- 1 — Beginner: follows a service framework someone else has set up.
- 2 — Intermediate: takes several inputs and organises their own work into a

- 3 — Advanced: improves a service framework so it works better for the
  wider team or across a cross-functional relationship.
- 4 — Expert: designs a service framework that a whole team or programme
  adopts.

**Evidence to gather**

- Ask the candidate to describe a framework or way of working they improved
  that spanned more than their own tasks.
- Ask a referee whether the candidate's framework changes have made the wider
  team's work easier.
- Review a process document or framework the candidate authored.

### Skill: Service management framework knowledge

**What the framework expects at this level**

A lead end user computing engineer shows they have a Level 3 service
management framework qualification and demonstrates knowledge of the life
cycle or capability elements of ITIL (Information Technology Infrastructure
Library).

**Baseline for this role level**

Baseline: 3 — Advanced. The framework adds ITIL life cycle or capability
knowledge on top of the qualification held at levels 2 and 3 — a genuine
widening of the skill that supports an Advanced baseline.

**Behavioural indicators**

- 0 — None: holds no service management framework qualification and cannot
  describe ITIL concepts.
- 1 — Beginner: holds the Level 3 qualification but cannot yet explain ITIL
  life cycle or capability elements.
- 2 — Intermediate: holds the qualification and describes ITIL life cycle or
  capability elements with some prompting.
- 3 — Advanced: holds the qualification and demonstrates working knowledge of
  ITIL life cycle or capability elements, applying them in day-to-day
  decisions.
- 4 — Expert: is asked to explain ITIL concepts to colleagues or shape how
  the team applies them.

**Evidence to gather**

- Ask the candidate to explain how an ITIL life cycle or capability element
  applies to a decision they made recently.
- Ask them to show their Level 3 service management framework certificate or
  equivalent evidence.
- Ask a referee whether the candidate has helped colleagues understand ITIL
  concepts.

### Skill: Technical specialism

**What the framework expects at this level**

A lead end user computing engineer drafts and maintains procedures and
documentation, and sets standards for the definition, security and integrity
of objects, ensuring conformity to these standards.

**Baseline for this role level**

Baseline: 4 — Expert. Setting the standards others must conform to, rather
than applying tools and carrying out configuration as at the senior level, is
the standard-setting definition of Expert on this scale, and fits a level
described as having expert technical understanding.

**Behavioural indicators**

- 0 — None: cannot describe what a technical standard for objects covers.
- 1 — Beginner: follows a technical standard someone else has set.
- 2 — Intermediate: drafts routine procedure documentation with a colleague
  reviewing it.
- 3 — Advanced: drafts and maintains procedures and documentation
  independently, and checks conformity to existing standards.
- 4 — Expert: sets the standards for the definition, security and integrity
  of objects that others must conform to, and is the escalation point when
  conformity is in doubt.

**Evidence to gather**

- Ask the candidate to describe a technical standard they set or
  significantly revised, and why.

### Skill: User focus

**What the framework expects at this level**

A lead end user computing engineer collaborates with user researchers and can
represent users internally, explains the difference between user needs and
the desires of the user, champions user research to focus on all users,
prioritises and defines approaches to understand the user story while guiding
others in doing so, and offers recommendations on the best tools and methods
to use.

**Baseline for this role level**

Baseline: 4 — Expert. Guiding others through the approach to the user story
and championing user research across the team is teaching-and-guiding work —
a clear jump from independently engaging users at the levels below, and the
scale's own definition of Expert.

**Behavioural indicators**

- 0 — None: fixes the reported fault without asking the user anything about
  their wider need.
- 1 — Beginner: engages users directly when directed to.
- 2 — Intermediate: engages users to understand their actual need and uses
  that to resolve issues well.
- 3 — Advanced: champions user research and can explain, to a colleague, the
  difference between what a user asks for and what they need.
- 4 — Expert: represents users internally, prioritises and defines the
  approach to the user story, guides colleagues through it, and recommends
  which tools or methods the team should use.

**Evidence to gather**

- Ask for an example of the candidate guiding a colleague through
  understanding a user's actual need.
- Ask a referee whether the candidate is seen internally as representing
  users' interests.
- Review a recommendation the candidate made about which tools or methods the
  team should use for user focus work.
