# Senior End User Computing Engineer - Competency Assessment

## Introduction

This assessment is for an assessor — a line manager, an interview panel
member, or anyone else evaluating a candidate or an employee — who needs to
judge whether a person has the baseline abilities the IT operations
profession's senior end user computing engineer role level requires. It
measures demonstrated skill against the UK GDAD Profession Capability
Framework's own description of this level, for a hiring decision, a promotion
or progression board, onboarding a new starter, or a periodic capability
check. It is one input into that decision, never the whole of it — see
`## Advisory` before you begin.

## Advisory

This competency assessment is created by AI and is a work in progress for
educational purposes. It is not a validated assessment instrument — it has
not been piloted, normed or checked for adverse impact — and a rating on this
form must never be the sole basis for a hiring, promotion, pay, performance or
disciplinary decision. Before using it, consult your organisation's human
resources, people development, occupational psychology, or legal compliance
colleagues.

## How to use this assessment

**Preparing.** Read `## About this role level` first, so you know what the
framework actually expects before you look at any evidence. Then gather what
exists for this person: a CV or portfolio, a structured interview, a work
sample or task, direct observation of them at work, or references from people
who have worked with them. At this level the framework expects both team
co-ordination and hands-on technical problem-solving, so look for evidence of
both, not just one or the other.

**Score on evidence, not impression.** Every rating must trace to something
the person did, said, produced, or was observed doing. If you cannot point to
evidence for a rating, record it as unknown rather than guess — an honest gap
teaches you more than a guess dressed up as a score.

**Stay consistent.** Score every candidate for this role level the same way,
using the same evidence sources wherever you can. For a hiring or promotion
decision, have more than one assessor score independently, then compare notes,
rather than settling on a single view first.

**Fairness.** An unvalidated, AI-drafted instrument like this one, used
inconsistently, can produce unlawful adverse impact even when nobody intends
it. Consistent, evidence-based administration by more than one assessor
materially reduces that risk. Never let a rating be influenced by anything
other than demonstrated, job-related evidence.

## Rating scale

Every skill in the competency matrix is rated on the same four-point
proficiency scale — how well the person does the thing, on the evidence
available, not how often they do it.

| Value | Rating | Meaning |
| ---: | --- | --- |
| 1 | Awareness | You can describe skill fundamentals and show basic knowledge of related tools |
| 2 | Working | You can apply the skill with some support and use appropriate tools |
| 3 | Practitioner | You can apply the skill independently, determine the best tools, and share your experience |
| 4 | Expert | You can lead organisational best practice and teach advanced techniques |

**Worked example.** Take Skill: Incident management. At 2 — Working, a
candidate diagnoses a familiar incident and finds a resolution with some
guidance from a colleague. At 3 — Practitioner, the baseline for this level, they
diagnose and prioritise an incident against other open work unassisted,
investigate its cause and find the resolution themselves — matching the
framework's own wording for this level. At 4 — Expert, they are the person
colleagues escalate to when an incident resists diagnosis, and they teach the
diagnostic technique to others. Calibrate against evidence like this before
you start scoring.

## About this role level

IT operations role: End user computing engineer. An end user computing
engineer is responsible for managing the product life cycle of all
service-raised incidents (incident control) and all service requests (request
control), which requires the use of knowledge management. In this role, you
are also responsible for informing customers on progress and advising on
workarounds where necessary, as well as the support and maintenance of end
user services.

The role has five levels, in order: associate end user computing engineer,
end user computing engineer, senior end user computing engineer, lead end user
computing engineer, and principal end user computing engineer. This assessment
covers senior end user computing engineer, the third of those.

Role level: Senior end user computing engineer. A senior end user computing
engineer is responsible for managing the team but also gets involved in
solving technical problems.

At this role level, the framework expects someone to:

- manage, co-ordinate and prioritise tasks to resolve technical incidents as
  quickly as possible
- work closely with infrastructure, capacity managers and availability
  managers to fix technical problems, and identify and escalate repeat issues
  to the lead end user computing engineer, the incident or problem manager
  and software developers

The framework names eleven skills for this level: Asset and configuration
management, Change management, IT service reporting, Incident management,
Ownership and initiative, Problem management, Service focus, Service
management framework knowledge, Technical specialism, Testing, and User
focus.

## Competency matrix

### Skill: Asset and configuration management

**What the framework expects at this level**

A senior end user computing engineer maintains secure configuration and
accurate information, controls IT assets in one or more areas, and verifies
the location and state of IT assets.

**Baseline for this role level**

Baseline: 2 — Working. The framework's wording for this skill is
unchanged from the level below, so the baseline stays at Working too —
this level's step up shows in Incident management and team co-ordination, not
here.

**Behavioural indicators**

- 1 — Awareness: updates the asset register when told exactly what to change.
- 2 — Working: keeps configuration and asset records accurate for their
  own area day to day, and can verify an asset's location and state without
  prompting.
- 3 — Practitioner: spots and corrects a discrepancy in the asset register before
  it causes a problem, and improves how their team keeps records.
- 4 — Expert: owns asset and configuration accuracy across a whole service and
  is the person others check a difficult record against.

**Evidence to gather**

- Ask the candidate to describe how they keep an asset or configuration record
  accurate day to day, with an example.
- Review an asset or configuration record they maintained, and ask what would
  have gone wrong if it had drifted.
- Ask a referee for an example of the candidate catching an inaccurate asset
  record before it caused an incident.

### Skill: Change management

**What the framework expects at this level**

A senior end user computing engineer analyses and assesses the impact of
change, documents change requests, and actions changes from change requests.

**Baseline for this role level**

Baseline: 3 — Practitioner. This is a clear step up from implementing change
requests under supervision at level 2: assessing impact and actioning changes
independently is exactly the strong grasp and independent working the scale
describes as Practitioner.

**Behavioural indicators**

- 1 — Awareness: documents a change request when given the details to record.
- 2 — Working: assesses the impact of a straightforward change with a
  colleague checking the assessment.
- 3 — Practitioner: independently analyses and assesses the impact of a change,
  documents the request properly, and actions it.
- 4 — Expert: is consulted on the impact assessment for the highest-risk
  changes in the service.

**Evidence to gather**

- Ask the candidate to walk through a change they assessed, documented and
  actioned, including what they judged the impact to be and why.
- Review a change record showing their impact assessment.
- Ask a referee about a change the candidate actioned that had a wider impact
  than first expected, and how they handled it.

**Rate this skill**

- [ ] 1 — Awareness
- [ ] 2 — Working
- [ ] 3 — Practitioner
- [ ] 4 — Expert

### Skill: IT service reporting

**What the framework expects at this level**

A senior end user computing engineer produces relevant reports in an
appropriate format and agreed timeframe, works with stakeholders to discuss
any changes in the reporting processes, and interprets a data set and
communicates this to others.

**Baseline for this role level**

Baseline: 3 — Practitioner. Interpreting a data set for stakeholders and shaping
the reporting process itself, rather than only collating basic reports, is
independent, judgement-based work.

**Behavioural indicators**

- 1 — Awareness: produces a report to a template someone else has set, with
  the content checked before it is sent.
- 2 — Working: produces reports to the agreed format and timeframe
  unassisted, but relies on others to interpret what the numbers mean.
- 3 — Practitioner: produces reports to format and timeframe, interprets the data
  for stakeholders in plain terms, and discusses process changes with them.
- 4 — Expert: redesigns the reporting process for a service and gets
  stakeholder buy-in for it.

**Evidence to gather**

- Ask the candidate to walk through a report they produced and how they
  explained the data in it to a stakeholder.
- Review a report and any accompanying commentary they wrote.
- Ask a referee for an example of the candidate discussing a reporting process
  change with a stakeholder.

**Rate this skill**

- [ ] 3 — Practitioner

### Skill: Incident management

**What the framework expects at this level**

A senior end user computing engineer diagnoses and prioritises incidents,
investigates their causes and finds resolutions.

**Baseline for this role level**

Baseline: 3 — Practitioner. This is the clearest step up in the whole matrix from
level 2's register-and-route work: diagnosing, prioritising, and resolving
unassisted is independent, strong-grasp work by the scale's own definition.

**Behavioural indicators**

- 1 — Awareness: diagnoses a familiar incident with a colleague checking the
  reasoning.
- 2 — Working: diagnoses and resolves familiar incidents unassisted, but
  needs help prioritising against a busy queue.
- 3 — Practitioner: independently diagnoses and prioritises incidents against
  competing work, investigates the cause, and finds the resolution.
- 4 — Expert: is the escalation point for incidents that have resisted
  diagnosis by others, and teaches the diagnostic approach to the team.

**Evidence to gather**

- Walk through a real or simulated incident scenario and observe how the
  candidate prioritises and diagnoses it.
- Ask for an example of an incident they investigated from first report to
  resolution.
- Ask a referee for an example of the candidate correctly prioritising one
  incident over another under pressure.

**Rate this skill**

- [ ] 2 — Working
- [ ] 3 — Practitioner

### Skill: Ownership and initiative

**What the framework expects at this level**

A senior end user computing engineer owns an issue until a new owner has been
found or the problem has been mitigated or resolved.

**Baseline for this role level**

Baseline: 2 — Working. The framework's wording for this skill is
unchanged from level 2, so the baseline holds; this level's accountability
growth shows in team co-ordination and incident management, not in a wider
definition of ownership.

**Behavioural indicators**

- 1 — Awareness: keeps an issue open on their own list but needs reminding to
  chase it.
- 2 — Working: tracks an issue through to a confirmed handover or
  resolution without being chased.
- 3 — Practitioner: proactively checks that a handed-over issue actually landed
  with its new owner and was picked up.
- 4 — Expert: is the person others rely on to never let an issue slip, across
  a whole shift or team.

**Evidence to gather**

- Ask for an example of an issue the candidate followed through to resolution
  or a confirmed handover.
- Ask a referee whether issues assigned to the candidate have gone missing or
  stalled.
- Review a ticket history showing the candidate's ownership of an issue over
  time.

### Skill: Problem management

**What the framework expects at this level**

A senior end user computing engineer initiates and monitors actions to
investigate patterns and trends to resolve problems, effectively consults
specialists where required, determines the appropriate resolution and assists
with its implementation, and determines preventative measures.

**Baseline for this role level**

Baseline: 3 — Practitioner. Determining the resolution and preventative measures,
rather than only investigating and contributing as at level 2, is
independent, judgement-driven ownership of the whole problem, matching
Practitioner.

**Behavioural indicators**

- 1 — Awareness: investigates a problem when told exactly what to look at.
- 2 — Working: investigates a problem and contributes ideas to a remedy,
  but relies on a colleague to decide the resolution.
- 3 — Practitioner: initiates and monitors an investigation into a pattern or
  trend, consults specialists appropriately, determines the resolution and
  the preventative measure, and assists with implementing it.
- 4 — Expert: spots a pattern across problems that others have missed and
  changes how the team investigates as a result.

**Evidence to gather**

- Ask the candidate to describe a problem investigation they initiated, who
  they consulted, and what resolution and preventative measure they
  determined.
- Review a problem record or root-cause report they own.
- Ask a referee for an example of a preventative measure the candidate
  determined that stopped a recurring issue.

**Rate this skill**

- [ ] 1 — Awareness
- [ ] 2 — Working
- [ ] 3 — Practitioner
- [ ] 4 — Expert

### Skill: Service focus

**What the framework expects at this level**

A senior end user computing engineer takes inputs and establishes coherent
frameworks that work.

**Baseline for this role level**

Baseline: 2 — Working. The framework's wording for this skill is
unchanged from level 2; this level's growth in scope is expressed through
Incident management, Problem management, and team co-ordination duties rather
than through a wider Service focus expectation.

**Behavioural indicators**

- 1 — Awareness: follows a service framework someone else has set up.
- 2 — Working: takes several inputs — tickets, requests, escalations —
  and organises their own and their team's work into a coherent, working
  routine.
- 3 — Practitioner: improves a service framework so it works better for the
  wider team.
- 4 — Expert: designs a service framework that a whole team adopts.

**Evidence to gather**

- Ask the candidate to describe how they organise a busy mix of incidents,
  requests and team co-ordination into a coherent routine.
- Ask a referee whether the candidate's way of working has helped or hindered
  the wider team.
- Review any process note or checklist the candidate has produced for the
  team.

### Skill: Service management framework knowledge

**What the framework expects at this level**

A senior end user computing engineer shows they have a Level 3 service
management framework qualification.

**Baseline for this role level**

Baseline: 2 — Working. The framework's wording is unchanged from level 2:
the same qualification is expected, applied with working knowledge rather than
taught to others.

**Behavioural indicators**

- 1 — Awareness: is working towards a Level 3 service management framework
  qualification.
- 2 — Working: holds a Level 3 service management framework
  qualification and applies its concepts correctly in day-to-day work.
- 3 — Practitioner: applies the framework's concepts to improve how their team
  works, beyond what the qualification alone requires.
- 4 — Expert: holds a higher-level qualification or is asked to explain the
  framework to others.

**Evidence to gather**

- Ask the candidate to show their Level 3 service management framework
  certificate or equivalent evidence.
- Ask the candidate to explain a framework concept, such as incident versus
  problem, in their own words.
- Ask a referee how the candidate applies the framework in practice.

### Skill: Technical specialism

**What the framework expects at this level**

A senior end user computing engineer uses management system software and
tools, uses logical schemata to investigate problems, collect performance
statistics and create reports, carries out the routine configuration,
installation and reconfiguration of database and related products, and
optimises performance and forecasts resource needs.

**Baseline for this role level**

Baseline: 3 — Practitioner. This is a marked step up from "assisting" and
"routine maintenance" at level 2: using management tools, optimising
performance and forecasting resource needs is independent specialist work.

**Behavioural indicators**

- 1 — Awareness: uses management system software for routine tasks with
  guidance.
- 2 — Working: uses management system software and logical schemata to
  investigate a familiar problem, with a colleague checking the outcome.
- 3 — Practitioner: independently uses management tools and schemata to
  investigate problems, configures and reconfigures database and related
  products, and forecasts resource needs.
- 4 — Expert: is consulted on the hardest performance and capacity forecasts
  in the service.

**Evidence to gather**

- Ask the candidate to describe a resource forecast or performance
  optimisation they carried out, and what data they used.
- Observe or ask them to walk through a routine database configuration task.
- Ask a referee for an example of the candidate's forecast proving accurate,
  or where it needed correcting.

**Rate this skill**

- [ ] 1 — Awareness
- [ ] 2 — Working
- [ ] 3 — Practitioner
- [ ] 4 — Expert

### Skill: User focus

**What the framework expects at this level**

A senior end user computing engineer identifies and engages with users or
stakeholders to collate user needs evidence, understands and defines research
that fits user needs, and uses quantitative and qualitative data about users
to turn user focus into outcomes.

**Baseline for this role level**

Baseline: 2 — Working. The framework's wording is unchanged from level 2;
this level's growth is expressed through team co-ordination and incident
ownership rather than a wider User focus expectation.

**Behavioural indicators**

- 1 — Awareness: asks the user basic clarifying questions when prompted to.
- 2 — Working: engages the user directly to understand what they
  actually need, not just what they reported, and uses that to resolve the
  issue in a way that works for them.
- 3 — Practitioner: spots a pattern in what several users need and feeds it back
  so the service improves for everyone.
- 4 — Expert: shapes how the wider team engages with users.

**Evidence to gather**

- Observe or ask the candidate to describe an interaction where they found out
  more than the user's initial report.
- Ask for an example where understanding a user's actual need changed how they
  resolved an issue.
- Ask a referee how users or colleagues describe the candidate's manner with
  users.
