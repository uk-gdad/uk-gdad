# Data architect - start here

Welcome. If you are working toward the data architect level, this page is
for you: what the role is about, where to find everything else this
repository has for it, and a pathway for building the skills it asks for.

## Purpose

A data architect sets the vision for how an organisation uses data, through
data design, making sure that data is managed properly and meets the
organisation's needs. At this level, you design and build the data models
that fulfil the strategic data needs defined by chief data architects —
turning someone else's strategic intent into something concrete teams can
actually build against. You design, support and guide the upgrade,
management, decommissioning and archiving of data in line with data policy,
contribute to data dictionaries, and define and maintain the data
technology architecture, including metadata, integration and business
intelligence or data warehouse architecture.

## Learning pathway

Work through these roughly in order. Each one is a requirement of this role
level, described plainly, with a way to go deeper by asking an AI tool a
specific question — the answers you get will be shaped around your own
organisation's data landscape, which a generic guide never is.

- [ ] **Build and maintain data models for real organisational needs**

  Explain the concepts and principles of data modelling, produce, maintain
  and update data models for your organisation's specific needs, and
  reverse-engineer models from a live system when no model already exists.

  Ask AI: "Explain, for someone new to data architecture, what a data model
  actually is and why reverse-engineering one from a live system is often
  necessary."

- [ ] **Understand what governance a data solution needs**

  Understand what data governance is required for a given solution, and
  take responsibility for assuring data solutions, recommending what's
  needed for compliance.

  Ask AI: "How would a data architect work out what level of data
  governance a specific solution actually needs, rather than applying the
  same checklist regardless of context?"

- [ ] **Apply and help develop data standards**

  Use data policies, processes and standards effectively, work with
  subject matter experts to develop standards that protect data, monitor
  compliance within your team, and analyse the impact when a standard is
  breached.

  Ask AI: "What would a data architect look for when analysing the impact
  of a standards breach, beyond just noting that it happened?"

- [ ] **Use metadata to support complex analysis**

  Use metadata repositories to complete complex tasks such as data and
  systems integration impact analysis, and maintain a repository to keep
  information accurate and current.

  Ask AI: "Explain, simply, what a metadata repository is for and why
  keeping it accurate matters for tasks like integration impact analysis."

- [ ] **Profile data, and present clear insight**

  Undertake data profiling and source system analysis, and present clear
  insights to colleagues to support how the data actually gets used.

  Ask AI: "What makes a data profiling finding genuinely useful to a
  colleague who isn't a data specialist, rather than just technically
  accurate?"

- [ ] **Investigate and resolve data problems**

  Initiate and monitor actions to investigate patterns and trends behind
  problems, consult specialists where needed, determine the right
  resolution and help implement it, and identify preventative measures.

  Ask AI: "What's the difference between fixing a data problem and
  preventing the same class of problem from recurring, and how would a
  data architect approach the second?"

- [ ] **Communicate data with the end user in mind**

  Show an awareness that data needs to be aligned to the end user's needs,
  and create basic visuals and presentations that reflect that.

  Ask AI: "What makes a data visualisation genuinely aligned to what an
  end user needs, rather than just an accurate chart?"

- [ ] **Communicate effectively between technical and non-technical people**

  Communicate effectively with technical and non-technical stakeholders,
  support discussions within a multidisciplinary team that may have
  difficult dynamics, advocate for your team externally, and manage
  differing stakeholder perspectives.

  Ask AI: "What should a data architect focus on when explaining a
  technical data decision to a non-technical stakeholder, so it actually
  lands?"

- [ ] **Stay aware of innovation in data tools and uses**

  Show an awareness of opportunities for innovation with new tools and
  uses of data, without needing to champion their adoption yet.

  Ask AI: "How would a data architect stay aware of emerging data tools
  and techniques without it becoming a full-time pursuit alongside their
  actual job?"

- [ ] **Start connecting your work to the wider strategy**

  Explain the strategic context of your work and why it matters, and
  support strategic planning in an administrative capacity.

  Ask AI: "How would a data architect find out the strategic context
  behind a data model they've been asked to build, if nobody's explained
  it to them?"

Ask your manager or a more senior architect which of these your team relies on
most right now, and start there.
