# Chief information security officer - start here

Welcome. If you are working as, or working toward, a chief information
security officer role, this page is for you: what the role is about, where
to find everything else this repository has for it, and a pathway for
building the areas it names.

**One thing to know before you start.** The framework publishes this role and
its duties, but marks the role level as **not in use** and gives no
expectations against any of its named skills. That is the framework's own
position, not a gap in this page. So instead of a level-graded pathway, what
follows works from the role's own duties, grouped under the skill names the
framework does publish for it.

## Purpose

A chief information security officer creates the environment and culture
that keeps an organisation's information and technology secure, so that it
can achieve its objectives and deliver services safely rather than
cautiously. The role sits in both the Government Digital and Data profession
and the Government Security profession, which is a useful reminder that
security here is not a specialist add-on: it has to work as part of how the
whole organisation delivers, or it will quietly get worked around. Everything
below — strategy, governance, architecture, risk, incident response, culture
and capability — exists to make security something the organisation does, not
just something it is told to comply with.

## Learning pathway

Work through these roughly in order. There is no level above this role to
measure yourself against, so use an AI tool as a sounding board: describe a
real decision you're weighing and ask it to argue the case you haven't made
yet.

- [ ] **Strategic cyber security planning**

  Create a strategy for information and cyber security that supports both
  your organisation's own strategy and the wider government security
  strategy — a security strategy written in isolation from the
  organisation's actual goals rarely survives contact with real priorities.

  Ask AI: "How does a security leader write a cyber security strategy that
  genuinely supports the organisation's broader goals, rather than sitting
  alongside them as a separate document?"

- [ ] **Cyber security governance**

  Lead the organisation in actually implementing the strategy, and
  honestly evaluate the current status and maturity of information and
  cyber security rather than assuming policies on paper reflect practice on
  the ground.

  Ask AI: "What's a credible way for a security leader to assess their
  organisation's real security maturity, as opposed to relying on
  self-reported compliance?"

- [ ] **Security architecture**

  Determine how to get the organisation to the level of security maturity
  it actually needs — which is an architectural question as much as a
  policy one: where controls sit, how systems are designed, and what
  changes have to happen structurally rather than procedurally.

  Ask AI: "What's the difference between closing a security gap with a new
  policy versus closing it with an architectural change, and how would a
  leader decide which one a given gap needs?"

- [ ] **Cyber risk management**

  Understand risk across the whole organisation, and advise the board and
  other leaders on how to mitigate it, both in their current areas and in
  future plans that haven't been built yet.

  Ask AI: "How should a security leader present cyber risk to a board of
  non-specialists in a way that leads to a real decision, rather than
  glazed eyes or false reassurance?"

- [ ] **Cyber incident management**

  Make sure the organisation is prepared for cyber attacks and can detect,
  respond to and recover from one, and that the security aspects of crisis
  management actually work when a crisis is real rather than only on paper.

  Ask AI: "What separates an incident response plan that works under real
  pressure from one that only works in a tabletop exercise?"

- [ ] **Changing security culture**

  Encourage a culture of cyber security awareness and good security
  practice across the whole organisation, not just within the security
  team — culture change here is slower and harder than any policy change,
  and it's usually the thing that actually determines whether an
  organisation stays secure.

  Ask AI: "What actually changes security behaviour across a large
  organisation, as opposed to security awareness training that people sit
  through and then ignore?"

- [ ] **Innovation in digital, data and technology**

  Enable the organisation to be innovative in a safe and secure way — the
  test of a good security function is not how much it blocks, but how much
  it lets happen safely that would otherwise have been too risky to try.

  Ask AI: "How does a security leader support genuine innovation instead of
  becoming the function that says no to everything new?"

- [ ] **Capability building for digital, data and technology**

  Implement the practices that actually increase the organisation's
  security maturity over time, which depends on the organisation having
  people with the right skills, not only the right policies.

  Ask AI: "What security capability gaps tend to appear first as an
  organisation's security maturity grows, and how would a leader plan for
  them ahead of time?"

Ask a peer chief information security officer, in your sector or another part
of government, which of these has taken them longest to get right — that
conversation will teach you more than any general reading on security
leadership.
