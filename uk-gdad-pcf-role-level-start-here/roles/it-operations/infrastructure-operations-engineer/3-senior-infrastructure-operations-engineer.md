# Senior infrastructure operations engineer - start here

Welcome. If you are working toward the senior infrastructure operations
engineer level, this page is for you: what the role expects, where to find
everything else this repository has for it, and a pathway for building
the skills it asks for.

## Purpose

A senior infrastructure operations engineer acts as second- or third-line
support for incidents, problems and changes to solutions and services,
providing specialist technical support to projects, coaching and mentoring
junior team members, and helping deliver first class services and
consistent levels of capability. Change management, coding and scripting,
incident management, problem management, technical specialism and testing
all grow at this level, because escalated support asks for more than
handling the first line of a request.

## Learning pathway

Work through these roughly in order. Where you want to go deeper, ask an AI
tool a specific question rather than searching for a generic guide — you'll
get an answer shaped around your own organisation's services.

- [ ] **Diagnose incidents, and find their resolution**

  Diagnose and prioritise incidents, investigate their causes, and find
  resolutions rather than just recording and routing them.

  Ask AI: "What's a structured way to diagnose the root cause of an
  infrastructure incident, rather than fixing the first plausible
  symptom?"

- [ ] **Analyse the impact of change before it happens**

  Analyse and assess the impact of change, document change requests, and
  action changes from approved requests.

  Ask AI: "What should a senior engineer look for when assessing the
  potential impact of an infrastructure change, beyond whether it
  technically works?"

- [ ] **Investigate patterns behind problems, and consult specialists**

  Initiate and monitor actions to investigate patterns and trends behind
  problems, consult specialists where needed, determine the right
  resolution and help implement it, and identify preventative measures.

  Ask AI: "What's the difference between fixing a recurring fault and
  preventing the pattern behind it from continuing?"

- [ ] **Use tools and schemata to investigate and optimise performance**

  Use management system software and tools, use logical schemata to
  investigate problems and collect performance statistics, carry out
  routine configuration and reconfiguration of database and related
  products, and optimise performance while forecasting resource needs.

  Ask AI: "What's the difference between fixing a performance issue on a
  system and forecasting the resource needs that would prevent it
  recurring?"

- [ ] **Define test conditions, and analyse results**

  Review requirements and specifications to define test conditions,
  identify issues and risks associated with the work, and analyse and
  report on test activities and results.

  Ask AI: "What makes a test condition genuinely well-defined, as opposed
  to a vague check that something 'looks right'?"

- [ ] **Keep secure configuration maintained, and IT assets tracked**

  This skill's wording plateaus here, unchanged from the level below:
  maintaining secure configuration, controlling IT assets, and verifying
  their location and state.

  Ask AI: "Given this skill's description hasn't changed since the level
  below, what would genuinely senior-level asset management judgement add
  beyond what's written here?"

- [ ] **Keep managing service components against business needs**

  This skill also plateaus: managing service components to make sure they
  meet business needs and key performance indicators.

  Ask AI: "What would setting availability and capacity standards for a
  team add, beyond meeting them well yourself?"

- [ ] **Keep describing scripting tools and software**

  This skill's wording plateaus too: describing different scripting tools
  and software that are available and currently in use.

  Ask AI: "At what point does describing available scripting tools turn
  into choosing which ones a team should standardise on?"

- [ ] **Keep owning an issue until it's genuinely resolved**

  This skill also plateaus: owning an issue until a new owner is found or
  it's mitigated or resolved.

  Ask AI: "What would taking accountability for an issue, rather than
  just owning it until resolved, look like at the next level?"

- [ ] **Keep building coherent frameworks from scattered inputs**

  This skill's wording plateaus too: taking inputs and establishing
  coherent frameworks that work.

  Ask AI: "What would leading how a team builds coherent frameworks add,
  beyond building good ones yourself?"

- [ ] **Keep building service management framework knowledge**

  This skill also plateaus: holding a Level 3 service management
  framework qualification.

  Ask AI: "What would deepening service management framework knowledge,
  beyond the base qualification, look like for a senior engineer?"

- [ ] **Keep turning user evidence into decisions**

  This skill's wording plateaus too: collating user needs evidence,
  defining fitting research, and using quantitative and qualitative data
  to turn user focus into outcomes.

  Ask AI: "What would leading user-focused decisions across a whole team,
  rather than one task at a time, look like at this level?"

Ask a lead infrastructure operations engineer, or an equivalent principal
colleague, which of these matters most in your organisation right now, and
start there.
