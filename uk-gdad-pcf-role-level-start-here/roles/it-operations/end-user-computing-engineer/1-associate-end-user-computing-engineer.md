# Associate end user computing engineer - start here

Welcome. If you are starting out as an associate end user computing
engineer, this page is for you: what the role is about, where to find
everything else this repository has for it, and a pathway for building the
skills it asks for, one step at a time.

## Purpose

An end user computing engineer manages the whole product life cycle of
service-raised incidents and service requests, using knowledge management
to do it well — informing customers on progress, advising on workarounds
where needed, and supporting and maintaining end user services. As a
trainee, you work in an established team and support more experienced
engineers in their daily work, under their direction — learning the job by
helping with it, not by doing it alone yet.

## Learning pathway

Work through these roughly in order. Each one is a requirement of this role
level, described plainly, with a way to go deeper by asking an AI tool a
specific question — the answers you get will be shaped around your own
organisation's end user services, which a generic guide never is.

- [ ] **Investigate problems at the right level**

  Investigate problems in systems, processes and services with an
  understanding of what level a problem sits at — strategic, tactical or
  operational — and contribute to implementing remedies and preventative
  measures.

  Ask AI: "I'm new to end user computing. Explain, simply, the difference
  between a strategic, a tactical and an operational problem, with an
  example of each."

- [ ] **Identify and register incidents accurately**

  Identify and register incidents, gathering the information needed and
  allocating them to the right channel.

  Ask AI: "What information does a good incident record need to contain
  so the next person picking it up doesn't have to ask basic questions
  first?"

- [ ] **Collate data, and understand what a KPI is**

  Collate data from data repositories and provide basic reporting, and
  explain what a key performance indicator is and why it matters.

  Ask AI: "Explain, for a beginner, what a key performance indicator
  actually measures for an end user computing team, with an example."

- [ ] **Build a basic sense of who you're supporting**

  Show an awareness or understanding of user experience analysis and its
  principles, and explain the purpose of user stories and their focus on
  user needs.

  Ask AI: "Why does understanding a user story help an end user computing
  engineer prioritise which request to handle first?"

- [ ] **Understand problem resolution, and pass on what you can't solve**

  Show an awareness of problem resolution processes, and pass problems on
  to your team when you can't resolve them yourself.

  Ask AI: "How would an associate engineer decide when to keep trying to
  fix a device themselves versus passing it on to someone more
  experienced?"

You do not need to master all of this before you start. Ask your manager or
a more senior colleague which of these your team leans on most, and start
there.
