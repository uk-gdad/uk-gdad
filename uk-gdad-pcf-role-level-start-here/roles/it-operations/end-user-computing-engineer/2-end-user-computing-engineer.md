# End user computing engineer - start here

Welcome. If you are working toward the end user computing engineer level,
this page is for you: what the role expects, where to find everything else
this repository has for it, and a pathway for building the skills it asks
for.

## Purpose

An end user computing engineer works on-site, maintaining hardware and
fixing technical problems as quickly as possible. You provide first-time
resolution by troubleshooting and diagnosing faults, escalating to service
desk managers, incident managers and problem managers when needed, and
coach associates while sharing knowledge with your team. Six new skills
appear at this level — asset and configuration management, change
management, service focus, service management framework knowledge,
technical specialism and testing — because fixing real hardware and
software problems on-site asks for far more than the basics an associate
builds.

## Learning pathway

Work through these roughly in order. Each one is a requirement of this role
level. Where you want to go deeper, ask an AI tool a specific question
rather than searching for a generic guide — you'll get an answer shaped
around your own hardware and services.

- [ ] **Keep configuration secure, and IT assets accounted for**

  Maintain secure configuration and accurate information, control IT
  assets in one or more areas, and verify the location and state of those
  assets.

  Ask AI: "I'm new to end user computing at this level. Explain, simply,
  why keeping accurate hardware asset records matters beyond just knowing
  where devices are."

- [ ] **Implement changes under supervision**

  Implement change requests, and apply change control procedures under
  supervision.

  Ask AI: "Why do organisations use a formal change control procedure for
  hardware changes instead of just making a fix when it's needed?"

- [ ] **Assist with technical support, and routine maintenance**

  Assist in technical support activities, and carry out agreed or routine
  maintenance and administration tasks.

  Ask AI: "What separates a well-run routine hardware maintenance task
  from one that's rushed, in a way that causes problems later?"

- [ ] **Execute test scripts, and understand how testing works**

  Correctly execute test scripts under supervision, and understand the
  role testing plays and how it works.

  Ask AI: "What is a test script actually checking for when rolling out a
  hardware or software change, and why does someone need to execute it
  correctly rather than just run it?"

- [ ] **Build coherent frameworks from scattered inputs**

  Take inputs and establish coherent frameworks that work, rather than
  leaving information scattered across different sources.

  Ask AI: "What does 'establishing a coherent framework' mean in practice
  for someone supporting end user devices across a whole team?"

- [ ] **Build service management framework knowledge**

  Work towards a Level 3 service management framework qualification, so
  your day-to-day practice is grounded in a recognised standard.

  Ask AI: "Explain, for a beginner, what a service management framework
  qualification actually covers, and why organisations value it."

- [ ] **Own an issue until it's genuinely resolved**

  Own an issue until a new owner has been found, or the problem has been
  mitigated or resolved — rather than passing it on the moment it gets
  difficult.

  Ask AI: "What does 'owning an issue' mean in practice when a fault turns
  out to need escalating to someone else's team?"

- [ ] **Turn user evidence into decisions**

  Identify and engage with users or stakeholders to collate evidence of
  their needs, understand and define research that actually fits those
  needs, and use both quantitative and qualitative data to turn user
  focus into real outcomes.

  Ask AI: "How would an end user computing engineer use evidence from
  users to decide which recurring fault is worth escalating as a
  pattern?"

- [ ] **Keep collating data, and understanding what a KPI is**

  This skill's wording plateaus here, unchanged from associate level:
  collating data and providing basic reporting, and explaining why key
  performance indicators matter.

  Ask AI: "Given this skill's description hasn't changed since the level
  below, what would genuinely more independent reporting look like at
  this level?"

- [ ] **Keep identifying and registering incidents accurately**

  This skill also plateaus: identifying and registering incidents, and
  allocating them to the right channel.

  Ask AI: "What would taking more ownership of incident handling, beyond
  registering it, look like at this level?"

- [ ] **Keep investigating problems at the right level**

  This skill's wording plateaus too: investigating problems with an
  understanding of their level, and contributing to remedies.

  Ask AI: "What would taking more ownership of problem investigation,
  beyond contributing to remedies, look like at the next level?"

Ask your manager or a more senior colleague which of these your team relies on
most right now, and start there.
