# Lead End User Computing Engineer - Competency Assessment

## Introduction

This is for you: a chance to rate your own current strengths against the
baseline the UK GDAD Profession Capability Framework sets for this role
level, using the framework's own words for what it covers.

An end user computing engineer is responsible for managing the product life cycle of all service-raised incidents (incident control) and all service requests (request control), requiring the use of knowledge management. In this role, you will also be responsible for informing customers on progress and advising on workarounds where necessary, as well as the support and maintenance of end user services. A lead end user computing engineer has expert technical understanding and is accountable for vendor and supplier management. At this level, you will work with relevant IT operations and other functions, such as technical architecture, to understand lower level productivity, development and feasibility.

Work through the competency matrix below, one skill at a time, then fill in
the overall determination at the end. Treat this as a mirror, not a test —
there's no assessor watching, so being honest with yourself only costs you a
slightly less flattering picture today in exchange for a far more useful one.
Read `## Advisory` before you begin.

## Advisory

This competency assessment is created by AI and is a work in progress for
educational purposes. It is not a validated assessment instrument — it has
not been piloted, normed or checked for adverse impact — and a rating you
give yourself here must never be treated as equivalent to a formal
assessment for a hiring, promotion, pay or performance decision. Use it for
your own reflection, and talk to your manager, a mentor, or your
organisation's people development team about what you find.

## How to use this assessment

**Preparing.** Read `## About this role level` first, so you're rating
yourself against what this level actually expects rather than the level
above or below it. Then think back over recent, real examples of your work —
not how you'd like to have handled something, but what you actually did.

**Rate on evidence, not impression.** For every skill, try to recall a
specific moment that supports the rating you give yourself. If you can't
think of one, that's useful information too — it might mean the rating
should be lower, or just that you haven't had the chance to show this skill
yet, which is worth noting separately.

**Be consistent with yourself.** Try to apply the same standard across every
skill, rather than being generous where you feel confident and harsh where
you feel unsure. Coming back to this after a few days, with fresh examples in
mind, often sharpens a rating more than sitting with it in one go.

**Be kind, and be honest.** This only works if you can look at the result
without flinching. A low rating here is not a verdict on you — it's a
starting point. Everyone doing this role, at every level, has skills they are
still building.

## Rating scale

Every skill in the competency matrix is rated on the same five-point
proficiency scale — how well someone does the thing, on the evidence
available, not how often they do it.

| Value | Rating | Meaning |
| ---: | --- | --- |
| 0 | None | No demonstrated experience of this skill |
| 1 | Beginner | Just starting to learn the skill; requires close supervision |
| 2 | Intermediate | Knows the basics and can perform tasks with some guidance |
| 3 | Advanced | Has a strong grasp of the skill and can work independently |
| 4 | Expert | Demonstrates full mastery and can teach or guide others in the skill |

**Worked example.** Take Skill: User focus. At 2 — Intermediate, someone
engages a user directly to understand their need and uses that to resolve one
issue well. At 3 — Advanced, they champion user research more widely and can
explain the difference between what a user asks for and what they actually
need. At 4 — Expert, the baseline for this level, they collaborate with user
researchers, represent users internally, prioritise and define the approach
to understanding the user story, guide others in doing so, and recommend
which tools and methods the team should use — the framework's own wording for
this level, and a clear step beyond independent competence into guiding
others. Calibrate against evidence like this before you start scoring.

## About this role level

IT operations role: End user computing engineer. An end user computing
engineer is responsible for managing the product life cycle of all
service-raised incidents (incident control) and all service requests (request
control), which requires the use of knowledge management. In this role, you
are also responsible for informing customers on progress and advising on
workarounds where necessary, as well as the support and maintenance of end
user services.

The role has five levels, in order: associate end user computing engineer,
end user computing engineer, senior end user computing engineer, lead end user
computing engineer, and principal end user computing engineer. This assessment
covers lead end user computing engineer, the fourth of those.

Role level: Lead end user computing engineer. A lead end user computing
engineer has expert technical understanding and is accountable for vendor and
supplier management. At this level, the framework expects someone to work
with relevant IT operations and other functions, such as technical
architecture, to understand lower-level productivity, development and
feasibility. The framework does not list separate day-to-day accountability
bullets for this level beyond this description; its expectations are carried
in the skills below.

The framework names eleven skills for this level: Asset and configuration
management, Change management, IT service reporting, Incident management,
Ownership and initiative, Problem management, Service focus, Service
management framework knowledge, Technical specialism, Testing, and User
focus.

## Competency matrix

### Skill: Asset and configuration management

**What the framework expects at this level**

A lead end user computing engineer maintains secure configuration and
accurate information, controls IT assets in one or more areas, and verifies
the location and state of IT assets.

**Baseline for this role level**

Baseline: 3 — Advanced. The framework's wording is unchanged since level 2,
but by the time someone leads vendor and supplier relationships and expert
technical work, foundational configuration control is assumed to be strong
and independent rather than merely guided — its absence from this level's
extra wording reflects that it is no longer a growth area, not a lowered
expectation.

**Behavioural indicators**

- 0 — None: cannot say where the asset register is or what it is for.
- 1 — Beginner: updates the asset register when told exactly what to change.
- 2 — Intermediate: keeps configuration and asset records accurate for their
  own area, and can verify an asset's location and state without prompting.
- 3 — Advanced: spots and corrects a discrepancy in the asset register before
  it causes a problem, and improves how the team keeps records.
- 4 — Expert: owns asset and configuration accuracy across a whole service
  and is someone others check a difficult record against.

**Evidence to gather**

- Think about how you'd describe how you have improved asset or configuration
  accuracy for a team, not just for yourself.
- Review an asset or configuration standard you set or improved.
- Ask a referee for an example of you catching a systemic
  configuration problem before it caused an incident.

### Skill: Change management

**What the framework expects at this level**

A lead end user computing engineer manages high-impact, complex change
requests and ensures that release policies, procedures and processes are
applied.

**Baseline for this role level**

Baseline: 4 — Expert. Managing high-impact, complex changes and being
responsible for release policy application, rather than just assessing and
actioning changes, is ownership at a scale that fits full mastery — someone others rely on to get the highest-risk changes right.

**Behavioural indicators**

- 0 — None: cannot describe what makes a change high-impact or complex.
- 1 — Beginner: contributes to part of a complex change under a colleague's
  direction.
- 2 — Intermediate: manages a moderately complex change with a senior
  colleague available to check progress.
- 3 — Advanced: manages a high-impact, complex change independently, and
  applies release policies correctly.
- 4 — Expert: manages the highest-impact, most complex changes in the
  service, and ensures the wider team applies release policy consistently.

**Evidence to gather**

- Think about how you'd describe a high-impact, complex change you managed
  end to end, including how you handled the risk.
- Look back at a change record or post-implementation review for a complex change
  you led.
- Ask a referee whether your management of complex changes has
  needed correction, and how release policy compliance was checked.

  stakeholder buy-in for it.

  explained the data in it to a stakeholder.

### Skill: Ownership and initiative

**What the framework expects at this level**

A lead end user computing engineer takes accountability for issues that occur
and is proactive in searching for potential problems, and achieves excellent
user outcomes.

**Baseline for this role level**

Baseline: 3 — Advanced. Proactively searching for problems before they occur,
rather than only owning an issue once it exists, is a genuine step up from
the level below, matching independent, strong-grasp practice.

**Behavioural indicators**

- 0 — None: only acts once an issue has already been raised.
- 1 — Beginner: owns an existing issue through to resolution when reminded to.
- 2 — Intermediate: owns issues through to resolution unprompted, but has not
  yet proactively surfaced a potential problem before it occurred.
- 3 — Advanced: takes accountability for issues that occur, proactively looks
  for potential problems, and consistently achieves a good outcome for users.
- 4 — Expert: builds a habit of proactive problem-searching into how the
  whole team works.

**Evidence to gather**

- Ask for an example of a potential problem you spotted and
  addressed before it became an incident.
- Ask a referee whether you takes accountability when something
  goes wrong, or shifts blame.
- Review evidence of a user outcome you achieved that went beyond
  the minimum fix.

### Skill: Problem management

**What the framework expects at this level**

A lead end user computing engineer initiates and monitors actions to
investigate patterns and trends to resolve problems, effectively consults
specialists where required, determines the appropriate resolution and assists
with its implementation, and determines preventative measures.

**Baseline for this role level**

Baseline: 3 — Advanced. The framework's wording is unchanged from the senior
level, so the baseline holds; this level's added weight sits in Change
management, Incident management and vendor accountability instead.

**Behavioural indicators**

- 0 — None: cannot distinguish a problem from an incident.
- 1 — Beginner: investigates a problem when told exactly what to look at.
- 2 — Intermediate: investigates a problem and contributes ideas to a remedy,
  but relies on a colleague to decide the resolution.
- 3 — Advanced: initiates and monitors an investigation into a pattern or
  trend, consults specialists appropriately, determines the resolution and
  the preventative measure, and assists with implementing it.
- 4 — Expert: spots a pattern across problems that others have missed and
  changes how the team investigates as a result.

**Evidence to gather**

- Think about how you'd describe a problem investigation you initiated, who
  you consulted, and what resolution and preventative measure you
  determined.
- Look back at a problem record or root-cause report you own.
- Ask a referee for an example of a preventative measure you
  determined that stopped a recurring issue.

### Skill: User focus

**What the framework expects at this level**

A lead end user computing engineer collaborates with user researchers and can
represent users internally, explains the difference between user needs and
the desires of the user, champions user research to focus on all users,
prioritises and defines approaches to understand the user story while guiding
others in doing so, and offers recommendations on the best tools and methods
to use.

**Baseline for this role level**

Baseline: 4 — Expert. Guiding others through the approach to the user story
and championing user research across the team is teaching-and-guiding work —
a clear jump from independently engaging users at the levels below, and the
scale's own definition of Expert.

**Behavioural indicators**

- 0 — None: fixes the reported fault without asking the user anything about
  their wider need.
- 1 — Beginner: engages users directly when directed to.
- 2 — Intermediate: engages users to understand their actual need and uses
  that to resolve issues well.
- 3 — Advanced: champions user research and can explain, to a colleague, the
  difference between what a user asks for and what they need.
- 4 — Expert: represents users internally, prioritises and defines the
  approach to the user story, guides colleagues through it, and recommends
  which tools or methods the team should use.

**Evidence to gather**

- Ask for an example of you guiding a colleague through
  understanding a user's actual need.
- Ask a referee whether you are seen internally as representing
  users' interests.
- Look back at a recommendation you made about which tools or methods the
  team should use for user focus work.
