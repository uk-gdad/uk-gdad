# Senior End User Computing Engineer - Competency Assessment

## Introduction

This is for you: a chance to rate your own current strengths against the
baseline the UK GDAD Profession Capability Framework sets for this role
level, using the framework's own words for what it covers.

An end user computing engineer is responsible for managing the product life cycle of all service-raised incidents (incident control) and all service requests (request control), requiring the use of knowledge management. In this role, you will also be responsible for informing customers on progress and advising on workarounds where necessary, as well as the support and maintenance of end user services. A senior end user computing engineer is responsible for managing the team but also gets involved in solving technical problems.

Work through the competency matrix below, one skill at a time, then fill in

## Advisory

This competency assessment is created by AI and is a work in progress for
educational purposes. It is not a validated assessment instrument — it has
not been piloted, normed or checked for adverse impact — and a rating you
give yourself here must never be treated as equivalent to a formal
assessment for a hiring, promotion, pay or performance decision. Use it for
your own reflection, and talk to your manager, a mentor, or your
organisation's people development team about what you find.

## How to use this assessment

**Preparing.** Read `## About this role level` first, so you're rating
yourself against what this level actually expects rather than the level
above or below it. Then think back over recent, real examples of your work —
not how you'd like to have handled something, but what you actually did.

**Rate on evidence, not impression.** For every skill, try to recall a
specific moment that supports the rating you give yourself. If you can't
think of one, that's useful information too — it might mean the rating
should be lower, or just that you haven't had the chance to show this skill
yet, which is worth noting separately.

**Be consistent with yourself.** Try to apply the same standard across every
skill, rather than being generous where you feel confident and harsh where
you feel unsure. Coming back to this after a few days, with fresh examples in
mind, often sharpens a rating more than sitting with it in one go.

**Be kind, and be honest.** This only works if you can look at the result
without flinching. A low rating here is not a verdict on you — it's a
starting point. Everyone doing this role, at every level, has skills they are
still building.

## Rating scale

Every skill in the competency matrix is rated on the same five-point
proficiency scale — how well someone does the thing, on the evidence
available, not how often they do it.

| Value | Rating | Meaning |
| ---: | --- | --- |
| 0 | None | No demonstrated experience of this skill |
| 1 | Beginner | Just starting to learn the skill; requires close supervision |
| 2 | Intermediate | Knows the basics and can perform tasks with some guidance |
| 3 | Advanced | Has a strong grasp of the skill and can work independently |
| 4 | Expert | Demonstrates full mastery and can teach or guide others in the skill |

**Worked example.** Take Skill: Incident management. At 2 — Intermediate, someone diagnoses a familiar incident and finds a resolution with some
guidance from a colleague. At 3 — Advanced, the baseline for this level, they
diagnose and prioritise an incident against other open work unassisted,
investigate its cause and find the resolution themselves — matching the
framework's own wording for this level. At 4 — Expert, they are someone
colleagues escalate to when an incident resists diagnosis, and they teach the
diagnostic technique to others. Calibrate against evidence like this before
you start scoring.

## About this role level

IT operations role: End user computing engineer. An end user computing
engineer is responsible for managing the product life cycle of all
service-raised incidents (incident control) and all service requests (request
control), which requires the use of knowledge management. In this role, you
are also responsible for informing customers on progress and advising on
workarounds where necessary, as well as the support and maintenance of end
user services.

The role has five levels, in order: associate end user computing engineer,
end user computing engineer, senior end user computing engineer, lead end user
computing engineer, and principal end user computing engineer. This assessment
covers senior end user computing engineer, the third of those.

Role level: Senior end user computing engineer. A senior end user computing
engineer is responsible for managing the team but also gets involved in
solving technical problems.

At this role level, the framework expects someone to:

- manage, co-ordinate and prioritise tasks to resolve technical incidents as
  quickly as possible
- work closely with infrastructure, capacity managers and availability
  managers to fix technical problems, and identify and escalate repeat issues
  to the lead end user computing engineer, the incident or problem manager
  and software developers

The framework names eleven skills for this level: Asset and configuration
management, Change management, IT service reporting, Incident management,
Ownership and initiative, Problem management, Service focus, Service
management framework knowledge, Technical specialism, Testing, and User
focus.

## Competency matrix

### Skill: Asset and configuration management

**What the framework expects at this level**

A senior end user computing engineer maintains secure configuration and
accurate information, controls IT assets in one or more areas, and verifies
the location and state of IT assets.

**Baseline for this role level**

Baseline: 2 — Intermediate. The framework's wording for this skill is
unchanged from the level below, so the baseline stays at Intermediate too —
this level's step up shows in Incident management and team co-ordination, not
here.

**Behavioural indicators**

- 0 — None: cannot say where the asset register is or what it is for.
- 1 — Beginner: updates the asset register when told exactly what to change.
- 2 — Intermediate: keeps configuration and asset records accurate for their
  own area day to day, and can verify an asset's location and state without
  prompting.
- 3 — Advanced: spots and corrects a discrepancy in the asset register before
  it causes a problem, and improves how their team keeps records.
- 4 — Expert: owns asset and configuration accuracy across a whole service and
  is someone others check a difficult record against.

**Evidence to gather**

- Think about how you'd describe how you keep an asset or configuration record
  accurate day to day, with an example.
- Review an asset or configuration record you maintained, and ask what would
  have gone wrong if it had drifted.
- Ask a referee for an example of you catching an inaccurate asset
  record before it caused an incident.

### Skill: Change management

**What the framework expects at this level**

A senior end user computing engineer analyses and assesses the impact of
change, documents change requests, and actions changes from change requests.

**Baseline for this role level**

Baseline: 3 — Advanced. This is a clear step up from implementing change
requests under supervision at level 2: assessing impact and actioning changes
independently is exactly the strong grasp and independent working the scale
describes as Advanced.

**Behavioural indicators**

- 0 — None: cannot describe what assessing the impact of a change involves.
- 1 — Beginner: documents a change request when given the details to record.
- 2 — Intermediate: assesses the impact of a straightforward change with a
  colleague checking the assessment.
- 3 — Advanced: independently analyses and assesses the impact of a change,
  documents the request properly, and actions it.
- 4 — Expert: is consulted on the impact assessment for the highest-risk
  changes in the service.

**Evidence to gather**

- Think about how you'd walk through a change you assessed, documented and
  actioned, including what you judged the impact to be and why.
- Look back at a change record showing your impact assessment.
- Ask a referee about a change you actioned that had a wider impact
  than first expected, and how you handled it.

### Skill: IT service reporting

**What the framework expects at this level**

A senior end user computing engineer produces relevant reports in an
appropriate format and agreed timeframe, works with stakeholders to discuss
any changes in the reporting processes, and interprets a data set and
communicates this to others.

**Baseline for this role level**

Baseline: 3 — Advanced. Interpreting a data set for stakeholders and shaping
the reporting process itself, rather than only collating basic reports, is
independent, judgement-based work.

**Behavioural indicators**

- 0 — None: cannot produce a report to an agreed format.
- 1 — Beginner: produces a report to a template someone else has set, with
  the content checked before it is sent.
- 2 — Intermediate: produces reports to the agreed format and timeframe
  unassisted, but relies on others to interpret what the numbers mean.
- 3 — Advanced: produces reports to format and timeframe, interprets the data
  for stakeholders in plain terms, and discusses process changes with them.
- 4 — Expert: redesigns the reporting process for a service and gets
  stakeholder buy-in for it.

**Evidence to gather**

- Think about how you'd walk through a report you produced and how you
  explained the data in it to a stakeholder.
- Look back at a report and any accompanying commentary you wrote.
- Ask a referee for an example of you discussing a reporting process
  change with a stakeholder.

### Skill: Incident management

**What the framework expects at this level**

A senior end user computing engineer diagnoses and prioritises incidents,
investigates their causes and finds resolutions.

**Baseline for this role level**

Baseline: 3 — Advanced. This is the clearest step up in the whole matrix from
level 2's register-and-route work: diagnosing, prioritising and resolving
unassisted is independent, strong-grasp work by the scale's own definition.

**Behavioural indicators**

- 0 — None: cannot diagnose a fault beyond following a runbook.
- 1 — Beginner: diagnoses a familiar incident with a colleague checking the
  reasoning.
- 2 — Intermediate: diagnoses and resolves familiar incidents unassisted, but
  needs help prioritising against a busy queue.
- 3 — Advanced: independently diagnoses and prioritises incidents against
  competing work, investigates the cause and finds the resolution.
- 4 — Expert: is the escalation point for incidents that have resisted
  diagnosis by others, and teaches the diagnostic approach to the team.

**Evidence to gather**

- Walk through a real or simulated incident scenario and observe how you prioritises and diagnoses it.
- Ask for an example of an incident you investigated from first report to
  resolution.
- Ask a referee for an example of you correctly prioritising one
  incident over another under pressure.

### Skill: Ownership and initiative

**What the framework expects at this level**

A senior end user computing engineer owns an issue until a new owner has been
found or the problem has been mitigated or resolved.

**Baseline for this role level**

Baseline: 2 — Intermediate. The framework's wording for this skill is
unchanged from level 2, so the baseline holds; this level's accountability
growth shows in team co-ordination and incident management, not in a wider
definition of ownership.

**Behavioural indicators**

- 0 — None: drops an issue once it is out of their hands.
- 1 — Beginner: keeps an issue open on their own list but needs reminding to
  chase it.
- 2 — Intermediate: tracks an issue through to a confirmed handover or
  resolution without being chased.
- 3 — Advanced: proactively checks that a handed-over issue actually landed
  with its new owner and was picked up.
- 4 — Expert: is someone others rely on to never let an issue slip, across
  a whole shift or team.

**Evidence to gather**

- Ask for an example of an issue you followed through to resolution
  or a confirmed handover.
- Ask a referee whether issues assigned to you have gone missing or
  stalled.
- Look back at a ticket history showing your ownership of an issue over
  time.

### Skill: Problem management

**What the framework expects at this level**

A senior end user computing engineer initiates and monitors actions to
investigate patterns and trends to resolve problems, effectively consults
specialists where required, determines the appropriate resolution and assists
with its implementation, and determines preventative measures.

**Baseline for this role level**

Baseline: 3 — Advanced. Determining the resolution and preventative measures,
rather than only investigating and contributing as at level 2, is
independent, judgement-driven ownership of the whole problem, matching
Advanced.

**Behavioural indicators**

- 0 — None: cannot distinguish a problem from an incident.
- 1 — Beginner: investigates a problem when told exactly what to look at.
- 2 — Intermediate: investigates a problem and contributes ideas to a remedy,
  but relies on a colleague to decide the resolution.
- 3 — Advanced: initiates and monitors an investigation into a pattern or
  trend, consults specialists appropriately, determines the resolution and
  the preventative measure, and assists with implementing it.
- 4 — Expert: spots a pattern across problems that others have missed and
  changes how the team investigates as a result.

**Evidence to gather**

- Think about how you'd describe a problem investigation you initiated, who
  you consulted, and what resolution and preventative measure you
  determined.
- Look back at a problem record or root-cause report you own.
- Ask a referee for an example of a preventative measure you
  determined that stopped a recurring issue.

### Skill: Technical specialism

**What the framework expects at this level**

A senior end user computing engineer uses management system software and
tools, uses logical schemata to investigate problems, collect performance
statistics and create reports, carries out the routine configuration,
installation and reconfiguration of database and related products, and
optimises performance and forecasts resource needs.

**Baseline for this role level**

Baseline: 3 — Advanced. This is a marked step up from "assisting" and
"routine maintenance" at level 2: using management tools, optimising
performance and forecasting resource needs is independent specialist work.

**Behavioural indicators**

- 0 — None: cannot use the team's management system software beyond basic
  tasks.
- 1 — Beginner: uses management system software for routine tasks with
  guidance.
- 2 — Intermediate: uses management system software and logical schemata to
  investigate a familiar problem, with a colleague checking the outcome.
- 3 — Advanced: independently uses management tools and schemata to
  investigate problems, configures and reconfigures database and related
  products, and forecasts resource needs.
- 4 — Expert: is consulted on the hardest performance and capacity forecasts
  in the service.

**Evidence to gather**

- Think about how you'd describe a resource forecast or performance
  optimisation you carried out, and what data you used.
- Observe or ask you to walk through a routine database configuration task.
- Ask a referee for an example of your forecast proving accurate,
  or where it needed correcting.

### Skill: User focus

**What the framework expects at this level**

A senior end user computing engineer identifies and engages with users or
stakeholders to collate user needs evidence, understands and defines research
that fits user needs, and uses quantitative and qualitative data about users
to turn user focus into outcomes.

**Baseline for this role level**

Baseline: 2 — Intermediate. The framework's wording is unchanged from level 2;
this level's growth is expressed through team co-ordination and incident
ownership rather than a wider User focus expectation.

**Behavioural indicators**

- 0 — None: fixes the reported fault without asking the user anything about
  their wider need.
- 1 — Beginner: asks the user basic clarifying questions when prompted to.
- 2 — Intermediate: engages the user directly to understand what they
  actually need, not just what they reported, and uses that to resolve the
  issue in a way that works for them.
- 3 — Advanced: spots a pattern in what several users need and feeds it back
  so the service improves for everyone.
- 4 — Expert: shapes how the wider team engages with users.

**Evidence to gather**

- Observe or ask you to describe an interaction where you found out
  more than the user's initial report.
- Ask for an example where understanding a user's actual need changed how you
  resolved an issue.
- Ask a referee how users or colleagues describe your manner with
  users.
